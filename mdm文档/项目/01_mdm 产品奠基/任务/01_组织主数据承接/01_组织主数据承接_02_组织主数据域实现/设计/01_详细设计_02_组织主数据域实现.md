## 1. 设计目标与范围 <a id="goal"></a>

承接需求 01-2：在 mdm `org` 服务（01_01 工程骨架）内实现**组织主数据域**——部门（组织架构树）、岗位（归属部门）、用户-岗位关联、角色-岗位 / 角色-部门分配，落库并提供维护能力（含**全部写入口**）。

1. **五表落库**：`org_dept` / `org_post` / `org_user_post` / `org_role_post` / `org_role_dept`（表文件见 §3），随 `org:tenant` 链迁移落地。
2. **维护能力（含全部端点写入）**：部门树 CRUD 与移动；岗位 CRUD；用户-岗位分配（插件写入口）；角色-岗位 / 角色-部门分配（插件写入口）。
3. **质量与留痕**：录入校验 + 唯一约束（源头控质）；审计经基座 `AuditCapturer` **占位**接入（写操作落审计占位）+ 结构化操作日志；字段级真实审计落库随审计阶段。
4. **用户联动**：消费 `sys.user.deleted` 事件清理用户-岗位关联。
5. **事件发布**：`org.dept.changed` / `org.post.changed` / `org.user_post.changed` / `org.role_post.changed` / `org.role_dept.changed`；**5 条事件契约随本任务一并登记**（`[event].contract_mode` 缺省 `enforce`，未登记契约拒发 10010）。
6. **表归属自持与包名前缀**：org 五表在 mdm 侧**自持登记**（`backend/services/table_registry.py`），经基座**产品注入通道**（应用装配 `table_records()` 钩子 + ops / alembic 装载入口）注册；运行期配 `[app].package_prefix = "mdm"` 使迁移链按 `mdm_org.models` 取模型。

**不在本期（归 01_03）**：对外**只读出口两契约**（组织数据源 / 名称回显，横切基座口径）、**按用户解析角色只读契约**（`/api/v1/org/user-roles`）。

## 3. 数据模型与表结构 <a id="data"></a>

字段级结构以**表文件为唯一事实源**，本节只给关系与引用：

| 表 | 表文件 | 关键关系 |
| --- | --- | --- |
| `org_dept` | [org_dept.md](../../../../../../设计/数据库设计/数据表设计/org_dept.md) | `parent_id` 自引用；`ancestors` 祖先路径 |
| `org_post` | [org_post.md](../../../../../../设计/数据库设计/数据表设计/org_post.md) | `dept_id` → `org_dept.id`（同库逻辑外键） |
| `org_user_post` | [org_user_post.md](../../../../../../设计/数据库设计/数据表设计/org_user_post.md) | `user_id` → bms `sys_user.id`（跨服务）；`post_id` → `org_post.id` |
| `org_role_post` | [org_role_post.md](../../../../../../设计/数据库设计/数据表设计/org_role_post.md) | `role_id` → bms `sys_role.id`（跨服务）；`post_id` → `org_post.id` |
| `org_role_dept` | [org_role_dept.md](../../../../../../设计/数据库设计/数据表设计/org_role_dept.md) | `role_id` → bms `sys_role.id`（跨服务）；`dept_id` → `org_dept.id` |

- **主键**：五表**一律雪花 ID（`BaseModel`）**；三张关联表以业务列复合唯一 `(x_id, y_id, deleted_at)` 防重（2026-10-07 口径修订，见 §13 决策 6）。
- **软删除 / 乐观锁**：五表均带软删除与 `version`（基座 `BaseModel` 口径）；关联表解绑走**软删除**（留痕），表文件同步回写。
- **跨库引用**：一律逻辑外键、无物理外键、无跨库 JOIN（bms《微服务演进规划》S2）。
- **库/链**：`mdm_org_{code}`，`org:tenant` 链。

## 4. 分层与代码落点 <a id="structure"></a>

`api → services → repositories → models / schemas` 单向（bms《后端开发规范》「目录与分层职责」节）：

| 层 | 职责 | 落点 |
| --- | --- | --- |
| `api` | 参数校验、路由分发、权限依赖、返回契约 | `mdm_org/api/{dept,post,user_post,role_post,role_dept}.py` |
| `services` | 业务逻辑、事务边界、部门树算法、事件发布、审计 | `mdm_org/services/` |
| `repositories` | 数据访问、数据源路由、数据范围过滤 | `mdm_org/repositories/` |
| `models` | ORM 模型（继承 `bms_core` `BaseModel`） | `mdm_org/models/` |
| `schemas` | 请求 / 响应模型（集合字段落 `ConcurrentStableList` 等插入序形态） | `mdm_org/schemas/` |

- **集合与排序**：对外契约集合字段落插入序集合类（bms《后端开发规范》「集合与排序」条）；列表排序走排序契约、可排序字段白名单。
- **审计**：业务表经 ORM 事件接入字段级变更审计（复用 `bms_core` 审计捕获）；不手工赋值审计字段。

## 5. 接口设计 <a id="api"></a>

管理面全端点（路径沿用 `org` 域口径 `/api/v1/org/...`；权限码 `org:*`）：

| 方法 | 路径 | 说明 | 权限码 |
| --- | --- | --- | --- |
| GET | `/org/depts` | 部门树（含 status/sort 过滤） | org:query |
| POST | `/org/depts` | 新建部门（parent_id/name/sort） | org:create |
| GET | `/org/depts/{id}` | 部门详情（含 ancestors 路径） | org:query |
| PUT | `/org/depts/{id}` | 修改部门（名称/排序/状态，version 乐观锁） | org:update |
| PUT | `/org/depts/{id}/move` | 移动部门（新 parent_id，级联 ancestors） | org:update |
| DELETE | `/org/depts/{id}` | 删除部门（有引用拒绝，软删除） | org:delete |
| GET | `/org/depts/{id}/users` | 部门（含子树）归属用户列表 | org:query |
| GET | `/org/depts/{id}/roles` | 部门角色分配回显 | org:query |
| GET | `/org/posts` | 岗位列表（page/size；dept_id/status/关键字） | org:query |
| POST | `/org/posts` | 新建岗位 | org:create |
| GET | `/org/posts/{id}` | 岗位详情 | org:query |
| PUT | `/org/posts/{id}` | 修改岗位（version 乐观锁） | org:update |
| DELETE | `/org/posts/{id}` | 删除岗位（有引用拒绝，软删除） | org:delete |
| GET | `/org/posts/{id}/users` | 岗位下用户列表 | org:query |
| GET | `/org/posts/{id}/roles` | 岗位角色分配回显 | org:query |
| GET | `/org/user-posts` | 按用户查已分配岗位（供插件与列表回显） | org:query |
| PUT | `/org/user-posts/{user_id}` | 全量覆盖分配用户岗位（插件写入口） | org:update |
| DELETE | `/org/user-posts/{user_id}/{post_id}` | 解绑单个用户-岗位 | org:update |
| GET | `/org/role-posts` | 按角色列已分配岗位（「岗位分配」插件） | org:query |
| PUT | `/org/role-posts/{role_id}` | 全量覆盖分配角色岗位（插件写入口） | org:update |
| DELETE | `/org/role-posts/{role_id}/{post_id}` | 解绑单个角色-岗位 | org:update |
| GET | `/org/role-depts` | 按角色列已分配部门（「部门分配」插件） | org:query |
| PUT | `/org/role-depts/{role_id}` | 全量覆盖分配角色部门（插件写入口） | org:update |
| DELETE | `/org/role-depts/{role_id}/{dept_id}` | 解绑单个角色-部门 | org:update |

- **分页 / 幂等 / 限流**：列表 `page/size`，响应 `{list, total, page, size}`；写接口支持 `Idempotency-Key`（Redis SETNX + 唯一约束兜底）；写操作按用户维度叠加限流。
- **数据范围 / 脱敏**：实现侧强制接入（调用方不可绕过），与 bms 口径一致。
- **只读出口与按用户解析角色**（组织数据源 / 名称回显 / `/org/user-roles`）归 **01_03**，不在本任务。

## 6. 关键逻辑 <a id="logic"></a>

| 逻辑 | 规则 |
| --- | --- |
| 部门新建 | 生成 `ancestors` = 父 `ancestors` + 父 id（如 `/1/5/` → 子 `/1/5/9/`）；根部门 `parent_id` 空、`ancestors` = `/` |
| 部门移动 | **防环**：新父不能是自身或其后代（`ancestors` 不在自身子树内）；同事务级联更新子树全部 `ancestors`；发布 `org.dept.changed` |
| 部门删除 | 引用检查（子部门 / 岗位 / `org_user_post` 关联的岗位 / 角色分配）→ 无引用则软删除；有引用拒绝并明确提示引用对象；同事务校验+删除 |
| 岗位 code | 租户内唯一（复合唯一 `(code, deleted_at)`）；格式受 `org.post_code_pattern` 约束；创建后不可改 `code` |
| 岗位归属部门 | 必须存在且启用（`org_dept.status=enabled`） |
| 用户-岗位分配 | 多对多；全量覆盖为「diff 后增删」单事务；单用户岗位数受 `org.post_max_per_user` 上限约束 |
| 角色-岗位 / 角色-部门 | 全量覆盖为「diff 后增删」单事务；`role_id` 对 bms 角色逻辑外键（不下库校验，由平台角色存在性保证） |
| 删除约束 | 岗位有关联用户 / 角色分配时禁删；部门有子部门 / 岗位 / 角色分配时禁删 |
| 用户删除联动 | 消费 `sys.user.deleted` → 清理该用户 `org_user_post`（`org_role_*` 不随用户，按岗位 / 部门维度） |
| 并发 | 业务表 `version` 乐观锁（冲突转统一并发冲突错误）；移动 / 覆盖分配为单事务 |

## 7. 权限 / 审计 / 事件 / 配置 <a id="perm"></a>

- **权限码**：域级 `org:query` / `org:create` / `org:update` / `org:delete`（部门与岗位共用）；域专属动作 `org:move`（移动）按《[mdm 英文简称规范](../../../../../../规范/英文简称规范.md)》登记。权限校验依赖经 `bms_core` 权限基座（`require_permission`）。
- **审计**：写操作经基座 `AuditCapturer` **占位**接入（同 identity / platform 现役口径；字段级真实审计落库随审计阶段）+ 结构化操作日志（记动作权限码）；**不新增 ORM 事件自研审计**（能力必须走基座）。
- **事件**：`org.dept.changed` / `org.post.changed` / `org.user_post.changed` / `org.role_post.changed` / `org.role_dept.changed`（经平台事件总线发布）；**5 条事件契约随本任务登记**（`mdm_org/events/contracts.py` + 经 `register_product_event_contracts()` 注入 + 快照），01_03 只做只读出口与按用户解析角色。
- **配置**：`org.dept_tree_max_depth`（默认 10）、`org.dept_max_children`（默认 500）、`org.post_code_pattern`、`org.post_max_per_user`（默认 10）经平台系统参数 / mdm 配置读取，不硬编码；**服务包名前缀** `[app].package_prefix = "mdm"`（迁移链按 `mdm_org.models` 取模型，见 §13 决策 7）。

## 9. 失败分支与边界 <a id="edge"></a>

| 场景 | 处置 |
| --- | --- |
| 移动形成环 | 拒绝，抛 `330053` |
| 删除有引用 | 拒绝，抛 `330054` / `330055` / `330056`（区分引用对象） |
| code 冲突 / 格式非法 | 抛 `330032` / `330036` |
| 归属部门不存在 / 停用 | 抛 `330033` |
| 乐观锁冲突 | 转统一并发冲突错误（可重试） |
| 用户-岗位超上限 | 抛 `330072` |
| 事件发布失败 | 不影响主事务（`bms_core` 事务性 Outbox 保证库↔事件原子，投递重试） |
| `sys.user.deleted` 消费 | 幂等（去重），重复事件只清理一次 |
