## 2. 任务内容 <a id="content"></a>

1. **内部写端点（服务身份通道）**：新增**服务间直连**写通道（`require_service("platform")` 白名单；东西向不经网关；**不挂 `org:*` 权限码**，与只读出口双通道口径同构）——四组「全量覆盖 + 主要项」提交：`PUT /api/v1/org/internal/user-posts/{user_id}`、`/internal/user-depts/{user_id}`、`/internal/role-posts/{role_id}`、`/internal/role-depts/{role_id}`（body 为对应全量集合 + 主项 id）。
2. **基线读取（快照）**（**过渡期用途**——仅服务 `[transaction_manager].provider = null` 的最终一致基线；启用 `xa` 后**退出主链路**）：同通道提供**只读基线**端点（`GET /internal/...`，与写端点同路径族）：返回「当前生效集合 + 主要项」，供 bms 编排在保存前**记两侧基线快照**（基线模型下用于失败写回；**强一致启用后不再需要**）。
3. **幂等与返回**：端点接受**宿主编排生成的同一业务幂等键**（`Idempotency-Key`）；同键重复提交返回同结果；响应返回**生效后的集合 + 主要项**（供编排比对与屏障判定）。
4. **收敛标记（屏障判据）**（**过渡期用途**，同上）：写成功后在缓存域写入**租户级收敛版本**（`org:assign:applied:{tenant}`），并提供内部只读查询（`GET /internal/applied-version`）——供 bms 编排侧屏障判定「组织侧变更已应用」；未达成立即返回可重试错误（`10011` / 409 由消费方判定）。
5. **口径不放松**：内部端点复用**同一套服务层**（校验 / 事务 / 事件 / 失效代 / 审计），不得因「内部通道」绕过任何校验；公开契约快照按**内部路径白名单**登记（不进对外可见面）。
6. **测试与登记**：先登记 Kiwi 用例再编码；实施与测试记录随任务留痕。
7. **强一致接入（跨仓口径，2026-10-09）**：本体（platform）与组织分配（mdm）的原子性改由 bms [05_07 跨服务事务管理器（强一致专项）](../../../../../../../bms文档/项目/02_后端基座与服务化地基/任务/05_服务间通信与一致性/05_服务间通信与一致性_07_跨服务事务管理器强一致专项/05_服务间通信与一致性_07_跨服务事务管理器强一致专项.md) 的 **TM + 各服务 XA 分支**保证（`prepare` 前两侧变更均不可见 ⇒ **不会出现「一侧已改、另一侧未改」**）——本任务须按该专项 §5 增挂 **XA 分支执行端点**（`POST /api/v1/txn/branches`：**调用方服务身份** + 业务载荷；单请求内 `XA_START` → 业务写（**复用同一套服务层**）→ `XA_END` → `XA_PREPARE`）与 `commit` / `rollback` / 分支状态查询（`require_service("txn")`）；**废除**「快照回滚 + 落待人工」措辞（恢复原语是**幂等重放**，人的动作只允许「重放」，**禁止手工改数据**）。

## 3. 完成标准 <a id="accept"></a>

服务身份 `platform` 经内部端点完成「用户-部门 / 用户-岗位 / 角色-岗位 / 角色-部门」四组全量覆盖与主要项提交（幂等、校验与事件与公开面同源）；非白名单服务身份被拒（`20001` / 401）；基线读取与收敛版本查询可用（屏障判定有据）；公开契约快照与 `@mdm/api-types` 零漂移；`pytest` / `ruff` / `pyright` 与模块 / 契约 / 事件门禁全绿。
