## 1. 设计目标与范围 <a id="goal"></a>

### 1.1 目标

bms 用户 / 角色的**宿主保存编排**（bms `02_02/_01` 用户侧、`02_03/_02` 角色侧）需要以**服务身份**跨服务写入组织分配数据——写「平台侧用户 / 角色本体」与写「组织侧分配」必须在**同一业务流程**内完成，而组织侧数据归 mdm 组织域，**不能经面向用户的公开面**（`org:update` 权限码属登录态通道、且东西向不应绕网关）。

故本任务在 mdm `org` 服务新增**内部通道**（东西向、服务身份白名单）：① 四组「全量覆盖 + 主要项」写端点；② 基线读取（快照）；③ 收敛版本标记与查询；④ **XA 分支执行端点**（强一致专项接入面）。

### 1.2 范围

| # | 内容 | 说明 |
| --- | --- | --- |
| 1 | 内部写端点（服务身份） | `PUT /api/v1/org/internal/{user-posts,user-depts}/{user_id}`、`PUT /api/v1/org/internal/{role-posts,role-depts}/{role_id}`；body＝全量集合 + 主项 id |
| 2 | ~~基线读取（快照）~~ | **已按拍板删除**（强一致已就绪，属废路径；见 §4） |
| 3 | ~~收敛版本~~ | **已按拍板删除**（同上） |
| 4 | XA 分支执行端点 | 挂基座 `build_branch_router()`（`/api/v1/txn/branches*`）+ 登记四组分配 `op` 处理器 |
| 5 | 门禁与登记 | 公开契约快照按内部路径白名单登记；服务目录 / 事件契约 / 模块探针；Kiwi 用例先登记再编码 |

### 1.3 不在本期

- **不改**公开面（`/api/v1/org/user-posts*` 等）的鉴权与语义——内部通道**复用同一套服务层**，不新增业务逻辑分支。
- **不做**跨服务事务的调用方编排（归 bms `02_02/_01` / `02_03/_02` 与 bms `05_07` 的 TM）。
- **不新建** mdm 侧独立账本 / 恢复器（TM 归 bms `05_07`，mdm 只作为**参与方**挂分支端点）。
- **不引入** `sys_user.dept_id` 通道（`_02` 已注销）。

## 2. 端点与契约 <a id="api"></a>

### 2.1 内部写 / 读端点（服务身份通道）

| 方法 | 路径 | 语义 | 鉴权 |
| --- | --- | --- | --- |
| `PUT` | `/api/v1/org/internal/user-posts/{user_id}` | 全量覆盖用户岗位 + 主要岗位 | `require_service("platform")` |
| `PUT` | `/api/v1/org/internal/user-depts/{user_id}` | 全量覆盖用户部门 + 主要部门 | 同上 |
| `PUT` | `/api/v1/org/internal/role-posts/{role_id}` | 全量覆盖角色岗位 | 同上 |
| `PUT` | `/api/v1/org/internal/role-depts/{role_id}` | 全量覆盖角色部门 | 同上 |

> **拍板变更（2026-10-09，§9 决策点 3）**：**不实施**基线快照读端点与收敛版本（`GET /internal/...` / `GET /internal/applied-version`）——强一致专项（bms `05_07`）已交付，`provider = null` 的过渡期基线与屏障判据属**废路径**，直接删除该口径。编排所需的「生效后集合」由写端点响应回带（下方响应体），**无需**独立读取端点。

**请求体（写）**：`{ "<ids>": [int...], "primary_id": int \| null }` —— 命名与各公开面一致（`post_ids` / `dept_ids`），角色侧无主项则不接受 `primary_id`（传了即 `330010` 参数错误）。

**响应体**：`{ "<ids>": [int...], "primary_id": int \| null }` —— 回**生效后**的集合与主项（供编排比对与幂等回放）。

**语义**：完全复用 `UserPostService.assign_user_posts` / `set_primary_post`（及 `UserDeptService` / `RolePostService` / `RoleDeptService`）——同一事务、同一校验（上限 / 不存在 / 主项归属）、同一事件、同一 `user-roles` 失效代推进。**写端点内部先全量覆盖、再置位 / 清除主项**（两段幂等，与前端提交器口径一致）。

### 2.2 契约可见性

内部路径**不挂 `org:*` 权限码**（与只读出口双通道同构），但**仍进公开契约快照**（`ops.contract_snapshot` 按路径登记，消费方 `@mdm/api-types` 需类型）——但**不进面向产品前端的可见面**（前端不调用；由 `deploy/contracts` 白名单确认，见 §9 决策点 1）。

## 3. 鉴权、幂等与审计 <a id="guard"></a>

1. **双通道**：内部面**仅**接受服务身份令牌（`aud=service`）且签发方（`iss`/`sub`）在**调用方白名单**内＝`platform`（bms 平台服务）；登录态令牌一律拒绝（`10010` / 401）；非白名单服务身份拒绝（`20001` / 401）。实现复用基座 `require_service("platform")`（与出口 `require_org_reader` 的服务通道同源口径，故内部面无旁路）。
2. **幂等**：接受 `Idempotency-Key`（宿主编排生成的**同一业务幂等键**）；同键重复提交返回**同结果**（载荷回放）。键按 `tenant` 归一（`build_idempotency_key`），与公开面同一存储。
3. **审计**：与公开面同一 `AuditCapturer`（内部通道不放松），`actor` 取服务主体（服务身份下 `current_user_id` 为空 → 记录为服务签发者，见 §9 决策点 2）。
4. **限流 / 校验 / 事件 / 失效代**：全部沿用公开面（不可因「内部」绕过）。

## 4. 基线快照与收敛版本（**已按拍板删除**） <a id="barrier"></a>

> **拍板结论（2026-10-09，§9 决策点 3）**：**不实施**。理由——强一致专项（bms `05_07` 跨服务事务管理器）**已交付**，平台侧与组织侧的原子性由 **TM + 各服务 XA 分支**保证（`prepare` 前两侧变更均不可见 ⇒ 不会出现「一侧已改、另一侧未改」），故：

| 原设计项 | 处置 |
| --- | --- |
| 基线快照读端点（`GET /internal/...`） | **不建**；编排所需「生效后集合」由写端点**响应回带**（§2.1 响应体） |
| 收敛版本（`org:assign:applied:{tenant}`）与 `GET /internal/applied-version` | **不建**（缓存键与查询端点均不引入） |
| 屏障判据 | **不建**；`provider = null` 的本地基线不再提供「组织侧已应用」判据（回退路径无屏障，属**已知取舍**） |
| 失败恢复原语 | 沿用 §5 第 4 条：**幂等重放**；**禁止手工改数据** |

*保留此节仅为变更留痕*：原「过渡期基线 + 屏障」口径**作废**，与本任务文档第 2、4 条同步删除。

## 5. 强一致接入（XA 分支） <a id="xa"></a>

按 bms `05_07` §5 接入面，mdm 作为**参与方**：

1. **挂载分支端点**：在 `org` 服务 `service_routers()` 增挂基座 `build_branch_router()`（`POST /api/v1/txn/branches`：**调用方服务身份** + `{xid, db_key, op, args}` → 单请求内 `XA_START → 业务写 → XA_END → XA_PREPARE`；`commit` / `rollback` / 状态 / 悬挂列举＝`require_service("txn")`）。
2. **登记分支处理器**：`app.state.branch_handlers` 登记四个 `op`（`org.user-posts.assign` / `org.user-depts.assign` / `org.role-posts.assign` / `org.role-depts.assign`），每个处理器**只调本域已有服务层方法**（`assign_*` + `set_primary_*`），不复制业务逻辑。
3. **配置**：`[transaction_manager].provider` 缺省 `null` ⇒ 参与方为占位实现（分支端点**明确拒绝** `10013` / 503，不静默降级）；启用 `xa` 后生效。
4. **恢复原语**：失败处理＝**幂等重放**（TM 重驱动分支）；**废除**「快照回滚 + 落待人工」措辞；人的动作只允许「重放」，**禁止手工改数据**。

## 9. 待拍板决策点 <a id="decision"></a>

| # | 决策点 | 建议 |
| --- | --- | --- |
| 1 | 内部路径是否进**公开契约快照**（消费方 `@mdm/api-types` 需类型；但前端不调用） | 进快照 + 类型（消费方是 bms 后端 / 编排，不进产品前端可见面）——与只读出口「不进面向产品前端」口径并存 |
