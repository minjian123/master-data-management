## 3. 实施过程 <a id="process"></a>

1. **上下文与决策**：按《AI开发规范》读 bms 规范（后端开发规范 / 数据库开发规范 / 数据规范 / 基类清单 / 架构 09·11）、bms `12_04` 实施与代码、mdm 需求 01-2 / 任务 01_02 / 详设 / 数据库设计 5 表文件 / 计划。
   - **待拍板事项逐项确认（question 工具，共 16 项）**：表归属落点（基座新增注入通道）、服务包模型解析（配置驱动包名前缀）、关联表主键（规范向实现收口）、审计接入（基座占位）、事件契约时点（随本任务登记）、权限码与种子（bms 侧登记）、契约基线（随 01_03）、横切能力范围、覆盖率口径、bms 登记方案、台账回写。
   - **实施中发现并回写设计的偏差**：① 关联表主键口径（原「联合主键、不设 `id`」与基座冲突）→ 拍板修订；② 事件契约登记从 01_03 前移（`[event].contract_mode` 缺省 `enforce` 会拒发）；③ 审计落基座占位（基座无 ORM 事件自动捕获）；④ 补充错误码 `330058` / `330059`；⑤ `org:tenant` 链需补齐基础设施三表迁移（发件箱 / 消费幂等 / 死信），否则运行期事件发布无表可用且迁移与模型漂移。
2. **跨仓前置消费**：把 `backend/pyproject.toml` 的 `[tool.uv.sources] bms-core.rev` 从 `9f05b2767` 升级到 `f77c326a7`（bms `12_04` 已推送提交），`uv lock && uv sync` 后验证新基座 API（`register_table_records` / `table_ownership_view` / `service_model_modules` / `require_service_model_modules`）可用。
3. **详设对齐回写**：更新详设（交付物清单 / 数据模型口径 / 审计 / 事件 / 配置 / 登记落点 / 边界开放项 / 决策记录 / 新增 §13.1 跨仓对齐记录）。
4. **Kiwi 先登记后编码**：登记输入 `test/scripts/kiwi/cases/2026-10-07_mdm阶段一01-02_组织主数据域实现.json`（经 `register_cases.py` 走 Kiwi 容器 Django shell），平台回读编号 **2255**；用例代码以 `@pytest.mark.kiwi_id(2255)` 标注。
5. **表文件回写（先改表文件）**：三张关联表（`org_user_post` / `org_role_post` / `org_role_dept`）改为「雪花 `id` 主键 + 业务列复合唯一 `(x_id, y_id, deleted_at)` + 软删除 + `version`」，补 `id` / `updated_at` / `updated_by` / `deleted_at` / `version` 行、索引段与变更记录 v2；mdm《数据库设计总览》同步修订关联表口径行并把登记状态置。
6. **模型层**：新建 `mdm_org/models/{dept,post,user_post,role_post,role_dept}.py`（均继承基座 `BaseModel`）并把五模块登记进 `models/__init__.py::MODEL_MODULES`；新建 `mdm_org/errors.py`（组织域 `33xxxx` 错误码与异常，统一并发冲突沿用基座）。
7. **迁移**：`org/tenant/0001_org_tables.py`（链首，业务五表 + 唯一约束 + 业务索引 + 软删索引）与 `0002_outbox_tables.py`（基础设施三表，字段与索引与基座模型逐项一致）。
8. **仓储层**：五个仓储继承 `BaseDbRepository`，声明 `model` / `sortable_fields`，实现列表筛选 + 计数同口径（`_scope_where()` + `_filter_conditions()`）、岗位码 / 父子名称 / 关联双向查询与引用计数。
9. **服务层**：`DeptService`（树算法：`ancestors` 路径 / 防环 / 同事务级联移动 / 深度与子节点上限 / 引用检查删除）、`PostService`（编码唯一与格式 / 归属部门校验 / 删除引用 / 乐观锁比对）、`UserPostService` / `RolePostService` / `RoleDeptService`（全量覆盖 diff 后增删单事务 / 解绑 / 用户删除清理幂等）；**写方法一律以 `async with uow.begin()` 包住「读 + 写」**（SQLAlchemy 2.0 先读后 `begin` 会因自动开启事务报错）。
10. **契约与路由**：`schemas/*`（集合字段 `Annotated[ConcurrentStableList[...], CONTRACT_COLLECTION]`）、`api/*`（`BaseRouter` + `require_permission("org:*")` + `Idempotency-Key` + `AuditCapturer` 占位 + 限流依赖位）；路由前缀按域口径 `/org/...`（对外经平台网关产品命名空间 `/api/mdm/v1/org/...`）。
11. **表归属自持与配置**：新建 `backend/services/table_registry.py`（`MDM_TABLE_RECORDS` + `register()`）并在应用装配钩子（`ApplicationFactory.table_records()`）、`alembic/env.py`、`ops/migrate.py` 装载期注册；`config.toml` 增 `[app].package_prefix = "mdm"`。
12. **事件契约**：新建 `mdm_org/events/contracts.py`（5 条 `org.*` 契约 + 字段规格）与 `mdm_org/events/__init__.py`（暴露 `register_product_event_contracts(registry)`）；`main.py` 模块级登记进默认注册表；新增 `backend/ops/event_contracts.py`（产品侧快照导出 / 零漂移 + 兼容校验）并接入 CI `backend-modules`。
13. **用例**：`services/org/tests/{dept,post,assignment}/`（部门树 / 防环 / 引用拒绝 / 上限；岗位 CRUD / 唯一与格式 / 删除引用 / 乐观锁 / 分页；分配 diff / 上限 / 解绑 / 用户删除清理 / 角色两向 / 部门用户聚合）、`tests/`（表归属注入、模型声明、迁移零漂移与降级、事件契约与快照）+ `tests_support/org_env.py`（内存库 + 服务装配支持）。
14. **验证**：见 §5；**记录**：见 §6 / §7。
