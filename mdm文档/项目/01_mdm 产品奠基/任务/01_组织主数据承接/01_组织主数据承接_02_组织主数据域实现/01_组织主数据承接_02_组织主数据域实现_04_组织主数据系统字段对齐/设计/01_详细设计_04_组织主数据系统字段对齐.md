## 1. 目的与口径 <a id="purpose"></a>

按 bms《数据库开发规范》「系统字段」节（§3.1.3 字典 5 项 / §3.1.4 对齐口径）与需求 [01-5](../../../../../需求/01_需求_组织主数据承接.md#r01-5)，把 mdm 组织主数据表的系统字段缺项补齐：

- **`form_key`（表单标识）**：`VARCHAR(64)`、`(form_key, deleted_at)` 复合唯一、**保存后不变**；核心用途是**多表联合（union）取数的表判别列**（同表所有行同值、每表常量）。
- **`parent_id`（上级字典 ID）**：`BIGINT` 自引用同表 `id`（非层级字典按口径**保留冗余**，恒 `NULL`）。
- **唯一事实源**：表结构（字段 / 类型 / 约束 / 索引）**只在各表文件维护**（`mdm文档/设计/数据库设计/数据表设计/{表名}.md`）；本设计只写**变更增量**，不复刻字段清单；通用约定以 bms《数据库设计 · 数据规范》为权威源（mdm 不复制）。
- **变更传导（强制）**：**先改表文件（追加变更记录）→ 改 ORM 模型 → 新增迁移 → 回写状态**；表文件 ↔ 模型 ↔ 迁移**零漂移**。

**不在本期**：4 张关联表（`org_user_dept` / `org_role_dept` / `org_role_post` / `org_user_post`）不落 `form_key` / `parent_id`（关联表不套明细口径）；`FormRecord.data_source_key` 回填（归 bms `02_10`，本任务只保证**同名闭合**成立）；界面「系统信息」展示（归通用页面路由 / 表单框架阶段）。

## 4. 表文件变更口径 <a id="table-files"></a>

每张受影响表文件改三处（`org_dept` 只改两处：`parent_id` 已在）：

1. **`## 2. 字段` 节**：`form_key` 行插在 `id` 之后（字典系统字段首位）；说明列标注为系统字段；`org_post` 另加 `parent_id` 行（可空、说明「非层级字典按系统字段口径保留冗余，顶层 `NULL`」）。
2. **`## 3. 索引与约束` 节**：补 `uq_{表}_form_key_deleted_at`（`(form_key, deleted_at)`，软删除后可释放）。
3. **`## 5. 变更记录` 节**：追加 `2026-10-22 | v3 | …`，与迁移 `0005_org_form_key` 一一对应。

**索引计数说明（偏差登记）**：`org_dept` 加列后业务索引 5 ＋ 新增唯一约束 1 ＝ 6，另有基座公共 `idx_org_dept_deleted_at`（《数据规范》「公共软删除索引」节，表文件不列），合计 7，超出「每表 ≤ 5」提示值。**判定**：`form_key` 复合唯一为规范强制（§3.1.3），不可省；既有 `idx_org_dept_status`（低选择性）与 `idx_org_dept_parent_id`（逻辑外键）均有用，暂不去冗余——与 bms `02_11` 对字典表的处理同口径，登记于此，后续如整治索引统一立项。

## 5. ORM 模型变更 <a id="models"></a>

- **`mdm_org/models/dept.py::OrgDept`**：
  - 新增 `DEPT_FORM_KEY = "org_dept"` 常量；
  - 新增列 `form_key: Mapped[str] = mapped_column(String(64), default=DEPT_FORM_KEY, comment="表单标识（全局唯一；保存后不变）")`（`default` 为应用侧缺省，**写入路径不改业务代码**）；
  - `__table_args__` 增 `UniqueConstraint("form_key", "deleted_at", name="uq_org_dept_form_key_deleted_at")`。
- **`mdm_org/models/post.py::OrgPost`**：
  - 新增 `POST_FORM_KEY = "org_post"` 常量；
  - 新增列 `form_key`（同上形态，`default=POST_FORM_KEY`）；
  - 新增列 `parent_id: Mapped[int | None] = mapped_column(BigInteger, nullable=True, comment="上级字典 ID（自引用同表 id；非层级字典保留冗余，顶层为空）")`（**不建索引**）；
  - `__table_args__` 增 `UniqueConstraint("form_key", "deleted_at", name="uq_org_post_form_key_deleted_at")`。
- **不落 `BaseModel`**：`form_key` 只在字典表具体模型声明（§3.1.1 基础字段不含 `form_key`），**不动** `bms_core/models/base.py`。
- **仓储 / 服务 / 契约零改动**：`form_key` 为每表常量、由模型缺省提供；管理面与只读出口的 Pydantic 契约按显式字段声明，不受新列影响（决策 3）。

## 6. 迁移设计 <a id="migration"></a>

### 6.1 链与编号 <a id="migration-chain"></a>

| 链 | 新迁移 | `down_revision` | 目标表 |
| --- | --- | --- | --- |
| `org:tenant` | `0005_org_form_key`（`alembic/versions/org/tenant/0005_org_form_key.py`） | `0004_user_dept_and_primary` | `org_dept` / `org_post` |

### 6.2 DDL 口径（四库通用） <a id="migration-ddl"></a>

1. `org_dept`：`batch_alter_table` 加 `form_key`（`VARCHAR(64)`、`nullable=False`、`server_default='org_dept'`）→ **独立 batch** 移除 `server_default` 并 `create_unique_constraint("uq_org_dept_form_key_deleted_at", ["form_key", "deleted_at"])`。
2. `org_post`：同上加 `form_key`（`server_default='org_post'`）＋ `parent_id`（`BIGINT`、`nullable=True`、无缺省）→ 独立 batch 移除 `form_key` 的 `server_default` 并建同名唯一约束。
3. **存量数据**：`form_key` 由 `server_default` 回填（每表同值），`parent_id` 保持 `NULL`，**无业务回填**。
4. **`downgrade`**：逐项反向（删 `org_post` 唯一约束 → 删 `parent_id` → 删 `org_post.form_key`；删 `org_dept` 唯一约束 → 删 `org_dept.form_key`）。
5. **方言**：全程 `op.create_table` / `batch_alter_table`（SQLite 走重建表）、不含方言专用类型；`(form_key, deleted_at)` 复合唯一在 MySQL / PostgreSQL 下 `NULL` 互异（同表多行不受约束力），**全局唯一由清单校验承担**，与 bms `02_11` 同口径；达梦 `NULL` 语义差异沿用既有归口（bms《方言特性 · DM8》），本任务不另做方言实现。

## 7. 产品 `form_key` 注入通道 <a id="injection"></a>

### 7.1 bms 侧（应用装配钩子） <a id="injection-bms"></a>

| 落点 | 变更 |
| --- | --- |
| `bms_core/application.py` | `BaseServiceApplicationFactory` 新增钩子 `form_records()`（缺省空清单，文档口径同 `service_records()` / `table_records()`）；`create()` 内 `injected_forms = ConcurrentStableList(self.form_records())`，置 `app.state.form_registry = FormRegistry(merge_form_records(injected=injected_forms))` 与 `app.state.form_injected_records`（**应用级视图**，无进程级注册表、不改 `FORM_CATALOG` 常量） |
| `bms_platform/api/form_key.py` | `GET /api/v1/form-keys` 改读**应用级视图**（`request.app.state.form_registry.catalog_records()`），不再直接 `merge_form_records()`；平台服务未注入时视图严格等于 `FORM_CATALOG`，行为不变 |
| 用例 | `libs/bms_core/tests/core/test_product_service_assembly.py` 增 `form_records()` 注入断言（Kiwi 2251 同一验收项）；`services/platform/tests/api/test_form_keys_api.py` 增「端点读应用级视图」用例（Kiwi 2292 同一验收项） |

**跨服务可见性边界（已知并登记）**：`/api/v1/form-keys` 由 **bms platform 服务**提供，产品服务（mdm `org`）是**独立部署**，其注入记录只进 **mdm 自身应用**的应用级视图，**不会**自动出现在 platform 的响应里。跨服务可见性需 bms 侧「产品清单下发 / 聚合」通道（与 `DATA_SOURCE_CATALOG` 现以「跨项目示例」直接登记产品的做法同源待统一），**归口见 §12 遗留 1**；本任务交付的是**通道本体**（钩子 + 视图 + 产品自持清单 + 守卫），产品记录一旦被任何宿主装配即可见。

### 7.2 mdm 侧（产品自持清单） <a id="injection-mdm"></a>

- 新增 `mdm/backend/services/form_registry.py`（与 `table_registry.py` 同构）：
  - `MDM_FORM_RECORDS: tuple[FormRecord, ...]`——`org_dept` / `org_post` 两条（`kind=dict`、`status=enabled`、`data_source_key` **同名** `org_dept` / `org_post`、名称「部门」/「岗位」）；
  - `form_records() -> ConcurrentStableList[FormRecord]`、`form_record(表名)`、`form_keys()` 取数助手（供用例与运维核对）。
- `mdm_org/main.py::ApplicationFactory` 覆写 `form_records()` 返回本产品清单（与 `table_records()` 并列）。
- **校验侧**：`FormRegistry.validate()` 的 `data_source_key` 只校验「非空 + 格式」（bms `02_10` 口径：产品注入记录的数据源不在 bms 清单内，成员校验由 bms 侧脚本对 bms 清单断言），故 mdm 侧**不重复**做 bms 清单成员校验，只断言**同名闭合**。

## 8. mdm 校验脚本 <a id="guard"></a>

新增 `mdm/backend/ops/check_forms.py`（`uv run python -m ops.check_forms`，离线、无库依赖）：

| # | 断言 |
| --- | --- |
| 1 | `MDM_FORM_RECORDS` 非空、`form_key` / `table` / `data_source_key` 格式合法（`^[a-z][a-z0-9_]*$`） |
| 2 | 跨表全局唯一：`form_key` 不重复、`table` 不重复 |
| 3 | **同名闭合**：`data_source_key == form_key`（1:1，与 bms `DATA_SOURCE_CATALOG` 的 `org_dept` / `org_post` 对齐） |
| 4 | 模型侧一致：每条记录的表在 `Base.metadata` 中存在、含 `form_key` 列、列缺省值等于清单值、存在 `uq_{表}_form_key_deleted_at` 复合唯一 |
| 5 | **反向**：`Base.metadata` 中凡含 `form_key` 列的表须登记进清单（防「表落了字段却没进清单」） |
| 6 | 字典表必带 `parent_id` 列；4 张关联表**不得**含 `form_key` / `parent_id`（口径一致） |
| 7 | `FormRegistry(MDM_FORM_RECORDS).validate()` 返回空（复用基座校验） |

冲突 / 非法 → 打印明细并退出码 1；通过 → 退出码 0。纳入 mdm 后端本地预检（`ruff` / `pyright` / 定向 `pytest` 之外的独立一步）。
