## 2. 任务内容 <a id="content"></a>

**口径来源**：bms《数据库开发规范》「系统字段」节（§3.1.3 字典 5 项 / §3.1.4 对齐口径）；bms 任务 `02_11`（系统字段 `form_key` 落表）交付口径——**字典表 = 基础系统字段 ＋ `form_key`（表单标识）/ `code` / `name` / `status` / `parent_id`**。`form_key` 为**多表联合（union）取数的表判别列**（同表所有行同值、每表常量、全局唯一、保存后不变）。

1. **`org_dept`**：落 `form_key`（＝ `org_dept`）＋ `(form_key, deleted_at)` 复合唯一（`code` / `name` / `parent_id` / `status` 已备，无需增补）；
2. **`org_post`**：落 `form_key`（＝ `org_post`）＋ `parent_id`（非层级字典按系统字段口径保留冗余，顶层 NULL）；
3. **4 张关联表不处置**：`org_user_dept` / `org_role_dept` / `org_role_post` / `org_user_post`——关联表不套明细口径，不落 `form_key` / `parent_id`；
4. **三处零漂移**：表文件（含变更记录）→ ORM 模型 → `org:tenant` 链新增一条迁移；
5. **清单登记**：`form_key` 值登记进 bms `form_key` 构建期清单的产品注入通道（`bms_core/registry/forms.py`），满足**跨表全局唯一**；
6. **跨仓协同**：bms 侧 `FormRecord.data_source_key`（`form_key → data_source_key` 多对一）由 bms `02_10` 回填，本任务不涉及。

> 详细设计（逐表字段、迁移编号、清单注入方式与测试映射）随后续开发窗口另出——本任务**仅立项**。

## 3. 完成标准 <a id="accept"></a>

- □ `org_dept` / `org_post` 落 `form_key`（`org_post` 另落 `parent_id`），迁移可跑（表文件 ↔ 模型 ↔ 迁移零漂移）
- □ `form_key` 登记进 bms 构建期清单且跨表全局唯一
- □ 4 张关联表未落 `form_key` / `parent_id`（口径一致）
- □ `pytest` / `ruff` / `pyright` 与定向用例全绿
