## 1. 设计目标与范围 <a id="goal"></a>

bms 阶段七用户管理页原型对齐「表单框架」时确认：**用户-部门关系应与其他组织关系一致归 mdm**（原 bms `sys_user.dept_id` 单值逻辑外键设计取消——cws 无 mdm 时该字段恒空且无对象可指，且不支持「一人多部门」），并需为「用户所属岗位 / 部门」补**主要项**（同用户至多一个主要岗位、至多一个主要部门）。本任务在 mdm `org` 服务内落地该能力：

1. **用户-部门多对多**：新建 `org_user_dept`（雪花 `id` 主键 + 审计 + 软删除 + `version`，业务列 `(user_id, dept_id, deleted_at)` 复合唯一），随 `org:tenant` 链迁移落地。
2. **「主要项」标记**：`org_user_dept` 与 `org_user_post` 各增 `is_primary`（布尔，默认假）；**同用户至多一个主要项**由服务侧在写事务内互斥置位保证。
3. **管理面契约**：新增 `/api/v1/org/user-depts`（列表 / 全量覆盖分配 / 解绑，与 `/user-posts` 同构）＋两个**独立置位端点**（`/user-posts/{user_id}/primary`、`/user-depts/{user_id}/primary`）。
4. **只读出口收口**：`OrgUser` **移除 `dept_id`**（恒空字段退场），`_user_dept()` 删除；`/api/v1/org/user-roles` 的**部门链改走 `org_user_dept` 的全部部门**（与岗位链「全部岗位」同口径，修掉「部门链恒空」的现状）。
5. **事件**：新增 `org.user_dept.changed`；既有 `changed_type` 取值扩一个 `primary`（主要项置位 / 清除）。
6. **前端插件**：既有「用户分配岗位」标题改**「岗位分配」**＋新增**「用户分配部门」**（`order` 30），两插件列表各加**「主要」列**（单选、即时提交）。
7. **跨仓同批**：与 bms `02_01` 追加子任务 `_01`（`02_06` 平台用户只读出口移除 `dept_id`）**同批零漂移**；bms `02_02` 追加子任务 `_01`（用户记录页「用户分配」页签）以本任务插件为前置。

**不在本期**：① **不新增带部门过滤的用户清单**（`01_03` 遗留「`users` 部门过滤切平台字段（bms `02_01`）」已注销，`sys_user.dept_id` 通道整体不引入）；② 不建「同用户唯一主要项」的**部分唯一索引**（服务侧保证，避免四库方言差异）；③ 部门链**不做子树展开**（沿用 `user-roles` 既有「精确匹配」口径）；④ 不给 `dept_id` / `post_id` 加物理外键（沿用组织域「无物理外键」口径）；⑤ 不做「主要项迁移 / 批量设默认主要项」类运营工具。

## 2. 口径与决策 <a id="decision"></a>

| # | 待定项 | 结论 |
| --- | --- | --- |
| 1 | 主要项置位契约形态 | **独立置位端点**：`PUT /api/v1/org/user-posts/{user_id}/primary`（body `{post_id}`）、`PUT /api/v1/org/user-depts/{user_id}/primary`（body `{dept_id}`）；**传 `null` ＝ 清除**（主要项可为空） |
| 2 | 主要项唯一性强制手段 | **服务侧同事务互斥置位**（先清该用户既有主要项 → 再置位目标项）；并发由单事务 + 既有仓储更新兜底；用例覆盖并发与跨用户隔离；**不引部分唯一索引** |
| 3 | 部门链数据源 | `user-roles` 部门链改用 `org_user_dept` 的**全部已分配部门**（与岗位链同口径）；**主要项不参与角色解析**（仅表达默认归属） |
| 4 | `OrgUser.dept_id` | **本任务移除**（含出口 `users` 数据源与 `_user_dept()` 消费），与 bms `02_01/_01` 同批零漂移一次到位 |
| 5 | 主要项变更是否发事件 | **复用现有事件**：`org.user_post.changed` / 新增 `org.user_dept.changed`，主要项置位 / 清除时 `changed_type="primary"`（字段规格不变、契约只增不删） |
| 6 | 用户-部门分配上限 | 新增系统参数 `org.dept_max_per_user`（**默认 10**，与 `org.post_max_per_user` 同口径），超限抛 `330112` |
| 7 | 前端「主要」列交互 | 列表加「主要」列（**单选、即时提交**）：点选即调置位端点、再次点选同一项则清除；两插件命名＝「岗位分配」（改名）＋「用户分配部门」（新增，`order` 30） |
| 8 | 用例编号 | 后端 **2271** ＋ 前端 **2272**（先登记取号再回填标注） |

**派生口径（一并定稿）**：

- **迁移编号**：`0004_user_dept_and_primary`（`org:tenant` 链，`down_revision="0003_dept_code"`）。
- **错误码（33xxxx 段顺延，用户-部门块自 `330111` 起）**：`USER_DEPT_NOT_FOUND = 330111`（解绑 / 置位时关联行不存在，对齐 `330071`）、`USER_DEPT_LIMIT_EXCEEDED = 330112`（超上限）、`USER_PRIMARY_NOT_ASSIGNED = 330113`（置位目标不在该用户已分配集合内；岗位 / 部门共用）；分配时目标部门不存在 / 停用**复用既有 `330051 DEPT_NOT_FOUND`**（岗位侧同口径复用 `330031`）。
- **解绑 / 全量覆盖移除主要项时的语义**：若被移除项正是主要项，则**同事务清空主要项**（不留悬空标记），只发 `unassigned` 事件（不额外发 `primary`）。
- **置位目标范围**：仅允许置位**该用户已分配**的岗位 / 部门（不在集合内即 `330113` 拒绝，**不做隐式分配**）。
- **写侧缓存失效**：用户-部门分配 / 解绑（`assigned` / `unassigned`）与主要项变更成功后，均按既有口径推进 `user-roles` 缓存的**租户级失效代**（主要项本身不影响解析，但分配集合影响 → 分配 / 解绑必推；主要项变更沿用同路径调用，无需分支）。
- **幂等**：全量覆盖分配端点沿用 `/user-posts` 既有**幂等键**口径（同键重复提交返回同结果）。

## 3. 数据模型与迁移 <a id="data"></a>

### 3.1 表结构变更

| 表 | 变更 | 约束 / 索引 |
| --- | --- | --- |
| `org_user_dept` | **新建**：`id` / `user_id` / `dept_id` / `is_primary`（BOOL NOT NULL 默认假）＋ 公共列（审计 / 软删除 / `version`） | 唯一 `uq_org_user_dept_user_dept_deleted_at (user_id, dept_id, deleted_at)`；普通索引 `idx_org_user_dept_dept_id (dept_id)` |
| `org_user_post` | 新增 `is_primary`（BOOL NOT NULL 默认假） | 既有唯一与索引不变；**不新增索引**（主要项查询按 `user_id` 走既有唯一索引前导列） |

- 字段口径与变更记录回写表文件：[新建 org_user_dept.md](../../../../../../../设计/数据库设计/数据表设计/org_user_dept.md)、[org_user_post.md（v3）](../../../../../../../设计/数据库设计/数据表设计/org_user_post.md)；总览登记见[数据库设计总览](../../../../../../../设计/数据库设计/01_数据库设计_总览.md)。
- `user_id` → bms `sys_user.id`（**跨服务逻辑外键**）；`dept_id` → `org_dept.id`（同库逻辑外键）；**无物理外键**。
- 解绑走**软删除**（复合唯一含 `deleted_at`，解绑后可重绑），与 `org_user_post` 同口径。

### 3.2 迁移 `0004_user_dept_and_primary`（`org:tenant` 链）

| 步骤 | 动作 | 说明 |
| --- | --- | --- |
| 1 | `op.create_table("org_user_dept", ...)` | 列与约束见 §3.1；公共列复用 `_common_columns()`（对齐 `0001_org_tables` 范式） |
| 2 | `op.create_index("idx_org_user_dept_dept_id", ...)` | 建表后紧接建索引 |
| 3 | `batch_alter_table("org_user_post")` 加 `is_primary` | `nullable=False, server_default=sa.false()` —— 存量行自动取假（「无主要项」） |
| 4 | 同一 batch 内 `alter_column("is_primary", server_default=None)` | 使**库结构与模型一致**（模型以 `default=False` 提供默认，不声明 `server_default`），保迁移零漂移断言 |
| 5 | `downgrade` | 逆序：`drop_column("is_primary")` → `drop_index` → `drop_table("org_user_dept")` |

- 全程经 `batch_alter_table`（SQLite 重建表 + 四库通用写法），不含方言专用类型；布尔落点用基座三库通用逻辑类型（无方言 SQL）。
- **存量数据**：`org_user_dept` 为空表（新建），`org_user_post.is_primary` 存量行取假 → **无业务回填**。

### 3.3 主要项唯一性的并发语义

置位在**单个 `async with self._uow.begin()` 事务**内完成：① 校验目标项属于该用户的已分配集合（否则 `330113`）；② 清空该用户既有主要项（`update ... set is_primary = false where user_id = :uid and is_primary = true`）；③ 置位目标项；④ 发 `primary` 事件并推进缓存失效代。并发下由「单事务 + 行级更新」收敛为**后提交者胜**；用例覆盖「两个置位请求并发 → 最终至多一个主要项」「跨用户互不影响」。

## 5. 接口设计 <a id="api"></a>

| 方法 | 路径 | 说明 | 权限码 |
| --- | --- | --- | --- |
| GET | `/api/v1/org/user-depts/{user_id}` | 该用户已分配部门列表（含 `is_primary`、部门 `code` / `name` / `status`） | org:query |
| PUT | `/api/v1/org/user-depts/{user_id}` | **全量覆盖**分配（body `dept_ids`；支持幂等键） | org:update |
| DELETE | `/api/v1/org/user-depts/{user_id}/{dept_id}` | 解绑单个部门（软删除） | org:update |
| PUT | `/api/v1/org/user-depts/{user_id}/primary` | 置位 / 清除**主要部门**（body `dept_id`，`null` 清除） | org:update |
| PUT | `/api/v1/org/user-posts/{user_id}/primary` | 置位 / 清除**主要岗位**（body `post_id`，`null` 清除）——**`/user-posts` 既有三端点不变**，仅响应增 `is_primary` | org:update |

**失败分支**（统一 HTTP 200 + 统一响应 `code`，同 mdm 既有口径）：

| 场景 | 错误码 |
| --- | --- |
| 分配 / 覆盖时目标部门不存在或停用 | `330051`（DEPT_NOT_FOUND） |
| 解绑 / 置位时该关联行不存在 | `330111`（USER_DEPT_NOT_FOUND） |
| 单用户部门数超上限 | `330112`（USER_DEPT_LIMIT_EXCEEDED） |
| 置位目标不在该用户已分配集合内 | `330113`（USER_PRIMARY_NOT_ASSIGNED） |
| 置位不存在的岗位 | `330031`（POST_NOT_FOUND） |
