## 1. 立项与拍板 <a id="kickoff"></a>

| 项 | 结论 |
| --- | --- |
| 立项 | 2026-10-09（`01_02` 二次追加），投入 **16h**，窗口 2026-10-09；**先行实施**——为 bms 阶段七 `02_01/_01` 与 `02_02/_01` 的共同前置（插件改名越早落地，`02_02` 联调免二次回归） |
| 跨仓来源 | bms 阶段七需求 `07-11`（用户-部门多分配与主要岗位 / 主要部门）；术语边界：组织域＝集团 / 公司 / 部门 / 岗位 / 人员（归 mdm），用户＝系统账号（归 bms platform） |
| 关键决策 | ① 用户-部门关系整体归 mdm（`org_user_dept`），`sys_user.dept_id` 通道**不引入**；② 主要项（`is_primary`）同用户至多一个，独立置位端点、同事务互斥置位；③ 插件改动**进草稿 + 随宿主保存一次提交**（`registerSubmitter` 通道），去「操作（解绑）」列、加「主要」单选列；④ 只读出口**不引入**带部门过滤的用户清单 |
| 交付注 | 任务文档状态 → **已完成**；阶段一计划（头部 / §3 行 / §5 门禁 / §7 台账）与需求 `01-2` 同步回写 |

## 2. 工序与产出 <a id="deliver"></a>

| # | 落点 | 产出 |
| --- | --- | --- |
| 1 | `backend/alembic/versions/org/tenant/0004_user_dept_and_primary.py`（新增） | 建 `org_user_dept`（雪花 `id` + 审计 / 软删除 / `version`，`(user_id, dept_id, deleted_at)` 唯一，`dept_id` 索引）＋ `org_user_post.is_primary`；存量取假、无业务回填；降级往返齐备 |
| 2 | `services/org/src/mdm_org/models/user_dept.py`（新增）+ `models/user_post.py` | 用户-部门模型与主要项字段；主要项唯一性由服务侧事务保证 |
| 3 | `schemas/user_dept.py` / `repositories/user_dept.py` / `services/user_dept.py`（新增） | 多分配全量覆盖 diff、解绑、主要部门置位（目标须已分配，否则 `330113`）；`user_post` 同口径补主要岗位置位 |
| 4 | `api/user_dept.py`（新增）+ `api/user_post.py` | `/api/v1/org/user-depts` 列表 / 全量分配 / 解绑 / 置位；`user-posts` 增主要岗位置位；均需 `org:update`，空值表示清除 |
| 5 | `events/contracts.py` + `events/__init__.py` | 新增 `org.user_dept.changed` 契约并登记（快照零漂移） |
| 6 | `errors.py` | 新增 `330113 USER_PRIMARY_NOT_ASSIGNED`（主要项置位目标不在已分配集合内） |
| 7 | `deploy/contracts/org.json` + `frontend/packages/api-types/src/org.ts` | 契约快照导出与类型重生成（`user-depts` / 置位端点纳入） |
| 8 | `frontend/modules/org/src/services/org-service.ts` | 补 `user-depts` 与主要项置位共 **5 个**服务层端点 |
| 9 | `frontend/modules/org/src/index.ts` + 插件组件 | 四具名插槽插件（用户分配岗位 / **新增用户分配部门** / 岗位分配 / 部门分配）改**草稿 + `registerSubmitter` 随宿主保存**（无通道自提交兜底）；列表加「主要」单选列、去「操作（解绑）」列；上下文改显式注入 `userId` / `registerSubmitter` |
| 10 | `OrgUser` 只读出口模型 | **去 `dept_id`**（`sys_user.dept_id` 通道作废） |

**口径要点**：主要项互斥置位与解绑 / 移除主要项**同事务**完成，避免出现「两个主要项」或「悬空主要标记」；`org_user_dept` 的 `user_id` 对 bms `sys_user.id` 为**逻辑外键**（不跨库、不建物理外键）。

## 4. 偏差与遗留 <a id="open"></a>

| # | 事项 | 归口 |
| --- | --- | --- |
| 1 | 「去操作（解绑）列」为原型口径，解绑改由弹窗分配（全量覆盖）完成 | 设计口径（无动作） |
| 2 | 插件由即时提交改为随宿主保存，依赖宿主 `registerSubmitter` 通道 | 已就绪（bms 阶段五 `05-11` / `05-14`，2026-10-08） |
| 3 | 主要项并发置位（两请求同时置不同目标）依赖服务侧事务与唯一约束兜底，未做行级锁压测 | 后续（如出现并发争用再评估） |
| 4 | 插件写操作乐观并发（多人同改分配） | 计划 §7 台账第 15 条 |
