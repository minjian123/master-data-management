## 2. 任务内容 <a id="content"></a>

1. **用户-部门多对多**：新建 `org_user_dept`（用户-部门关联，与原 `sys_user_post` 同口径迁入路径一致）——雪花 `id` 主键 + 审计字段 + 软删除 + `version`（基座 `BaseModel`），业务列 `(user_id, dept_id, deleted_at)` 复合唯一（解绑走软删除、可重绑）；先落表文件（含变更记录）→ ORM 模型 → `org:tenant` 链迁移。
2. **「主要项」标记**：`org_user_dept` 与 `org_user_post` 各增 `is_primary`（布尔，默认假）——**同一用户至多一个主要部门、至多一个主要岗位**（服务侧在「写分配」事务内校验与互斥置位，含并发；违反返新错误码）。
3. **管理面契约**：新增 `/api/v1/org/user-depts`（用户-部门 分配 / 解绑 / 查询，全量覆盖语义与 `/user-posts` 同构）；`/api/v1/org/user-posts` 增「主要岗位」置位能力（分配请求带 `primary` 或独立置位动作，二者择一由详细设计定）；两契约均暴露 `is_primary`。
4. **只读出口**：组织只读出口按需补用户-部门关系（消费方为 bms 记录页插件与后续数据权限）；**不引入**带部门过滤的用户清单（`sys_user.dept_id` 通道随 bms `07-11` 正式作废——原 `01_03` 遗留「`users` 部门过滤切平台字段（bms `02_01`）」条目**同步注销**）。
5. **事件**：用户-部门 / 用户-岗位「主要项」变更事件（域名与载荷按现有 `org.*` 契约口径登记，随本任务补事件契约快照）。
6. **前端与原型**：现有插件「用户分配岗位」标题改**「岗位分配」**、列表增「主要岗位」列（至多一个，置位即时提交）；新增「用户分配部门」插件（列表增「主要部门」列），区域项顺序与角色侧一致（岗位 20 / 部门 30）；两插件均挂 bms 用户记录页 `sys.user.detail.tabs`（**该槽宿主位置为「用户分配」页签内子 Tabs**，见 bms 阶段七 `01_01` 消费约定登记）。原型对照按 mdm `设计/原型设计/04_组织域插件/` 与 bms `08_用户管理/03_用户表单页.html`。

## 3. 完成标准 <a id="accept"></a>

`org_user_dept` 落库且迁移可跑（含降级往返）；`org_user_dept` 与 `org_user_post` 的 `is_primary` 唯一性（同用户至多一个）经校验与用例验证（含并发与跨用户隔离）；`/api/v1/org/user-depts` 契约可用且公开契约快照与 `@mdm/api-types` 零漂移；两插件在 bms 用户记录页正常挂接（缺失即隐藏、不报错，「主要项」列可置位）；事件契约快照零漂移；`pytest` / `ruff` / `pyright` / 前端 `check` / 契约门禁全绿。
