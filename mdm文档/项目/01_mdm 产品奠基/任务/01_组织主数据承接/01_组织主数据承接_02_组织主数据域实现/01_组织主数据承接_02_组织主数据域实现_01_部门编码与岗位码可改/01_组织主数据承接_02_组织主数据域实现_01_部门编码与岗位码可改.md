## 2. 任务内容 <a id="content"></a>

1. **部门编码**：`org_dept` 新增 `code`（部门编码）——**必填、租户内唯一**（`(code, deleted_at)` 复合唯一），格式受系统参数 `org.dept_code_pattern` 约束（默认 `^[A-Za-z0-9][A-Za-z0-9_-]{0,63}$`，1~64 位字母 / 数字 / 下划线 / 连字符、首字符须为字母或数字），**创建后可修改**（格式与唯一校验、自身同值豁免）。
2. **存量回填**：迁移按部门 `id` 升序生成 `DEPT` + 定长 4 位序号（`DEPT0001`…，超 9999 自动扩位），回填后再置列非空并加唯一约束。
3. **岗位码同步放开可改**：`org_post.code` 由「创建后不可改」改为**可修改**（同部门口径：格式 + 唯一校验、自身豁免），两域口径统一；内部引用一律 `post_id` / `dept_id`，改码无副作用。
4. **出口契约带 `code`**：管理面（部门明细 / 部门树节点）与只读出口（`OrgDept` 部门树，bms 组织选择字段族消费）均返回部门编码。
5. **前端与原型**：mdm 部门列表 / 表单页展示与编辑部门编码（含新建必填校验）、岗位表单页岗位码解除只读；bms 侧部门选择器树节点 label 附编码（`研发部 (DEPT0002)`）。
6. **错误码**：新增 `330060`（部门编码已存在）、`330061`（部门编码格式非法）。

## 3. 完成标准 <a id="accept"></a>

`org_dept.code` 落库且迁移可跑（含存量回填与降级往返）；部门编码必填 / 唯一 / 格式 / 可改四条校验生效；岗位码可改生效；两类出口与管理面契约带 `code` 且契约快照、`@mdm/api-types` 零漂移；mdm 前端部门 / 岗位页与原型逐页对照通过；bms 侧部门选择器展示编码且有护栏用例；`pytest` / `ruff` / `pyright` / 前端 `check` 全绿。
