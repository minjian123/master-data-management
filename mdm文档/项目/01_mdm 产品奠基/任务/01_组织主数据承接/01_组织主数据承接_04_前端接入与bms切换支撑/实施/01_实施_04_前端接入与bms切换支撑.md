## 3. 实施过程 <a id="process"></a>

1. **先登记再编码**：Kiwi 用例输入 → mjbk 容器登记 → 回读编号 **2261** → 代码与用例标注 `// kiwi_id: 2261`。
2. **工作区与类型管道先行**：先落 `frontend/` 工作区与 `@mdm/api-types`（自产品契约快照生成 + 零漂移门禁），再落模块工程（消费该类型）。
3. **跨仓基座包解析**（关键试错，见 §4 第 1 条）：`file:` 引用 + 纳入工作区成员两步走通，`@bms/core` 直连 bms 目录、`@bms/ui-ep` 经虚拟 store、`@mdm/api-types` 走本工作区。
4. **模块工程承平台口径**：MF remote（`exposes ./module`、`remoteEntry.js`、`import:false` + `strictVersion`）、外部 sourcemap、`element-plus` 独立 vendor 块、版本构建期注入、产物元数据；构建配置**直接引用 bms 工作区脚本与单一来源文件**（不复制）。
5. **页面与插件**：管理页（部门树 + 详情 + 增删改移；岗位筛选 + 列表 + 增删改启停）与三个具名插槽插件（用户分配岗位＝路由参数通道；岗位 / 部门分配＝显式上下文通道）；写操作**即时提交**、**全量覆盖**语义。
6. **门禁与取证**：类型检查 / lint / 用例 / 远端构建 + 体积预算 + 产物面隔离；后端门禁复跑；**跨仓发布演练**（平台侧 `publish --module-dir`）；**原型对照**（截图 7 张 + 逐页结论，见测试记录）。
7. **代码提交与推送**：mdm `933d0e0` / `11a9a19`（`-o ci.skip`）。

## 4. 问题与处置 <a id="issues"></a>

| # | 现象 | 处置 |
| --- | --- | --- |
| 1 | **跨仓基座包解析失败**：仅用 `file:../../../../bms/frontend/packages/*` 时 pnpm 报 `ERR_PNPM_WORKSPACE_PKG_NOT_FOUND`（bms 包内部 `workspace:*` 依赖无从解析） | `pnpm-workspace.yaml` **纳入 bms 前端包为工作区成员**（`- '../../bms/frontend/packages/*'`）+ 模块侧 `file:` 引用；安装后 7 个工作区项目、链接指向正确。已回写详细设计 §3.2 |
| 2 | pnpm 11 忽略依赖构建脚本致 `pnpm install` **exit 1**（进而 `pnpm --filter … run <script>` 因前置 install 检查整体失败） | `pnpm approve-builds --all` 写入 `allowBuilds`（正确键名；`onlyBuiltDependencies` 不足）；登记告警口径 |
| 3 | **产品契约类型包进运行时依赖被平台发布前强校验拒**：`模块依赖 @mdm/api-types 未登记`（平台共享白名单只认单一来源清单） | `@mdm/api-types` 改为 **devDependency**（纯类型面依赖，运行时零影响，产物不变）；登记为跨仓口径 |
| 4 | **独立预览构建产物白屏**：`shared` 的 `import:false` 在无宿主时无从解析（`TypeError: S is not a function`） | `vite.config.ts`：**独立预览目标不启用 Module Federation**（框架依赖本地提供，与详细设计 §3.3「两个构建目标」的意图一致）；重建后 4 页正常渲染 |
| 5 | 跨仓脚本在 Vitest 下解析失败 / `new URL` 报 `Invalid URL` | `vitest.config.ts` 加 `resolve.alias['@bms-scripts']` + `server.fs.allow`；路径用 `join()` 拼接（`URL` 的 base 须为 URL） |
| 6 | `vue-tsc` 严格档下表单模型 `status` 被收窄为字面量 | 表单模型显式标注 `status: string` |
| 7 | **契约标识口径两面不一致**：响应面 id 为字符串（雪花），`DeptCreateRequest.parent_id` / `PostCreateRequest.dept_id` / 分配请求体 id 数组声明为**整数** | 前端**按字符串原样透传**（后端宽松解析，避免 `Number()` 精度丢失），集中在 `domain.ts` 的 `toIdParam` / `toIdParamList`；登记为遗留（见 §6 第 3 项） |
| 8 | 模板内 EP 组件 kebab-case 仍须显式导入（`<el-checkbox>` 未导入 → 运行期未解析） | 补 `ElCheckbox` 导入 |
