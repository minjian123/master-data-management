## 1. 设计目标与范围 <a id="goal"></a>

承接需求 01-4（**2026-10-08 扩容：含 mdm 前端工程全量**）：mdm 自建前端工程并以**运行时模块**（Module Federation）接入 bms 宿主，交付组织域管理页（部门 / 岗位）与三个具名插槽插件，自持契约类型生成管道；同时交付 bms 侧组织选择字段切换 mdm 出口所需的**类型 + 契约对齐 + 联调方案**（切换改动归 bms `11_02`）。

1. **前端工程**：`mdm/frontend/` pnpm 工作区（Vue 3 + TS + Vite），模块工程 `@mdm/module-org`（MF 容器名 `mdm-org`）与类型包 `@mdm/api-types`。
2. **组织域管理页**：部门管理、岗位管理（本域 CRUD，经 mdm 组织域管理面契约）。
3. **三个具名插槽插件**：用户分配岗位（挂 bms 用户详情页页签）、岗位分配与部门分配（挂 bms 角色分配页签）。
4. **契约类型包**：`@mdm/api-types`（自 mdm 契约快照生成，**零漂移门禁入 CI**），供本模块与（后续）消费方使用。
5. **切换支撑**：为 bms 组织选择字段族提供类型与契约对齐结论 + 联调方案；**改址归 bms `11_02`**，联通作联合验收。
6. **范围外**：bms 侧前端改址与 `bms_core/org` 清理（归 bms `11_02`）；mdm 后端契约改动（01_02 / 01_03 已交付，本任务只**消费**）；生产托管与网关联调（随部署）；表单 / 字段 / 按钮元数据种子（属平台表单定制与字段权限体系，需求 01-4 未列，登记遗留）；移动端宿主。

## 3. 前端工程形态与依赖 <a id="engineering"></a>

### 3.1 工作区布局

```text
mdm/frontend/
├── package.json / pnpm-workspace.yaml        # workspaces: modules/*, packages/*
├── tsconfig.base.json / eslint.config.js / .npmrc
├── modules/org/                              # 模块工程 @mdm/module-org（MF 容器名 mdm-org）
│   ├── package.json / vite.config.ts / vitest.config.ts / budget.json
│   ├── src/                                  # index.ts（模块定义）/ env.d.ts / runtime.ts / i18n/ / services/ / components/ / views/
│   └── tests/
└── packages/api-types/                       # @mdm/api-types（契约生成产物 + 生成器）
```

### 3.2 平台基座包获取（构建前提）

| 项 | 口径 |
| --- | --- |
| 获取方式 | **pnpm workspace + `file:` 指向工作区 bms 克隆**：`@bms/core` / `@bms/ui-ep` / `@bms/api-types` 均为 `file:../../../../bms/frontend/packages/<包>`（相对模块工程目录），**不复制、不另发布** |
| 构建前提（硬） | `mdm/` 与 `bms/` 必须**同级克隆**（工作区模型）；CI 与本地均须满足——CI 前端作业先 clone bms（同 GitLab 匿名只读即可） |
| 平台单一来源复用 | 模块构建配置直接**引用 bms 工作区脚本与单一来源文件**：`bms/frontend/scripts/{module-meta.mjs,shared-deps.mjs}`、`bms/frontend/{module-contract.json,shared-dependencies.json}`——共享依赖与契约版本**不复制、不各写一份** |
| 代价与边界 | 跨仓目录布局耦合（登记为构建前提）；bms 侧脚本签名变更需同批适配（登记为跨仓协同项） |

### 3.3 模块工程配置（承 bms 模块工程同口径）

| 项 | 口径 |
| --- | --- |
| MF 角色 | remote：`name = mdm-org`、`filename = remoteEntry.js`、`exposes = { './module': './src/index.ts' }` |
| 共享依赖 | `loadSharedDependencies({ role: 'remote' })`（bms 单一来源）：`import: false` + `strictVersion: true`（**不打包本地回退副本**） |
| 版本注入 | `moduleVersionDefine`（`package.json` 版本为单一来源）→ `__BMS_MODULE_VERSION__` |
| 产物元数据 | `createModuleMetaPlugin` → `dist/module.meta.json`（名称 / 版本 / 契约版本） |
| 两个构建目标 | 缺省 `dist/`（远端产物：容器 + 暴露模块 + 页面异步分包）；`build:standalone` → `dist-standalone/`（带 HTML 壳的独立预览） |
| sourcemap | 外部 `.map`（发布前四关强校验要求存在） |
| 第三方分包 | `element-plus` 独立为 vendor 块（避免产物面隔离扫描误判） |
| 体积预算 | `budget.json` + bms `module-metrics` 单一计量（`check-bundle-budget.mjs` 同口径） |
| 隔离 | 源码面：模块自身 ESLint + 平台隔离扫描（复用 bms 脚本，`--module` 指向本工程）；产物面：`guard:isolation` |

### 3.4 样式与文案

- 一律 `<style scoped>`；只消费 `--bms-*` 令牌（含模块自有令牌 `--bms-mdm-org-*`）；类名以 `.mdm-org-` 前缀。
- 文案真源 `src/i18n/messages.ts`（兼作 `i18nPacks` 注册载荷，键 `mdm-org:zh-cn`）；页面经模块内组合式取文案，**不硬编码中文**、不直连宿主 i18n 实例。

## 4. 模块契约与运行时接入 <a id="module"></a>

### 4.1 模块定义（八类声明：本项目只用三类）

```ts
export const orgModule = defineModule({
  manifest: { name: 'mdm-org', version: __BMS_MODULE_VERSION__, contractVersion: MODULE_CONTRACT_VERSION },
  setup: (context) => {
    applyHostContext(context)          // 只读消费注入上下文（缺失降级）
    return { routes, regions, i18nPacks }   // components / fieldRenderers / icons / cards / themeTokens 不声明
  },
})
export default orgModule
```

### 4.2 路由与菜单（自动装配，不落 `sys_menu` 种子）

| 路由 | 组件 | `meta` |
| --- | --- | --- |
| `/org/depts` | `() => import('./views/org/DeptListView.vue')` | `{ title: '部门管理', icon: 'organization', group: '组织主数据', groupIcon: 'organization', keepAlive: true }` |
| `/org/posts` | `() => import('./views/org/PostListView.vue')` | `{ title: '岗位管理', icon: 'briefcase', group: '组织主数据' }` |
| `/org/depts/form/:id?`、`/org/posts/form/:id?` | 表单页 | `{ title: …, menu: false }` |

菜单由宿主按路由 `meta` **自动装配**（分组 / 图标 / `devOnly` 过滤），**不产生 `sys_menu` 种子**；多语言经 `i18nPacks`。> 表单 / 字段 / 按钮元数据种子**不做**（登记遗留，见 §12）。

### 4.3 区域项（三个具名插槽插件）

| 区域项键 | `area` | 标题 / 次序 | 权限码 | 上下文来源 |
| --- | --- | --- | --- | --- |
| `mdm-org:user-posts` | `sys.user.detail.tabs` | 用户分配岗位 / 20 | `org:update` | 路由参数 `:id`（bms 用户详情页 `/sys/users/:id`，经注入 `router` 只读读取） |
| `mdm-org:role-posts` | `sys.role.detail.assign` | 岗位分配 / 20 | `org:update` | **显式上下文** `useModuleSlotField('roleId')`（bms 角色分配页签注入，需求 `05-11`） |
| `mdm-org:role-depts` | `sys.role.detail.assign` | 部门分配 / 30 | `org:update` | 同上 |

- **降级**：插件未注册 / mdm 不可达 / 权限不满足 / 上下文缺失 → 该项不渲染，宿主页其余正常（不报错、不阻塞）。
- **即时提交**：数据归 mdm，插件写操作**即时提交**（不随宿主工具栏保存）——与宿主页内建字段的保存语义区分，原型与页面文案明示。

### 4.4 清单条目与发布编排

| 步 | 动作 | 命令 / 落点 |
| --- | --- | --- |
| 1 | mdm 侧独立构建 | `cd mdm/frontend && pnpm --filter @mdm/module-org run build` → `dist/`（容器 + 元数据 + 外部 sourcemap） |
| 2 | 平台侧发布（**跨仓形态**） | `node frontend/scripts/release-module.mjs publish --module mdm-org --module-dir <mdm>/frontend/modules/org --origin <基址>`（四关强校验 → 归档 `releases/mdm-org/<版本>/` → 清单指向 → 留痕 `source: external`） |
| 3 | 本机发布存储 + 宿主 | `serve-module-releases.mjs`（5002）+ `apps/desktop` dev（5173），经菜单进入模块页面 |

- 链路**不持跨仓凭据**（bms `03_04` 口径）；本任务以**本地演练**跑通（生产托管随部署阶段）。
- 契约版本/共享依赖双端校验由 bms 既有护栏承接（本任务不新造）。

## 5. 组织域管理页 <a id="views"></a>

| 页面 | 能力 | 契约（管理面，经产品寻址 `/api/mdm/v1/org/...`） |
| --- | --- | --- |
| 部门管理 | 组织架构树（含子树）、新建 / 编辑 / 移动 / 删除；部门下用户 / 角色只读查看 | `GET/POST /depts`、`GET/PUT/DELETE /depts/{dept_id}`、`PUT /depts/{dept_id}/move`、`GET /depts/{dept_id}/{users,roles}` |
| 岗位管理 | 列表（按部门筛选含子级）、新建 / 编辑 / 删除 / 启停；岗位下用户 / 角色只读查看 | `GET/POST /posts`、`GET/PUT/DELETE /posts/{post_id}`、`GET /posts/{post_id}/{users,roles}` |

- **页面组合**：`PageContainer` + `SectionContainer` + `DataTable` / 树件 + `StatusTag` + 输入件（**复用 bms 组件库**，不自造重复组件）。
- **原型先行（强制）**：以 `mdm文档/设计/原型设计/` 为验收基准（界面先原型红线）；实施与测试记录须写**「原型对照结论」**（逐页表 + 截图路径）。
- **命名与文案**：页面文案用语义名，不出现实现侧类名 / 能力键 / 文件路径。

## 6. 数据通路 <a id="data"></a>

| 通路 | 口径 |
| --- | --- |
| mdm 组织域（本域） | **产品域作用域**：`context.api.product('mdm', 'org')` → `get` / `post` / `put` / `patch` / `del`（bms 需求 `05-13` 交付；未登记产品键 / 非法域段即抛，模块**不自拼前缀**） |
| 平台用户查询（插件选择用户 / 回显） | 平台服务通道：`context.api.get('platform', '/users', { kw, status, page, size })`；响应类型取 `@bms/api-types` 的 `platform` 命名空间（与 bms 侧同源类型，不另抄） |
| 请求能力缺失 | 一律降级：不请求、渲染提示态；**禁自建 HTTP / 裸请求**（隔离护栏 R3）、**禁自拼 `/api/...` 前缀**（R4） |
| 写操作 | 插件写 mdm 归属数据：用户-岗位 `PUT/DELETE /user-posts/{user_id}[/{post_id}]`；角色-岗位 `PUT/DELETE /role-posts/{role_id}[/{post_id}]`；角色-部门 `PUT/DELETE /role-depts/{role_id}[/{dept_id}]`（全量覆盖语义，即时提交） |

## 7. 契约类型包与零漂移门禁 <a id="types"></a>

| 项 | 口径 |
| --- | --- |
| 事实源 | mdm **产品自持**契约快照 `mdm/deploy/contracts/org.json`（唯一事实源；`baseline/` 为门禁基线，不参与生成） |
| 生成器 | `frontend/packages/api-types/scripts/generate.mjs`（承 `@bms/api-types` 同口径）：`openapi-typescript` → `src/org.ts` + `src/index.ts`（按域命名空间导出 `export type * as org`） |
| 生成物 | **入库**（消费方无需跑生成器即可类型检查）；文件头标注来源与「勿手改」 |
| 零漂移门禁（**硬**） | `node frontend/packages/api-types/scripts/generate.mjs --check`：重新生成并与入库产物**逐字节比对**（缺文件 / 漂移 / 多余文件均失败）→ **入 mdm CI 作业**，本地亦作为提交前门禁复跑 |
| 与 bms 切换的关系 | bms 前端消费方**不依赖本包**（其类型仍取自 `@bms/api-types`）；本包服务 mdm 模块自身与「契约字段 ↔ 前端解析零漂移」的证据链（联调方案见 §8） |

## 8. 与 bms 切换的接口（联合验收） <a id="switch"></a>

| 面 | 归属与口径 |
| --- | --- |
| mdm 负责 | 组织只读出口与契约稳定（01_03）+ 类型包与生成门禁（§7）+ 联调方案与证据 |
| bms 负责 | 需求 `11-2` / 任务 `11_02`：组织选择字段族（`OrgSelectField` / `PostSelectField` / `DeptTreeSelectField` / `OrgCompositePicker`）与 `OrgSourceAdapter` 改指 mdm 出口；`bms_core/org` 与装配清理 |
| 契约对齐结论（本任务交付物） | 出口五端点 ↔ 前端解析器：① 用户 / 岗位 / 部门树路径为 `/api/mdm/v1/org/data-source/{users,posts,dept-tree}`；② 序列响应为 `{ items: [...] }` 包装（前端 `readArray` 兼容 `list` / `items` / `records`）；③ 名称回显 `/resolve-names` 批量、未命中占位；④ 部门树一次性返回（不分页）、`children` 嵌套；⑤ 雪花 id 在响应中为字符串 |
| 联调口径（本任务内） | **契约零漂移 + 本地真 HTTP 对打**：mdm 出口 ASGI 真跑 × 前端 HTTP 解析器真跑（本机打 mdm 服务），逐端点核对响应形态与解析结果；网关、真实令牌与三库端到端随部署联调任务 |
| 联合验收 | 前端组织选择经 mdm 出口联通（查询与批量回显分列、部门树一次性返回）+ bms `org` 服务退役验收（bms `11-2` / `11-3`）——**跨仓联合**，本任务交付前置与证据 |

## 9. 失败分支与边界 <a id="edge"></a>

| 场景 | 处置 |
| --- | --- |
| 模块未注册 / 未启用 / 不可达 | 宿主不加载或插槽项不渲染，其余正常（既有兜底口径） |
| 无 `org:update` 权限 | 插槽项与写操作入口不渲染（前端显隐）；后端强制校验仍生效 |
| 上下文缺失（如角色标识未注入） | 插件**不渲染 / 不请求**（自行降级），宿主页其余正常 |
| 请求能力未注入 | 页面与插件降级为提示态（不假定存在） |
| mdm 服务不可达 / 业务失败 | 统一响应解包后按错误码提示（业务失败多为 HTTP 200 + 统一 `code`）；不静默空 |
| 产品寻址未登记 | `api.product()` 调用处即抛（构建/运行早失败，不静默回退） |
| 类型生成物与快照漂移 | `--check` 门禁失败（阻断） |
| 体积超预算 / 隔离违规 | 构建门禁失败（阻断） |
| 原型对照不通过 | 视为未完成（逐页对照结论入测试记录） |

## 13. 决策记录 <a id="decision"></a>

| # | 决策项 | 结论 |
| --- | --- | --- |
| 1 | 范围 | **扩容为含 mdm 前端工程全量**（工程 + 管理页 + 三插件 + 类型包 + 门禁 + 联调），不再只做「类型 + 联调」 |
| 2 | 类型产物落点 | **mdm 自建 `frontend/packages/api-types` 独立管道**（产品契约自持；不在 bms 复用 `@bms/api-types` 生成管道） |
| 3 | 改址归属 | **留 bms `11_02`**（本任务只交类型 + 契约对齐 + 联调方案，联通作联合验收） |
| 4 | 工程形态与命名 | `mdm/frontend/` workspace；模块 `mdm-org` + `@mdm/module-org` + `@mdm/api-types`；路由 `/org/depts`、`/org/posts` |
| 5 | 基座包获取 | **pnpm workspace + `file:` 指向工作区 bms 克隆**（同级克隆为构建前提；共享依赖与契约版本复用平台单一来源，不复制） |
| 6 | 构建与发布 | **mdm 侧构建，平台侧 `--module-dir` 发布**（本任务本地演练；链路不持跨仓凭据） |
| 7 | 种子范围 | 只做**菜单（路由 meta 自动装配）+ 多语言（`i18nPacks`）**；表单 / 字段 / 按钮种子不做（登记遗留） |
| 8 | 联调口径 | **契约零漂移 + 本地真 HTTP 对打**；网关 / 令牌 / 三库端到端随部署 |
| 9 | 门禁 | 类型零漂移＝**脚本 + CI 硬门禁**；原型对照＝**人工结论 + 截图**（不移植 bms 原型评审脚本） |
| 10 | 数据通路 | mdm 组织域经**产品域寻址** `api.product('mdm','org')`（bms `05-13` / `06_02` 交付）；平台用户查询经平台通道 + `@bms/api-types` 类型 |
| 11 | 插件上下文 | 用户分配岗位经**路由参数**；岗位 / 部门分配经**显式上下文**（bms `05-11` / `06_03` 交付，宿主页已留槽并注入 `roleId`） |
| 12 | 前置补齐顺序 | **依赖先行**：先交 bms `05-12` / `03_04`、`05-13` / `06_02`、`05-11` / `06_03` 三条基座能力，再在本任务消费 |
