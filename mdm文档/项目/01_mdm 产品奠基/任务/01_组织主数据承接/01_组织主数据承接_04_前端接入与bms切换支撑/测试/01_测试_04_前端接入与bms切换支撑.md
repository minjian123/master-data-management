### 3.1 联调证据（契约零漂移 + 发布链路） <a id="integration"></a>

1. **契约对齐（前端侧硬门禁）**：`tests/contract-alignment.spec.ts` 以请求能力替身驱动**全部服务方法**，把捕获的「方法 + 路径 + 查询参数名」与产品契约快照逐条比对——① 每条调用命中契约 `paths` 与方法；② 查询参数名命中契约声明；③ **契约管理面端点被前端全部覆盖**（防漏接）。该用例是「契约零漂移」在前端侧的对称面（`gen:check` 管**类型**、本用例管**调用面**）。
2. **后端出口行为（权威回归）**：`uv run pytest -q` 93 例通过（含出口五端点真实取数 / 鉴定与数据边界 / 缓存失效代）；公开契约快照零漂移、破坏性变更门禁通过。
3. **跨仓发布链路**：平台侧执行 `publish --module-dir` → 四关强校验（版本 / 隔离 / 共享 / sourcemap）通过 → 归档 `bms frontend/releases/mdm-org/0.1.0/` → 宿主清单条目 `{name: mdm-org, entry: http://127.0.0.1:5002/mdm-org/0.1.0/remoteEntry.js, version: 0.1.0, mode: remote}` → 留痕 `source: external`（不记目录 / 主机 / 凭据）；`check-module-manifest.mjs` 报告「在册模块：仓内 3 项 / **跨仓 1 项（mdm-org）**，跨仓条目版本发现与产物校验在发布时执行」。**演练后已回滚 bms 工作区**（`releases/*` 为 gitignore，仅回滚清单与留痕两处改动）。
4. **联调口径边界**（与详细设计 §8 一致）：真实网关、真实令牌与三库端到端**未做**，随部署联调；组织选择字段**改址**归 bms `11_02`（联合验收）。

## 4. 原型对照 <a id="prototype"></a>

**基准**：`mdm文档/设计/原型设计/`（界面先原型红线；原型即验收基准）。
**取证方式**（可复现）：① 独立预览产物静态托管（`dist-standalone` → `http://localhost:5004`，哈希路由）；② 原型静态托管（以**仓根**为根，`http://localhost:8899`，原型资源经 `bms文档` 软链解析）；③ 逐页截图与识图对照（截图存 `mdm/temp/prototype-check/`，该目录 gitignore）。

| 页面 | 原型 | 实现 | 结论 |
| --- | --- | --- | --- |
| 部门管理页 | 工具栏（新增子部门 / 移动 / 停用 / 刷新 / 关闭）+ 左侧部门树 + 右侧详情（修改 / 删除 **页内编辑表单**：上级部门 / 名称 / 排序 / 状态 / `ancestors` 链 / 直属用户·岗位计数 / 角色绑定） | 标题 + 描述 + 工具栏（新建部门 / 刷新）+ 部门树 + 详情（名称 / 状态 / 用户数 / 角色数 + 编辑 / 移动 / 删除）+ **独立表单页**（`/org/depts/form/:id?`） | **布局与能力对齐**；差异：① 编辑形态＝页内编辑 vs **独立表单页**；② 未展示 `ancestors` 链；③ 未做「系统信息」子页签与「角色绑定」编辑（角色分配归 bms 角色管理页）；④「关闭」归宿主页签职责、未实现 |
| 岗位管理页 | 工具栏（新增 / 删除 / 绑定角色 / 刷新 / 关闭 / 导出）+ 查询区（**关键字**、归属部门、查询 / 重置 / 展开）+ 表格（**多选**、岗位码、名称、归属部门、状态）+ 分页 | 标题 + 描述 + 筛选（所属部门 / 状态）+ 表格（岗位码 / 名称 / 归属部门 / 状态 + 行内编辑·启停·删除）+ 分页 + 工具栏（新建岗位 / 刷新） | **查询与表格列对齐**；差异：① 缺**关键字**筛选入口（服务层已支持）；② 缺**多选批量删除**与**绑定角色**入口；③「导出 / 关闭」未实现（导出属平台能力、关闭归宿主） |
| 用户分配岗位（插件） | 已分配岗位列表 + 「分配岗位」弹窗（**部门筛选 + 岗位多选**）+ **单条解绑（二次确认）** + 即时提交提示 + 降级三态（插件未加载 / 上下文缺失 / 恢复） | 面板（已分配计数 + 候选勾选列表 + 「提交变更」+ 刷新）+ 降级（上下文缺失 / 无权限 / 未接入） | **通道与降级对齐**（路由参数通道取用户标识）；差异：① 分配入口为**内联勾选**而非弹窗（无部门筛选）；② 无**单条解绑**入口（以整体提交取消勾选等效） |
| 岗位分配（插件） | 同页签下已分配列表 + 「去分配」弹窗 + 全量覆盖 + **权限显隐（无权提示）** + 上下文未就绪降级 | 面板（同用户插件骨架；上下文经 `useModuleSlotField('roleId')`）+ 无权限提示 + 上下文缺失降级 | **通道、全量覆盖与降级对齐**；差异同「用户分配岗位」第 ①② 项 |
| 部门分配（插件） | 部门树多选（**精确匹配、不含下级**）+ 全量覆盖保存 + 与岗位分配的页签联动 | 面板（部门树展平 + 层级缩进勾选；**精确匹配**语义提示 + 全量提交） | **语义对齐**（精确匹配已提示并实现）；差异：分配入口为内联勾选而非弹窗 |
| 部门 / 岗位表单页 | 表单页（字段与校验） | 独立表单页（名称 / 上级部门 / 排序 / 状态；岗位含编码 / 名称 / 归属部门 / 排序 / 状态） | **字段对齐**；校验规则（如编码格式 `org.post_code_pattern`）由后端兜底，前端未前置校验 |

**原型对照结论**：**结构、字段与能力骨架对齐；交互形态与入口完整性存在差异**（见上表 ⚠️ 项）。差异处置**待拍板**（补齐 vs 接受差异并回写原型 / 详细设计），登记为实施记录 §6 第 1 项。

## 5. 覆盖率 <a id="coverage"></a>

前端工作区未单独设覆盖率阈值（沿用平台前端口径：全量用例回归 + 构建 / 体积 / 隔离门禁）。后端组织域沿用既有门槛（`pytest` + `--cov-fail-under=70`，CI 作业 `backend-test`）。新增前端代码路径均由用例直接覆盖：类型生成与零漂移、模块定义三类声明、上下文三通道（路由参数 / 显式注入 / 缺失）、数据通路（产品域寻址与平台通道）、契约对齐（调用面双向覆盖）、插槽件降级三态。
