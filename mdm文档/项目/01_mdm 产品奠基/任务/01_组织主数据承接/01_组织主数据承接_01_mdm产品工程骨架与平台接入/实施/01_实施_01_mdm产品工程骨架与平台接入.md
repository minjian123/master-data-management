## 3. 实施过程 <a id="process"></a>

1. **上下文与决策**：按《AI开发规范》读 bms 规范（后端开发规范 / 基类清单 / 架构 09·11）、bms `12_01` / `12_02` / `12_03` 详设与代码（`application.py` 工厂协议、`module_registry.py` 清单机制与合并去重、`service_contract.py` 契约视图、`db/migration.py` 链注册、`db/bootstrap.py` 开发库建表、`db/keys.py` 库名派生、工厂样例 `services/notification`、CI 与镜像口径），以及 mdm 规划 / 简称规范 / 架构总览 / 需求 / 任务 / 详设。
   - **标识冲突拍板**：mdm 详设原登记 `org` 全套与 bms 现役 `org` 服务行（`module_key` / `service_key` / `table_prefix` / `event_domain` 四项）重复，注入即启动拒。经用户拍板采 **B 路线**：**bms 先退役释放 `org` 标识、mdm 随后承接**，mdm 侧标识**零改动**（与规划登记完全一致），避免“先起步后改回”的破坏性变更。
   - **跨仓协同（bms 11_01 提前执行）**：`org` 条目易主（平台能力 → mdm 产品行，四要素不变）、`PRODUCT_ROUTES` 增 `mdm/org → org`、产品档案 `mdm` 升 `enabled`、网关服务级路由排除产品分组、基座库名前缀参数化（`[database].name_prefix`）、产品服务合并同值去重；mdm 段锁该提交 SHA 作为 `bms-core` 依赖 ref。
2. **Kiwi 先登记后编码**：登记输入 `test/scripts/kiwi/cases/2026-10-07_mdm阶段一01-01_mdm产品工程骨架与平台接入.json`（经 `register_cases.py` 走 mjbk 容器 Django shell），平台回读编号 **2253**；用例代码以 `@pytest.mark.kiwi_id(2253)` 标注。
3. **工作区与跨仓依赖**：新建 `backend/pyproject.toml`（uv workspace，成员 `services/*`），以 `[tool.uv.sources]` 声明共享基座 git 源依赖（`subdirectory=backend/libs/bms_core`，`rev` 锁 bms 提交 SHA）；加传递依赖约束 `sqlalchemy>=2.0,<2.1`（与平台运行锁口径对齐——SQLAlchemy 2.1 起 `greenlet` 不再默认随包，基座异步栈必需）。
4. **服务工程骨架**：新建 `backend/services/org`（`mdm-org`）——`src/mdm_org/` 含入口（`main.py` 应用工厂 / `asgi.py` / `__main__.py`）、分层骨架（`api` / `services` / `repositories` / `models` / `schemas`，本期仅 `api/router.py` 有实现：服务级登记表聚合，暂无模块路由）；`models/__init__.py` 声明空 `MODEL_MODULES`（本期无业务表）。
5. **产品服务装配**：`ApplicationFactory` 覆写 `service_records()` 注入本产品清单、声明 `product_key = "mdm"`；基座据此形成应用级服务目录视图（平台清单 + 注入记录，同值去重）。
6. **产品服务清单（单一来源）**：新建 `backend/services/module_registry.py`——`MDM_SERVICE_RECORDS`（首条 = 组织域，四要素 `org` / `org` / `org_` / `org`、错误码段 `33`、产品分组 / `product_key=mdm` / 批次 3），并提供 `service_package()`（包名规则 `mdm_{服务键}`）、`local_service_keys()`、`catalog_view()`、`validate_local_catalog()`（清单校验 + 产品维度 + **两侧同值**断言）。
7. **运行期配置**：`config.toml` 最小差异（应用名 + `[server]` 结构段 + `[database].name_prefix = "mdm"`），`config.dev/test/prod.toml` 仅覆盖环境差异（SQLite 每服务库 / CI 临时库 / 生产关闭文档与自动建表）。
8. **迁移骨架与运维脚本**：`alembic.ini` 登记 `org` 三链配置段与版本目录（`alembic/versions/org/{platform,tenant,archive}/`，本期无脚本）；`alembic/env.py` 与 `script.py.mako` 与平台同构；`backend/ops/` 落 `check_modules.py`（离线清单 + 产品维度 + 两侧同值 + 服务包声明）、`db_admin.py`（建库，复用基座能力）、`migrate.py`（分链迁移，服务维度取产品清单、租户维度取显式 `--code`，**不跨服务直读租户注册库**）、`contract_snapshot.py`（产品侧自持契约快照与零漂移）。
9. **部署与 CI**：`deploy/Dockerfile`（单服务参数化；venv 落工作目录以支撑基座工程根定位）、`deploy/compose/mdm.yml`（Compose 服务名 `org`、接入平台外部网络、平台基础设施不重复编排）、`deploy/.env.example`（平台网络 / 镜像标签 / 运行库与凭证注入位）；`.gitlab-ci.yml` 落精简门禁（门禁冒烟 / ruff / pyright / pytest + 覆盖率 / 离线清单 + 契约零漂移）。
10. **用例**：`services/org/tests/test_service_boot.py`（启动 / 探针 / 装配 / 路由）、`tests/test_module_catalog.py`（清单与产品维度四项断言 / 异值即拒 / 两侧同值 / 产品路由 / 服务包声明）、`tests/test_config_and_databases.py`（配置分层 / 库名派生 / 服务身份回写 / 事件域视图）、`tests/test_ops_cli.py`（ops 四个脚本 CLI）。
11. **验证**：见 §5；**文档回写与记录**：见 §6 / §7。
