## 1. 目的与口径 <a id="purpose"></a>

mdm 至今的验证面只有「开发机单测 + CI 静态门禁」，**从未以产品形态落到部署主机**：没有运行镜像、没有服务库、网关无 `mdm` 上游、前端模块未发布。本设计把这条链路一次打通，并让**部署入口只有一处实现**（bms `release.py`），避免产品仓再写一套发布脚本导致回滚与台账口径分叉。

设计约束（2026-11-05 拍板）：

1. 部署入口 = 扩展 bms `scripts/tools/deploy/release.py`，**只加通用参数，不写产品字面量**；
2. 服务器保留 `~/bms` 不动，新增 `~/mdm`（部署主机形态，不迁工作区）；
3. 镜像由 **mdm CI 构建并推送**（SHA 标签），服务器只拉取；
4. 密钥**复用 bms `deploy/.env` 同一套**（服务令牌 / 用户令牌 / 对称密钥）；
5. 库为 MySQL 全量租户：`mdm` / `mdm_demo` / `mdm_acme` / `mdm_archive`；
6. 网关走**注册表模式重渲 + APISIX 文件轮询热加载**，不手改生成物。

## 2. 决策确认汇总 <a id="decisions"></a>

| # | 事项 | 结论 | 取舍说明 |
| --- | --- | --- | --- |
| 1 | 任务落点 | 需求 `01-8` + 任务 `01_07` | 部署事实有唯一落点，bms `11_02` 验收可直接引用；与 `01_05` 遗留「部署窗口」合并，避免同一批前置条件准备两次 |
| 2 | 迁移漂移 | 直接修订历史迁移 `0001/0002/0004/0005` 为 `SnowflakeId` | 产品未上线、无生产数据；链保持五版、新库一次到位。代价：既有开发库版本号不变但结构不同，必须删库重建（本地 `.cache/test/*.db` 与 `database/` 一并清） |
| 3 | 镜像构建 | mdm CI 新增 `image-build`（SHA 标签推 GitLab Registry） | 构建可重复、产物可追溯；与 bms 同口径。上下文需 `mdm/` + `bms/` 平级 → 取仓库父目录 |
| 4 | 构建忽略规则 | 工作区根 `.dockerignore` → `mdm/deploy/Dockerfile.dockerignore` | Dockerfile 专用 ignore 随仓库走，CI 与本地共用一份；工作区根不再承担产品构建细节 |
| 5 | 服务器检出 | 保留 `~/bms`，新增 `~/mdm` | 零中断；服务器是部署主机不是构建机（镜像来自 CI，无构建上下文需求） |
| 6 | 部署入口 | 扩展现有子命令 + 通用参数 | 一套发布 / 回滚 / 门禁 / 台账实现；产品侧只提供 compose 与 `.env` |
| 7 | 库创建 | mdm 新增 `ops/provision.py`（读配置派生库名，幂等建库） | bms 的 `ops.provision_tenant` 不在 mdm 镜像内；产品侧自持「自己有哪些库」比让 bms 认识产品库更内聚 |
| 8 | 迁移执行 | `ops.migrate {tenants}`（在目标镜像内一次性执行） | 与发布镜像同版本，避免「旧镜像建表、新镜像启动」错位 |
| 9 | 网关 | `release.py gateway --render` 从平台注册表重渲 → APISIX 热加载 | 路由只由声明生成，零手改；对账（不写）与重渲（写）分两档 |
| 10 | 前端发布 | mdm CI 归档 dist → 服务器 `node:24` 容器内跑 bms `release-module.mjs publish` | 构建在 CI、四关校验与发布台账在服务器一处；不在部署主机装 node / pnpm |
| 11 | CI 覆盖率 | `MDM_COVERAGE_DATA` + `engkit coverage` | 与本地预检同源，杜绝「CI 绿、门禁红」两套口径 |
| 12 | bms 协作 | `11_02` 只补真机证据、不改代码 | 代码已于 2026-10-08 迁出（`e7a0ab092`）；本次验证真实网关 / 令牌 / 三库 |

## 4. 镜像与 CI <a id="image"></a>

### 4.1 构建上下文与忽略规则 <a id="context"></a>

`bms-core` 是**路径依赖**（`../../bms/backend/libs/bms_core`），镜像内需同时具备 `mdm/` 与 `bms/backend/libs/bms_core`，Docker 只能从单一上下文取其内容 → 上下文上移到**工作区根**（服务器上即仓库父目录）。

忽略规则改由 `mdm/deploy/Dockerfile.dockerignore` 承载（BuildKit 对该文件优先于上下文根的 `.dockerignore`），内容 = 原工作区根 `.dockerignore` 逐条迁入，并补 `bms/deploy/`（部署态变量与生成物不进镜像）。

### 4.2 `image-build` job <a id="ci-image"></a>

```yaml
image-build:
  stage: build
  image: docker:27-cli
  script:
    - . scripts/tools/ci/bms_setup.sh        # 上下文需要 bms 源码（路径依赖）
    - echo "$CI_REGISTRY_PASSWORD" | docker login "$CI_REGISTRY" -u "$CI_REGISTRY_USER" --password-stdin
    - cd ..
    - docker build --provenance=false -f mdm/deploy/Dockerfile -t "$IMAGE" .
    - docker push "$IMAGE"
```

- `IMAGE = ${MDM_REGISTRY_IMAGE_PREFIX:-$CI_REGISTRY/mjs/mdm}/mdm:$CI_COMMIT_SHORT_SHA`；
- `--provenance=false`：BuildKit 默认 attestation 清单会被 GitLab Registry 拒绝（`blob unknown`，bms 侧实测）；
- 凭据用 **CI 预定义** `CI_REGISTRY_USER` / `CI_REGISTRY_PASSWORD`（mdm 项目无项目级变量，不需要新建）。

### 4.3 覆盖率口径 <a id="ci-coverage"></a>

`backend-test` 改为：

```yaml
variables:
  MDM_COVERAGE_DATA: $CI_PROJECT_DIR/.cache/coverage/.coverage
  MDM_COVERAGE_SOURCE: mdm,services,ops
script:
  - *backend-setup
  - rm -rf "$CI_PROJECT_DIR/.cache/test" "$CI_PROJECT_DIR/.cache/coverage"
  - find "$CI_PROJECT_DIR" -name '*.db' -not -path '*/.git/*' -delete
  - uv run pytest
  - >-
    uv run engkit coverage --root "$CI_PROJECT_DIR"
    --data-file "$MDM_COVERAGE_DATA" --out "$CI_PROJECT_DIR/coverage.json"
    --module mdm --module services --module ops --fail-under 100
coverage: '/percent=(\d+(?:\.\d+)?)/'
```

## 5. 部署入口扩展（bms `release.py`） <a id="entry"></a>

### 5.1 新增通用参数 <a id="entry-params"></a>

| 参数 | 缺省 | 含义 |
| --- | --- | --- |
| `--repo-root` | 脚本所在仓根 | `ops` 脚本定位与只读挂载基准（产品仓部署时指向 `~/mdm`） |
| `--compose-file` | `compose/bms.yml` | compose 文件（相对 `deploy-dir`） |
| `--service` | 平台服务清单 | 目标服务键（改为自由字符串；`--all` 取 `compose config --services`） |
| `--container-name` | `bms-{service}` | 容器名模板（mdm 为 `mdm`） |
| `--tag-env` | `BMS_TAG_{SERVICE}` | 镜像标签变量名模板（mdm 为 `MDM_TAG`） |
| `--image-prefix-env` | `REGISTRY_IMAGE_PREFIX` | 镜像前缀变量名（mdm 为 `MDM_REGISTRY_IMAGE_PREFIX`） |
| `--health-path` | `/readyz` | 容器内就绪探测路径 |
| `--gateway-path` | `/api/{service}/v1/__gate__` | 网关冒烟路径模板（mdm 用产品命名空间 `/api/mdm/v1/mdm/__gate__`） |
| `--skip-gateway-probe` | 关 | 容器门禁跳过「网关可达」第三步（首部署路由尚未生成时用；跳过记入发布日志） |
| `--init-command` | `python -m ops.init_schema --service {service}` | 建表 / 迁移命令模板；含 `{tenant}` 时逐租户执行，含 `{tenants}` 时展开为 `--code X --code Y` |
| `--provision-command` | 空 | 建库命令模板（同上占位符）；缺省不建库 |
| `--db-grant-pattern` | `bms\_%` | 应用账号授权库模式（仅 `bootstrap` 使用） |

### 5.2 新子命令 <a id="entry-cmds"></a>

| 子命令 | 作用 |
| --- | --- |
| `provision` | 按 `--provision-command` 在目标镜像内建库（幂等），供首次部署 |
| `gateway [--render]` | 无 `--render`：注册表对账（重渲结果 ↔ 仓库生成件逐字比）；`--render`：**按注册表重渲并写回** `deploy/gateway/apisix.yaml`（APISIX 文件轮询自动热加载） |
| `exec -- <命令>` | 通用一次性执行（种子 / 排障），不引入产品字面量 |

### 5.3 mdm 调用形态 <a id="entry-mdm"></a>

```bash
cd ~/mdm
python3 ~/bms/scripts/tools/deploy/release.py \
  --repo-root ~/mdm --deploy-dir ~/mdm/deploy \
  --compose-file compose/mdm.yml \
  --container-name mdm --tag-env MDM_TAG --image-prefix-env MDM_REGISTRY_IMAGE_PREFIX \
  --health-path /readyz --gateway-path /api/mdm/v1/mdm/__gate__ \
  --init-command "python -m ops.migrate {tenants}" \
  --provision-command "python -m ops.provision {tenants}" \
  <子命令>
```

## 6. 服务器部署步骤 <a id="server"></a>

```text
① 克隆 ~/mdm（与 ~/bms 平级）→ 写 deploy/.env（库连接、平台网络、密钥取 bms 同值）
② release.py provision                              # 建 mdm / mdm_demo / mdm_acme / mdm_archive
③ release.py deploy --service mdm --tag <sha> --skip-gateway-check --skip-gateway-probe
                                                    # 迁移 → 起容器 → 门禁（容器 healthy + /readyz）
④ bms release.py gateway --render                   # 平台侧按注册表重渲 + APISIX 热加载
⑤ release.py health-gate --service mdm              # 网关门禁复核（此时产品路由已生成）
⑥ 断言 /api/mdm/v1/mdm/... 无凭据 401，带令牌 200
⑦ bms ops.seed_platform --tenant demo / acme（平台 + 产品同构声明，一个 XA 事务）
⑧ node:24 容器内 bms release-module.mjs publish --module mdm_org
```

**顺序口径**：③ 的两个跳过各管一件事——`--skip-gateway-check` 跳过 **bms 平台注册表对账**（mdm 仓没有 `deploy/gateway/` 生成件，对账对象不适用）；`--skip-gateway-probe` 跳过容器门禁里的**网关可达**探测（首部署时 `mdm` 声明尚未生成路由，探测必然失败）。两者都写入发布日志留痕。因此 ③ 之后必须先做 ④，再用 ⑤ 单独复核——复核通过即视为门禁通过。④ 的重渲是幂等的：注册表未变化时生成件逐字不变。

### 6.1 库与账号 <a id="db"></a>

| 库 | 键 | 生成方式 |
| --- | --- | --- |
| `mdm` | `platform_mdm` | `[database].name_prefix = mdm` + 「前缀 = 服务标识去重」 |
| `mdm_demo` / `mdm_acme` | `tenant_mdm_{code}` | 同上 + 租户编码（与 `BMS_DEPLOY_TENANTS` 同集） |
| `mdm_archive` | `platform_archive` | `archive_database_name(prefix="mdm")` |

应用账号 `mdm_app`：`GRANT ALL ON \`mdm\\_%\`.*`（与 bms `bms_app` 同形）。

### 6.2 `.env` 键位（相对 bms 的差异） <a id="env"></a>

| 键 | 值 |
| --- | --- |
| `PLATFORM_NETWORK` | `deploy_default`（bms 部署创建） |
| `MDM_REGISTRY_IMAGE_PREFIX` | `192.168.0.107:5050/mjs/mdm` |
| `MDM_TAG` | 本次 SHA |
| `BMS_DATABASE__PLATFORM__URL_TEMPLATE` | `mysql+aiomysql://mdm_app@mysql:3306/{database}` |
| `BMS_DATABASE__TENANTS__URL_TEMPLATE` | 同上模板 |
| `BMS_DATABASE__*__PASSWORD` | 与 `BMS_APP_DB_PASSWORD` 同值 |
| `BMS_SERVICE_TOKEN__*` / `BMS_SECURITY__*` | 取 bms `deploy/.env` 同值（决策 4） |

## 7. 前端模块发布 <a id="frontend"></a>

1. mdm CI `frontend-build` 增加 `artifacts.paths: [frontend/modules/org/dist/]`（保留 30 天）；
2. 服务器按 `GET /projects/15/jobs/artifacts/<sha>/download?job=frontend-build` 取包，解出 `frontend/modules/org/dist/`；
3. 用 `node:24` 容器（挂载 `~/bms` 与解包目录）执行：
   ```bash
   docker run --rm -v ~/bms:/bms -v <产物根>:/artifact -w /bms/frontend node:24 \
     node scripts/release-module.mjs publish --module mdm_org --module-dir /artifact/modules/org
   ```
4. 产物落 `~/bms/frontend/releases/mdm_org/<版本>/`，`release-log.json` / `release-log.md` 记台账；宿主清单 `modules.json` 同步。

> 四关强校验（`dist/remoteEntry.js` / `module.meta.json` / sourcemap / 体积预算）由发布脚本自身执行，服务器只提供产物与目标仓。

## 9. 风险与回退 <a id="risk"></a>

| 风险 | 处置 |
| --- | --- |
| 镜像构建时 `uv sync --frozen` 因 bms `main` 头变动失败 | `BMS_REF` 钉 SHA（CI 变量），构建可复现 |
| 迁移在真实库报方言差异（SQLite 通过、MySQL 失败） | 首次部署即验；失败保留容器日志，库为空的库可 `--skip-...` 重建 |
| APISIX 未热加载 | 检查 `apisix.yaml` 挂载与 `config.yaml` 的 `standalone` 轮询；必要时 `docker restart bms-apisix` |
| 前端产物版本与宿主清单不匹配 | `release-module.mjs` 四关拒收；回滚用 `releases/` 上一版本目录重发 |
| 密钥不一致导致 401 连环 | 两仓 `.env` 同值核对（`BMS_SERVICE_TOKEN__KEYS` 的 kid 与 key 必须成对） |
