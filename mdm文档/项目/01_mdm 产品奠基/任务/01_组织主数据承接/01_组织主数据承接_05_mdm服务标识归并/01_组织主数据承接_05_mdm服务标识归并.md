## 2. 任务内容 <a id="content"></a>

**口径（2026-10-23 拍板）**：服务标识统一为 `mdm`；目录 `services/org` 保留分类、服务包名随服务去重为 `mdm`；平台侧产品登记改为**产品仓自持清单 + 装载时注册**，bms 不持有 mdm 字面量。

> **前端模块名不受本任务影响（2026-10-23 二次确认）**：`@mdm/module-org` 与 MF 容器名 `mdm-org` 是「产品前缀 + 域」的**模块标识**，与服务标识分属两层——模块清单 `name`、多语言包键 `mdm-org:zh-cn`、插槽插件键 `mdm-org:user-posts`、样式前缀 `.mdm-org-` 与包名均由它派生，一并不改；后续 sup / cus 等域按同规则长成 `mdm-sup` / `mdm-cus`（详见详细设计 §2 决策 12.1）。

1. **服务标识与服务目录**：`org` → `mdm`（`module_key` / `service_key` = `mdm`、`table_prefix` = `mdm_`、`event_domain` = `mdm`、`errcode_segment` = `33` 沿用、`build_batch` = `3`、`product_key` = `mdm`）；bms 平台侧同值行由产品清单装载，不再写常量。
2. **数据实体与迁移**：六表 `org_dept` / `org_post` / `org_user_post` / `org_user_dept` / `org_role_post` / `org_role_dept` → `mdm_*`；`form_key` / `data_source_key` 与表名同名闭合；迁移链 `org:tenant` → `mdm:tenant`（`alembic/versions/mdm/tenant/0001~0005` 直接改写）；库名 `mdm_{租户}`。
3. **库名派生**：基座 `db/keys.py` 在 `[database].name_prefix == service` 时去重（`mdm` 而非 `mdm_mdm`）；平台库 `mdm`、租户库 `mdm_{租户}`、归档库 `mdm_archive`。
4. **对外路径与前端**：`/api/mdm/v1/org/...` → `/api/mdm/v1/mdm/...`（产品路由登记 `mdm/mdm → mdm`）；前端产品域寻址改 `api.product('mdm','mdm')`；模块包名 `@mdm/module-org` 与 MF 容器名 `mdm-org` 保留。
5. **事件与契约**：事件域 `org.*` → `mdm.*`（6 条契约改名）；公开契约 `deploy/contracts/org.json` → `mdm.json`（含 baseline）重生成。
6. **产品登记去耦**：mdm 仓新增 `deploy/registry/mdm.json`（产品档案 + 服务行 + 产品路由 + 数据源条目）；运行服务导入期经基座注册函数（`register_service_records()` / `register_product_records()` / `register_product_routes()`）注册，服务行另经应用工厂 `service_records()` 参与产品维度校验；bms 离线脚本按配置路径读同一份清单；bms 三个常量删除产品字面量。

## 3. 完成标准 <a id="accept"></a>

① 服务目录 `mdm` 行与 `deploy/registry/mdm.json` 逐字段同值（`ops.check_modules` 通过）；② 六表 `mdm_*` 与迁移链 `mdm:tenant` 零漂移、库名 `mdm_{租户}`；③ 对外 `/api/mdm/v1/mdm/...` 可达且网关生成件零漂移；④ `mdm.*` 事件契约与公开契约快照零漂移；⑤ bms 仓无 mdm 字面量（三个常量 / 网关生成 / 相关用例），产品登记经 `deploy/registry/mdm.json` 装载；⑥ `pytest` / `ruff` / `pyright` 与定向用例全绿，覆盖率行 + 分支 100%。
