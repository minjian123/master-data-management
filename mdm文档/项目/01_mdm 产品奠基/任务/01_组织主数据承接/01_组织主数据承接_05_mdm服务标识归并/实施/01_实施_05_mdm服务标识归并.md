**关键实施口径**（与详设一致）：

- **服务行单一来源**：`services/module_registry.py::MDM_SERVICE_RECORDS` 为唯一出处；`deploy/registry/mdm.json` 为同内容声明副本，`ops.check_modules` 断言逐字段同值。
- **表前缀闭合**：六表 `mdm_*`，`owner = mdm`（基座 `TableOwnershipRegistry._validate_prefix()` 硬校验通过）。
- **库名去重**：`[database].name_prefix = "mdm"` 且服务标识 `mdm` → 基座 `_service_segment()` 返回 `service`，派生 `mdm` / `mdm_{租户}` / `mdm_archive`（不出现 `mdm_mdm`）。
- **包名去重**：`service_package("mdm")` 返回 `mdm`；目录 `services/org` 保留域分类，**包名与镜像名均为 `mdm`**。
- **迁移直改**：`alembic/versions/mdm/{tenant,platform,archive}/0001~0005` 内表名 / 索引名 / `branch_labels` 全改，不写改名迁移（生产未上线，开发库重建）。
- **契约与事件**：`deploy/contracts/mdm.json`（含 baseline）与 `deploy/events/contracts.json` 重生成；事件 6 条 `mdm.*`。

## 3. 问题与处置 <a id="issues"></a>

| # | 问题 | 处置 |
| --- | --- | --- |
| 1 | **前端类型生成器旧域残留**：`packages/api-types/src/org.ts` 未清理（生成器只写不删），`gen:check` 报「多余生成文件」；`index.ts` 注释与断言文件仍写 `org` | 删除旧生成物；生成器 index 注释改为按快照文件名动态表述；`tests/generated.spec.ts` 与 `contract-alignment.spec.ts` 改指 `mdm.ts` / `contracts/mdm.json` |
| 2 | **域类型命名空间失配**：`modules/org/src/domain.ts` 仍 `import type { org }`，`vue-tsc` 报 11 处隐式 any（级联） | 改取 `mdm` 命名空间；类型恢复后隐式 any 全部消失 |
| 3 | **页内表单组件未引入**：`DeptListView.vue` 模板用 `<el-form>` / `<el-form-item>` 但未 import，运行时解析失败（真实宿主下表单不渲染） | 补 `ElForm` / `ElFormItem` 引入（属真实缺陷，随本任务修复） |
| 4 | **岗位列表行内操作永不渲染**：`columns` 缺 `actions` 列，`#cell-actions` 插槽无对应列，编辑 / 启停 / 删除按钮不可见（文案键早已存在） | `columns` 补 `{ key: 'actions', title: mdmOrg.post.column.actions }` |
| 5 | **对话框取消抛未捕获 rejection**：`ElMessageBox.prompt` / `confirm` 在 `try` 外，用户取消即产生 unhandled rejection，原 `catch` 内 `'cancel' / 'close'` 判断为死代码 | `DeptListView`（移动 / 删除）与 `PostListView`（删除 / 批量删除）改为「确认对话框单独 try/catch，取消即静默返回」 |
| 6 | **启停后空选中取值崩溃**：`onToggleStatus` 在 `load()` 之后读 `selected.value.id`，而 `load()` 在树中找不到该部门时已把选中置空 → TypeError | 先取 `id` 常量再重载，重载后按 `id` 重选 |
| 7 | **覆盖率包名漏改**：`.gitlab-ci.yml` 的 `--cov=mdm_org` 与 `engkit.toml` 的 `coverage_packages` 仍指旧包名（去重后覆盖率将统计为空） | 改 `mdm`；本地实测覆盖率回到 100% |
| 8 | **部署环境样例不一致**：`deploy/.env.example` 写 `MDM_TAG_ORG`（compose 实读 `MDM_TAG`），示例库名与 upstream 仍 `mdm_org` / `org:8000` | 改 `MDM_TAG` / `mdm` / `mdm:8000`；`config*.toml`、`alembic.ini` 注释同步 |
| 9 | **文档改名前值被误伤**：机械改名把「改前 → 改后」两侧都替换（如 `mdm:tenant` → `mdm:tenant`、`mdm_dept` → `mdm_dept`） | 详设 §2 / §4 与需求 `01-6` 的改前值逐条还原（`org:tenant` / `org_dept` / `/api/mdm/v1/org/...` 等）；§4 改名映射总表承担历史口径说明 |
| 10 | **表文件名与表名脱节**：六份表文件仍 `org_*.md`，而总览登记链接已指向 `mdm_*.md`（断链） | `git mv` 重命名六份表文件为 `mdm_*.md`，总览与互链一致，`engkit links` 断链 0 |
| 11 | **历史文档包名残留**：约 30 个文件、200 处仍写 `mdm_org`（包名已去重为 `mdm`） | 按拍板统一改 `mdm`；历史机制表述（如「两侧同值」）保留原文 |
| 12 | **前端缺覆盖率门禁**：CI 只有 lint / typecheck / test / build / budget / guard，两管理页与独立预览壳从未有测试（变更 8 文件实测 24.5% 行 / 16.66% 分支） | 接入 `@vitest/coverage-v8` + `test:cov` + vitest 覆盖率配置；补 5 个用例文件（领域工具 / 模块注册面 / 独立预览壳 / 两管理页），变更 8 文件**行与分支双 100%**；CI `frontend-test` 改跑 `test:cov` 并归档报告 |
| 13 | **模块名易与服务标识混淆**：`mdm-org` 派生面（模块清单 `name` / 多语言包键 / 插件键 / 样式前缀 / 包名）在评审中被反复质疑 | 经二次确认**维持 `mdm-org`**（模块按域拆分，与服务标识分属两层），口径落详细设计 §2 决策 12.1 与任务文档口径段，避免后续误改 |
