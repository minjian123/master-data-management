# 05 详细设计 · mdm 服务标识归并（`org` → `mdm`）

## 1. 目的与口径 <a id="purpose"></a>

mdm 以产品形态接入平台，但内部服务标识沿用承接前的 `org`，形成「产品叫 mdm、服务叫 org、库叫 mdm_org、表前缀 org_、事件域 org.*、对外域段 org」六处口径分裂；后续每新增一个主数据域（参考数据域等）都得再起一个与产品名无关的服务名。另有平台侧耦合：bms 在 `SERVICE_CATALOG` / `PRODUCT_ROUTES` / `DATA_SOURCE_CATALOG` 三个常量里写死 mdm 的服务行、产品路由与数据源条目。

本任务按 2026-10-23 拍板做两件事：**① 服务标识统一为 `mdm`**（包 / 目录保留分类）；**② 产品登记改为产品仓自持清单 + 装载时注册**，bms 不持有产品字面量。

**唯一事实源**：表结构只在各表文件（`mdm文档/设计/数据库设计/数据表设计/*.md`）维护；本文档只写**变更增量**与跨仓机制。通用约定与方言见 bms《数据库设计 · 数据规范》。

### 5.2 单一来源与零漂移 <a id="manifest-source"></a>

- **单一来源**为 mdm 代码清单（`services/module_registry.py` 的 `MDM_SERVICE_RECORDS` / `MDM_PRODUCT_RECORDS` / `MDM_PRODUCT_ROUTES` 与数据源清单）；`deploy/registry/mdm.json` 为**同一份内容的声明副本**（供平台装载）。
- `ops/check_modules.py` 装载清单后断言「JSON ↔ 代码清单」逐字段同值（零漂移），并入预检与 CI；手改 JSON 即红。
- mdm `services/module_registry.py::validate_local_catalog()` 的基准为**合并视图**（平台 `SERVICE_CATALOG` + 本产品清单）：产品档案与产品级路由由清单装载后进入校验基准，未装载即按产品维度断言报错（fail-closed），不再依赖 bms 侧同值行。

### 5.3 bms 侧装载 <a id="manifest-load"></a>

- 新增 `bms_core/registry/products.py`：`ProductManifest`（产品档案 / 服务行 / 产品路由 / 数据源条目四类）+ `load_product_manifest(s)(paths)` + `register_manifest()`，字段必填与产品归属校验（`CatalogError`）。
- **配置**：`[registry].product_manifests: list[str]`（缺省 `[]`）；`config.dev.toml` 指向 `../mdm/deploy/registry/mdm.json`。环境变量 `BMS_REGISTRY__PRODUCT_MANIFESTS` 可覆盖（部署态注入）。
- **运行时（平台服务）**：装配期装载清单 → 注册进运行期视图（`SERVICE_CATALOG` / `PRODUCT_ROUTES` / `DATA_SOURCE_CATALOG` 合并，同键同值去重、异值即拒），供 `/api/v1/data-sources`、服务目录校验与网关派生使用；装载后清库键缓存（`clear_known_service_keys()`）使新服务键可被解析。
- **运行时（产品服务 mdm）**：不读文件，模块导入即经 `register_service_records()` / `register_product_records()` / `register_product_routes()` 注册本产品记录（与平台清单合并同值），服务行另经应用工厂 `service_records()` 参与产品维度校验。
- **离线（网关生成）**：`ops/gateway_config.py` 按配置路径装载清单 → `render_apisix_config(services=..., routes=...)` 合并生成；**清单缺失即降级为空**（跳过不存在的路径，仅平台路由），不阻断 CI。
- **失败分支**：清单 JSON 非法 / 与产品档案不符 → 平台服务拒启与 `gateway_config check` 失败（`CatalogError`）；清单路径不存在 → 空合并（CI 与未挂载产品的环境可跑）。

### 5.4 产品路由与数据源注册通道 <a id="hooks"></a>

| 通道 | 落点 | 语义 |
| --- | --- | --- |
| `service_records()`（应用工厂钩子） | 已有（`application.py`） | 本服务补充的服务目录记录；进应用级视图与产品维度校验 |
| `register_product_routes()` / `product_routes_view()` | 新增（`services/module_registry.py`） | 产品级路由注册与合并视图；`PRODUCT_ROUTES` 置空 |
| `register_data_source_records()` / `data_source_records_view()` | 新增（`datasource/registry.py`） | 产品数据源条目注册与合并视图；平台字典仍留 `DATA_SOURCE_CATALOG` |
| `register_product_records()` / `product_catalog_view()` | 已有（`services/module_registry.py`） | 产品档案注册与视图 |
| `table_records()` / `form_records()` | 已有 | 表归属 / 表单标识，口径不变 |

## 6. 库名派生去重 <a id="dbname"></a>

- `db/keys.py`：`platform_database_name(service, prefix)` 与 `tenant_database_name(service, basis, prefix)` 在 `prefix == service` 时返回 `service` / `{service}_{basis}`（不重复拼接）；`prefix != service` 行为完全不变（平台 `bms` 与各服务不受影响）。
- 效果：mdm `[database].name_prefix = "mdm"` + 服务 `mdm` → 平台库 `mdm`、租户库 `mdm_{租户}`、归档库 `mdm_archive`（`archive_database_name` 不涉服务，保持 `{prefix}_archive`）。
- 校验：新增用例覆盖 `prefix == service` 与 `prefix != service` 两侧；`_checked_database_name` 规则不变。

## 7. 迁移改写 <a id="migration"></a>

- 目录 `alembic/versions/org/{tenant,platform,archive}` → `alembic/versions/mdm/{...}`；`alembic.ini` 段名与 `version_locations` 同步。
- 脚本 `0001` ~ `0005`：revision id 改 `0001_mdm_tables` …（链内递增不变）；建表 / 索引 / 唯一约束名改 `mdm_*`；`branch_labels` 改 `mdm:tenant`；`down_revision` 链保持。
- 开发 SQLite 库**删库重建**（`database/mdm/` 下旧库文件一并清理），不写改名迁移。

## 8. 失败分支与边界 <a id="failure"></a>

| 场景 | 处置 |
| --- | --- |
| 表前缀不属于归属服务 | 基座 `TableOwnershipRegistry._validate_prefix()` 拒启（改名后六表均为 `mdm_`，闭合） |
| 服务行与平台清单异值 | 合并视图「同键同值去重、异值即拒」，拒启并打印差异 |
| 产品清单缺失（CI / 未挂载环境） | 跳过不存在的路径得空清单，网关仅生成平台路由；不静默用旧值 |
| 清单 JSON 非法 | `gateway_config check` 失败、平台服务拒启（`CatalogError`） |
| 清单与代码清单不同值 | `ops.check_modules` 失败（手改 JSON 即红） |
| 契约 / 事件快照未重生成 | `ops.contract_snapshot check` / `ops.event_contracts check` 失败 |
| 前端仍指向旧域段 | 契约对齐用例失败（前端调用面 ⊆ 契约） |

## 10. 登记回写 <a id="writeback"></a>

- **mdm**：数据库设计总览（库划分 / 表登记）、六份表文件（表名 / 约束名 / 变更记录）、架构设计总览（域服务划分 / 工程骨架）、概要设计总览（表登记）、规划（标识符登记：服务 `mdm` 行）、英文简称规范、文档首页、计划（进度唯一落点）、任务与需求。

## 11. 风险与遗留 <a id="risk"></a>

- **跨仓协同面大**：mdm 90+ 文件 + bms 15 文件；bms 侧先合入（清单装载 + 库名去重 + 常量删除），mdm 侧改名随后，二者须同批联调。
- **清单装载依赖路径**：CI 无 mdm 仓时降级为空；部署态须配 `product_manifests`，否则网关缺 mdm 路由（日志 `product_manifests_loaded` 缺省即未装载）。
- **镜像名 `mdm`**：随「一个产品一个服务」直接取服务标识，后续新增主数据域不再新增镜像。
- **生产未上线**：本次改名不涉及存量数据迁移；一旦上线后再改名须走数据迁移，故须在首次部署前完成。
