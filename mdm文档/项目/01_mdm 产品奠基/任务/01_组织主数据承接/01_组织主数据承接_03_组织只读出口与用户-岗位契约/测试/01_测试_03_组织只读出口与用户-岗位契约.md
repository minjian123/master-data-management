| 取数口径一致性核对 | 原型中组织选择字段所依赖的取数口径与本任务出口契约一致：部门树一次性返回（`{items}` 嵌套 `children`）、岗位分页（`{list,total,page,size}`）、名称批量回显（`{items}`，未命中占位）、按用户解析角色（`{role_ids}`） |
| 插件 / 页面对照时点 | 01_04（前端接入与 bms 切换支撑）：以 `02_岗位管理` / `03_部门管理` 原型页为准逐项对照 |

## 7. 结论与遗留 <a id="conclusion"></a>

- **结论**：通过——组织只读出口四类取数（用户 / 岗位 / 部门树 / 名称回显）与按用户解析角色契约可用；出口与管理面路径彻底分离；鉴权双通道（登录态 + 服务身份白名单）与数据范围 / 脱敏依赖强制接入；用户数据经平台内部契约取数、不可达即 fail-closed（`330101`）；结果缓存含租户级失效代并由写侧推进；公开契约基线 + 破坏性变更门禁落地并接入 CI；组织域原型按模块迁入就位；全部门禁绿。
- **遗留（与实施记录 §7 同源）**：前端类型产物与生成门禁（01_04）、前端切路径与 bms 侧一次性切换（bms 11_02 + mdm 01_04）、`users` 部门过滤切换为平台 `sys_user.dept_id` 字段过滤（bms 02_01）、`OrgUser.avatar` 平台契约补全（bms 用户完整域）、`user-roles` 部门链粒度与缓存失效粒度口径、数据范围 / 脱敏真实策略（随 RBAC / 脱敏阶段）、生产 Redis 与多副本失效验证（部署联调）。
