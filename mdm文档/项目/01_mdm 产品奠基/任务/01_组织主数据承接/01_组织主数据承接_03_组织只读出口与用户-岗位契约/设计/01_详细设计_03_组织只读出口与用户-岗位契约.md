## 1. 设计目标与范围 <a id="goal"></a>

承接需求 01-3：交付组织域**对外只读出口两契约**（组织数据源 / 名称回显）与**按用户解析角色只读契约**，确认**事件契约**（5 条 `org.*` 已随 01_02 登记），供 bms 与业务产品一致性引用。

1. **端口契约迁入**：`BaseOrgDataSource`（`users` / `posts` / `dept_tree`）与 `BaseOrgNameResolver`（`resolve_names`）连同数据契约与常量自 **bms `bms_core/org/`** 迁入 mdm 组织域（bms 需求 11-2 后段负责移除基座侧）。
2. **用户数据来源端口**：新增 `BaseOrgUserSource`（用户只读取数端口）+ **平台实现**（经 `BaseServiceClient` 调 bms platform 新增的 `/api/v1/platform/internal/users/query`，bms 侧登记为阶段七 `02_06`）——mdm **不跨库读** `sys_user`。
3. **真实取数实现**：`posts` / `dept_tree` / `resolve_names(post,dept)` 取本域库（`org_post` / `org_dept`）；`users` / `resolve_names(user)` / `user-roles` 部门链取平台来源。
4. **HTTP 出口**：五端点对外（**产品命名空间** `/api/mdm/v1/org/...`，服务内部前缀 `/api/v1`），出口路径统一挂 **`/org/data-source/*`** 与 `/org/resolve-names`（与 01_02 管理面 `/org/posts` 等**彻底分离**，见 §4）。
5. **鉴权**：出口一律 `require_auth`（已登录用户，经网关或本地用户令牌）；服务间调用另经 `require_service`（**调用方服务白名单**，供 bms 权限引擎等）——同一端点两种身份，见 §4.2。
6. **数据范围与脱敏（强制接入）**：出口经基座 `DataScope` 注入点过滤、经基座 `BaseMasker` 掩码（`OrgUser.masked_fields` 声明手机 / 邮箱敏感）；**调用方不可绕过**。RBAC 阶段未交付期间数据范围按基座占位（`NullDataScope` 不过滤）放行。
7. **`user-roles` 缓存**：结果按租户 + 用户短时缓存（复用基座缓存域 `CacheRegion`），写侧以**租户级失效代**失效（见 §6）。
8. **公开契约基线与门禁**：建立 `deploy/contracts/baseline/org.json` 与 `ops.contract_gate`（oasdiff 破坏性变更比对，接 CI）。
9. **事件契约**：5 条 `org.*` 契约已在 01_02 登记并入快照，本任务**只核验零漂移**（写侧发布已在 01_02 落地）。

**不在本期**：

| 事项 | 归口 |
| --- | --- |
| 用户-岗位分配写入口（`GET/PUT/DELETE /org/user-posts` 全量覆盖 / 解绑） | **已由 01_02 交付**（本任务范围据此收敛，见 §13 决策 12） |
| 前端类型产物与生成门禁（`@mdm/api-types` 类） | 01_04（前端接入与 bms 切换支撑）；bms 侧消费由 11_02 重生成 `@bms/api-types` 承担 |
| bms 前端出口切换与 `bms_core/org` 契约 / 装配移除 | bms 11_02（前段切前端 → 后段移除） |
| 数据范围真实规则（RBAC 阶段七）与脱敏真实策略 | 平台相应阶段（本任务只加固接入点与占位） |

## 3. 端口契约 <a id="contract"></a>

自 bms `bms_core/org/` 迁入（**同一套形态与语义**，仅宿主包不同）：

```python
# mdm_org/org/base.py（节选）
class BaseOrgDataSource(BasePluggable, ABC):
    key: str = "org_data_source"
    plugin_key: str = "org_data_source"

    @abstractmethod
    async def users(self, keyword=None, *, dept_id=None, include_children=False,
                    status=None, page=1, size=DEFAULT_ORG_PAGE_SIZE) -> BasePageResponse[OrgUser]: ...
    @abstractmethod
    async def posts(self, keyword=None, *, dept_id=None, include_children=False,
                    status=None, page=1, size=DEFAULT_ORG_PAGE_SIZE) -> BasePageResponse[OrgPost]: ...
    @abstractmethod
    async def dept_tree(self, *, status=None) -> ConcurrentStableList[OrgDept]: ...

class BaseOrgNameResolver(BasePluggable, ABC):
    key: str = "org_name_resolver"
    plugin_key: str = "org_name_resolver"

    @abstractmethod
    async def resolve_names(self, target: str, ids: ConcurrentStableList[int]) -> ConcurrentStableList[OrgNameRef]: ...

class BaseOrgUserSource(BasePluggable, ABC):
    """用户只读来源端口（跨服务；平台 `sys_user` 的唯一取数通道，不跨库读）。"""

    key: str = "org_user_source"
    plugin_key: str = "org_user_source"

    @abstractmethod
    async def query(self, keyword=None, *, status=None, ids=None,
                    page=1, size=DEFAULT_ORG_PAGE_SIZE) -> BasePageResponse[OrgUser]: ...
    @abstractmethod
    async def by_ids(self, ids: ConcurrentStableList[int]) -> ConcurrentStableList[OrgUser]: ...
```

- **数据契约**：`OrgUser`（`masked_fields = {"phone", "email"}`）/ `OrgPost` / `OrgDept`（嵌套 `children`）/ `OrgNameRef`（`exists` / `status` 标记）；常量 `ORG_STATUSES`（`enabled`/`disabled`）、`ORG_TARGETS`（`user`/`post`/`dept`）、`DEFAULT_ORG_PAGE_SIZE`（20）。
- **语义**：契约方法**不显式传租户 / 数据范围参数**——租户隔离与数据范围过滤由**实现侧**强制接入，调用方不可绕过；部门树**一次性返回、不分页**；已删除 / 停用对象**不抛错**，由 `OrgNameRef.exists` / `status` 标记（前端回退展示 id）。
- **`BaseOrgUserSource.query` 的 `ids`**：非空时表示「**限定在这批 id 内**查询」（仍支持 `keyword` / `status` 与分页），供 `users` 出口的部门过滤派生交集使用（见 §5.2）。
- **装配落点（2026-10-07 拍板）**：三契约保留 `BasePluggable` 形态，但**经 mdm 本地装配注入**出口路由（**不依赖平台 `PLUGIN_WIRINGS`**——bms 11_02 后段将移除 `org_data_source` / `org_name_resolver` 两条接线与基座契约）。装配入口：`mdm_org/api/open_read.py` 的依赖提供者（请求级组装真实实现；测试可覆写依赖注入替身）。

## 4. HTTP 出口设计 <a id="api"></a>

### 4.1 端点与路径 <a id="api-paths"></a>

| 方法 | 路径（服务内部 / 对外产品命名空间） | 说明 |
| --- | --- | --- |
| GET | `/api/v1/org/data-source/users` · `/api/mdm/v1/org/data-source/users` | 组织数据源 · 用户（`keyword` / `dept_id` / `include_children` / `status` / `page` / `size`） |
| GET | `/api/v1/org/data-source/posts` · `/api/mdm/v1/org/data-source/posts` | 组织数据源 · 岗位（同上入参） |
| GET | `/api/v1/org/data-source/dept-tree` · `/api/mdm/v1/org/data-source/dept-tree` | 组织数据源 · 部门树（`status`；一次性返回、不分页） |
| GET | `/api/v1/org/resolve-names` · `/api/mdm/v1/org/resolve-names` | 名称回显（`target` + `id_in` 逗号分隔） |
| GET | `/api/v1/org/user-roles` · `/api/mdm/v1/org/user-roles` | 按用户解析其经岗位 / 部门获得的角色（并集去重；入参 `user_id`） |

- **为何出口挂 `/org/data-source/*`（2026-10-07 拍板）**：01_02 已占用管理面 `GET /api/v1/org/posts`（`org:query` + `PostItem`），与本出口 `posts`（`require_auth` + 数据范围 / 脱敏 + `OrgPost`）**同名不同语义、返回契约亦不同**（`PostItem` vs `OrgPost`）→ 出口统一收口到独立子命名空间 `data-source/*`，管理面零改动、出口契约可独立演进。`/org/resolve-names` 无同名冲突，保持顶层（唯一例外，登记为口径）。
- **响应形态（与既有前端解析器对齐，勿改）**：
  - `users` / `posts` → `ApiResponse[BasePageResponse[OrgUser|OrgPost]]`（`{list,total,page,size}`）；
  - `dept-tree` → `ApiResponse[OrgDept 序列]`（**裸数组**，嵌套 `children`）；
  - `resolve-names` → `ApiResponse[OrgNameRef 序列]`（**裸数组**）；
  - `user-roles` → `ApiResponse[OrgUserRoles]`（`{role_ids:[...]}`）。
- **对外经网关**：平台侧 `PRODUCT_ROUTES` 已登记 `mdm/org → org`（bms 12_02 / 11_01），网关把 `/api/mdm/v1/org/...` 重写为服务内 `/api/v1/org/...`。
- **参数上限**：`page` / `size` 走基座 `page_query`（`size ≤ 200`）；`id_in` 元素上限 **200**（超出抛参数校验错误 10001）。

### 4.2 鉴权（双通道） <a id="api-auth"></a>

| 通道 | 依赖 | 适用 |
| --- | --- | --- |
| 用户身份 | `require_auth`（网关可信身份 或 本地 `aud=api` 用户令牌 + 会话标记校验） | 前端（bms 桌面端组织选择字段） |
| 服务身份 | `require_service(*ORG_READER_SERVICES)`（服务 JWT `aud=service`，校验签发方服务标识在白名单） | bms 权限引擎等服务间调用（东西向直连，不经网关） |

- 落点：`mdm_org/api/open_read.py::require_org_reader`——先按 `Authorization` Bearer 试**服务身份**（命中白名单即放行，租户由服务 JWT `tenant` claim 经全局租户中间件解析），否则回落 `require_auth`；两者皆不通过抛 `AuthError`（20001 / 401）。
- **白名单**：模块级常量 `ORG_READER_SERVICES: tuple[str, ...] = ("platform",)`（bms 侧角色 / 授权与权限计算同落 platform 服务租户库），后续接入方按需追加。
- **与管理面的分野**：`org:*` 权限码只用于管理面（01_02）；出口**不挂权限码**（面向跨产品消费、与平台 RBAC 解耦）——与概要设计 §5.3 把 `/org/user-roles` 记为 `org:query` 的写法不一致，**以本详设为准并回写概要设计**（见 §10）。

### 4.3 依赖注入 <a id="api-di"></a>

| 依赖 | 用途 |
| --- | --- |
| `Depends(require_org_reader)` | 路由级鉴权（双通道） |
| `Depends(get_masker)` | 激活请求级掩码上下文，使 `OrgUser.masked_fields` 在序列化期生效 |
| `get_uow` / `get_config_source` / `get_cache_region` / `get_service_client` | 请求级会话、系统参数、缓存域、服务间调用客户端 |

## 5. 真实取数与数据范围 / 脱敏 <a id="impl"></a>

### 5.1 各维度取数 <a id="impl-source"></a>

| 维度 | 取数 |
| --- | --- |
| `posts` | 本域 `org_post`：关键字（`code` / `name` 模糊）、`dept_id`（含子级经 `org_dept.ancestors` 前缀展开）、`status`、分页 + 计数同口径 |
| `dept_tree` | 本域 `org_dept`：全量一次取回（按 `sort` / `id` 排序）后组装嵌套树；`status` 过滤 |
| `resolve_names(post)` / `resolve_names(dept)` | 本域按 id 批量取（单批 IN 查询，避免 N+1）；未命中 → `exists=false`、`name=""`（保留请求插入序） |
| `resolve_names(user)` | 平台用户来源 `by_ids(ids)` |
| `users` | 平台用户来源 `query(...)`（见 §5.2） |

### 5.2 `users` 的部门过滤（过渡口径） <a id="impl-dept"></a>

平台 `sys_user.dept_id` 尚未落地（bms 需求 07-2 / 任务 02_01 落字段），故 `users` 的 `dept_id` / `include_children` 过滤**本期按下述过渡口径实现**（`sys_user.dept_id` 落地后切换为平台字段，登记为开放项）：

1. 由 `dept_id`（`include_children=true` 时含子树，经 `org_dept.ancestors` 展开）→ 本域 `org_post`（该部门 / 子树下岗位）→ `org_user_post` 反查 → **候选 user_id 集**；
2. 候选集为空 → 直接返回空分页（不调平台）；非空 → 调平台 `query(ids=候选集, keyword, status, page, size)`（平台在候选集内筛选与分页）；
3. 候选集规模上限 `org.data_source_max_filter_ids`（默认 1000；超出抛参数校验错误 10001，提示改用关键字检索）。

> 语义差异（**显式登记**）：本期 `dept_id` 过滤语义为「**用户在该部门（含子树）下有岗位**」，与平台字段落地后的「**用户归属部门**」不等价；已在摘要与开放项标注。

### 5.3 数据范围与脱敏 <a id="impl-scope"></a>

| 项 | 口径 |
| --- | --- |
| 租户隔离 | 请求上下文租户 → 本域仓储 `_scope_where()` / 平台服务 JWT `tenant` claim（两侧均强制），不可绕过 |
| 数据范围 | 出口服务读取基座 `DataScope.read_predicate()`：`None` 不过滤；`ScopeCondition(field="dept_id", operator in ("in","eq"), value=...)` 按部门限制（`dept_tree` 过滤 + `posts` 限定 `dept_id` + `users` 候选集交集）；其他形态记 warning 后忽略（真实规则随 RBAC 阶段） |
| 脱敏 | `OrgUser.masked_fields = {"phone","email"}` + 路由 `Depends(get_masker)`：序列化自动掩码；持 `data:plain` 权限方见明文（`BaseMasker.check_plain` 单点判定） |

- **强制接入的含义**：出口**只有这一条取数路径**（路由 → 出口服务 → 仓储 / 用户来源端口），数据范围与脱敏均在此路径内落地，调用方无法绕过（不提供旁路端点）。
- **失败降级**：平台用户来源不可达（`ServiceUnavailableError` 10007 / 非 2xx / 契约缺件）→ 用户维度出口抛 `OrgSourceUnavailableError`（`330101`），**不静默返回旧值**；`posts` / `dept_tree` / `resolve_names(post,dept)` 不受影响。
- **一致性**：部门 / 岗位取本域库（写侧唯一归属）；用户维度取平台**实时直读**（无投影、无跨服务缓存）→ 无需一致性屏障（2026-10-07 拍板；如后续引入用户投影再按需接入）。

## 6. 按用户解析角色与缓存 <a id="user-roles"></a>

### 6.1 解析口径 <a id="user-roles-rule"></a>

| 项 | 口径 |
| --- | --- |
| 入参 | `user_id`（租户由请求上下文提供） |
| 岗位链 | 用户 → 岗位（`org_user_post.user_id`）→ 角色（`org_role_post` 按 `post_id` IN） |
| 部门链 | 平台用户 `dept_id` → 角色（`org_role_dept` 按该 `dept_id` **精确匹配**，不含子树） |
| 返回 | 角色 id 集合（**并集去重**，插入序：岗位链在前、部门链补入）；**不返回用户直接角色**（`sys_user_role` 留 platform，由 bms 侧合并） |
| 平台缺 `dept_id` | 部门链**不参与**（当前即此态）；平台返回 `dept_id` 后自动生效 |
| 索引 | 全部命中既有索引（`org_user_post(user_id,…)` / `org_role_post(post_id,…)` / `org_role_dept(dept_id,…)`）；**本任务不新增表 / 索引 / 迁移** |

### 6.2 缓存与失效 <a id="user-roles-cache"></a>

| 项 | 口径 |
| --- | --- |
| 落点 | 基座缓存域 `CacheRegion`（`[cache]`：dev / test `memory`、prod `redis`；未配置回落 `null`） |
| key | `bms:{租户}:{域}:org:user_roles:{失效代}:{user_id}`（经 `CacheRegion.build_key` 拼域与租户位） |
| 值 | `normalize_collections({"role_ids": [...]})`（JSON 原生结构；读回重建 `ConcurrentStableList[int]`） |
| TTL | 系统参数 `org.user_roles_cache_ttl`（默认 **30** 秒） |
| 失效 | **租户级失效代**：写侧（角色-岗位 / 角色-部门 / 用户-岗位 分配或解绑）成功后对 `org:user_roles:gen:{租户}` 执行 `aincrease` → 缓存 key 换代、旧键立即不可达并由 TTL 自然回收 |
| 降级 | 缓存读写失败 / 未配置即直查（不阻断、不报错）；失效代读取失败按 0 处理 |

> **为何用失效代而非逐键 evict（2026-10-07 拍板）**：基座 `CacheRegion` 无「按模式扫描 / 租户级批量删」能力（仅 `get` / `set` / `delete` / `aincrease`）；且角色-部门分配变更时，受影响用户（平台 `dept_id ∈ dept_ids`）在 mdm 侧**无法枚举**。失效代以一次 `INCR` 换取正确性与多副本一致（Redis），代价是**同租户整体失效**。

## 7. 事件契约 <a id="events"></a>

| 事件 | 触发（01_02 已落地） | 主要载荷 |
| --- | --- | --- |
| `org.dept.changed` | 部门增删改 / 移动 | `dept_id`、`changed_type` |
| `org.post.changed` | 岗位增删改 / 启停 | `post_id`、`changed_type` |
| `org.user_post.changed` | 用户-岗位分配 / 解绑 | `user_id`、`post_id`、`changed_type` |
| `org.role_post.changed` | 角色-岗位分配 / 解绑 | `role_id`、`post_id`、`changed_type` |
| `org.role_dept.changed` | 角色-部门分配 / 解绑 | `role_id`、`dept_id`、`changed_type` |

- **本任务只核验**：5 条契约形态与快照零漂移（`ops.event_contracts check`）、写侧同事务写发件箱（01_02 已实现）；**不新增事件契约**。
- 消费方刷新投影 / 缓存的语义由消费方自持；mdm 侧 `user-roles` 缓存不依赖事件回环（同进程写侧失效代，见 §6.2）。

## 8. 失败分支与边界 <a id="edge"></a>

| 场景 | 处置 |
| --- | --- |
| 平台用户来源不可达 / 未装配 | 用户维度出口抛 `OrgSourceUnavailableError`（`330101`，业务失败 200）；部门 / 岗位出口不受影响 |
| `id_in` 非法（非整数） / 超上限（>200） | 参数校验错误（10001，不 500） |
| `target` 不在 `ORG_TARGETS` | 参数校验错误（10001） |
| 回显 id 不存在 / 已删除 | 不抛错，`exists=false`、`name=""`（前端回退展示 id） |
| 回显 id 对应对象已停用 | 不抛错，`status=disabled` |
| `dept_id` 过滤候选集超上限 | 参数校验错误（10001，提示改用关键字检索） |
| 无数据范围权限 | 结果按范围过滤为空（不报错、不泄露） |
| 敏感字段无明文权限 | 掩码返回 |
| 缓存不可用 | 直查（degrade-open，不阻断） |
| 服务身份不在白名单 | `AuthError`（20001 / 401） |
