# 01 详细设计 · 组织只读出口与用户-岗位契约

> mdm 产品奠基 · 01_组织主数据承接 · 子任务 03（需求 01-3）· 详细设计

[文档首页](../../../../../../文档首页.md) › [01 组织主数据承接](../../01_组织主数据承接.md) › 详细设计　|　[← 任务](../01_组织主数据承接_03_组织只读出口与用户-岗位契约.md)

## 1. 设计目标与范围 <a id="goal"></a>

承接需求 01-3：交付组织域**对外只读出口两契约**（组织数据源 / 名称回显）与**按用户解析角色只读契约**，并登记**事件契约**，供 bms 与业务产品一致性引用。

1. **端口契约**：mdm 组织域内定义 `BaseOrgDataSource`（组织数据源：`users` / `posts` / `dept_tree`）与 `BaseOrgNameResolver`（名称回显：`resolve_names`）两端口契约 + 数据契约，服务内部以**真实取数**实现（同 bms 范式）。
2. **HTTP 出口**：两契约经 HTTP 端点对外（**产品命名空间** `/api/mdm/v1/org/...`），供 bms 前端与业务产品消费。
3. **按用户解析角色只读契约**：`GET /api/mdm/v1/org/user-roles`，供 bms 权限引擎跨服务汇总（岗位 / 部门角色）。
4. **数据范围与脱敏（强制接入）**：出口查询按数据范围过滤、敏感字段按权限脱敏，调用方不可绕过。
5. **事件契约登记**：`org.*` 事件经事件契约注册表登记并入快照。

**不在本期（归 01_02）**：组织主数据维护 CRUD 与全部写入口（含用户-岗位 / 角色-岗位 / 角色-部门分配端点）。

## 3. 端口契约 <a id="contract"></a>

```python
# mdm_org/org/base.py（节选）
class BaseOrgDataSource(BasePluggable, ABC):
    key: str = "org_data_source"
    plugin_key: str = "org_data_source"

    @abstractmethod
    async def users(self, keyword=None, *, dept_id=None, include_children=False,
                    status=None, page=1, size=DEFAULT_ORG_PAGE_SIZE) -> BasePageResponse[OrgUser]: ...
    @abstractmethod
    async def posts(self, keyword=None, *, dept_id=None, include_children=False,
                    status=None, page=1, size=DEFAULT_ORG_PAGE_SIZE) -> BasePageResponse[OrgPost]: ...
    @abstractmethod
    async def dept_tree(self, *, status=None) -> ConcurrentStableList[OrgDept]: ...

class BaseOrgNameResolver(BasePluggable, ABC):
    key: str = "org_name_resolver"
    plugin_key: str = "org_name_resolver"

    @abstractmethod
    async def resolve_names(self, target: str, ids: ConcurrentStableList[int]) -> ConcurrentStableList[OrgNameRef]: ...
```

- **数据契约**：`OrgUser`（`masked_fields = {"phone", "email"}`）/ `OrgPost` / `OrgDept`（嵌套 `children`）/ `OrgNameRef`（`exists` / `status` 标记）；常量 `ORG_STATUSES`（`enabled`/`disabled`）、`ORG_TARGETS`（`user`/`post`/`dept`）、`DEFAULT_ORG_PAGE_SIZE`（20）。
- **语义**：契约方法**不显式传租户 / 数据范围参数**——租户隔离与数据范围过滤由**实现侧**强制接入，调用方不可绕过；部门树**一次性返回、不分页**；已删除 / 停用对象**不抛错**，由 `OrgNameRef.exists` / `status` 标记（前端回退展示 id）。
- **契约来源**：自 **bms `bms_core/org/`** 迁入 mdm 组织域（bms 需求 11-2 同步移除 `bms_core/org` 与装配）。

## 4. HTTP 出口设计 <a id="api"></a>

| 方法 | 路径（产品命名空间） | 说明 | 权限 |
| --- | --- | --- | --- |
| GET | `/api/mdm/v1/org/users` | 组织数据源 · 用户（关键字 / 部门与含子级 / 状态 / 分页） | `require_auth` |
| GET | `/api/mdm/v1/org/posts` | 组织数据源 · 岗位（关键字 / 部门与含子级 / 状态 / 分页） | `require_auth` |
| GET | `/api/mdm/v1/org/dept-tree` | 组织数据源 · 部门树（一次性返回、不分页） | `require_auth` |
| GET | `/api/mdm/v1/org/resolve-names` | 名称回显（`target` + `id_in` 逗号分隔） | `require_auth` |
| GET | `/api/mdm/v1/org/user-roles` | 按用户解析其经岗位 / 部门获得的角色（并集去重） | `require_auth` |

- **网关**：对外 `/api/mdm/v1/org/...` 经平台网关路由到 mdm `org` 服务（服务内部前缀 `/api/v1`）。
- **鉴权**：出口面向**已登录用户**（`require_auth`）；服务间调用另经服务 JWT（`require_service`，供 bms / 业务产品服务端）。
- **批量回显**：`resolve-names` 按 `id_in` 批量、避免 N+1；非法 `id_in`（非整数）返回参数校验错误。

## 5. 真实取数与数据范围 / 脱敏 <a id="impl"></a>

| 项 | 口径 |
| --- | --- |
| 用户查询 | 承接 bms 用户数据（`sys_user`，跨服务）：mdm 侧按逻辑外键持有用户 id 关联；用户明细（名称 / 部门 / 手机 / 邮箱）经平台用户数据来源获取（服务间契约 / 只读投影），不跨库读 |
| 部门 / 岗位查询 | 本域表（`org_dept` / `org_post`）真实取数；部门含子级经 `ancestors` 前缀展开 |
| 名称回显 | 按 `target` 分派（user / post / dept），单次批量查；`exists=false` / `status` 标记缺失或停用 |
| 数据范围 | 实现侧强制注入（复用 `bms_core` 数据范围注入），按当前用户可见范围过滤，**不暴露给调用方** |
| 脱敏 | 实现侧强制接入（复用 `bms_core` 脱敏基座）：`OrgUser.masked_fields` 声明手机 / 邮箱敏感，序列化自动掩码；持 `data:plain` 权限方可见明文 |

- **一致性**：部门 / 岗位取本域库（写侧唯一归属）；用户维度取平台来源（最终一致 + 按需一致性屏障）。
- **失败降级**：平台用户来源不可达时，用户维度出口返回明确降级错误（`33xxxx`），不静默返回旧值。

## 6. 按用户解析角色契约 <a id="user-roles"></a>

| 项 | 口径 |
| --- | --- |
| 入参 | `user_id`（+ 租户位由请求上下文提供） |
| 解析 | 用户 → 岗位（`org_user_post`）→ 角色（`org_role_post`）∪ 用户 → 部门（`sys_user.dept_id` / 部门主体）→ 角色（`org_role_dept`） |
| 返回 | 角色 id 集合（**并集去重**）；不返回用户直接角色（`sys_user_role` 留 bms，由 bms 侧合并） |
| 性能 | 单次查询批量解析；结果可短时缓存，随 `org.role_post.changed` / `org.role_dept.changed` 失效 |
| 消费方 | bms 权限计算引擎（跨服务汇总，取并集） |

## 7. 事件契约 <a id="events"></a>

| 事件 | 触发 | 主要载荷 | Webhook |
| --- | --- | --- | --- |
| `org.dept.changed` | 部门增删改 / 移动 | `dept_id`、`parent_id` | 否 |
| `org.post.changed` | 岗位增删改 / 启停 | `post_id`、`dept_id`、`status` | 否 |
| `org.user_post.changed` | 用户-岗位分配 / 解绑 | `user_id`、`post_ids` | 否 |
| `org.role_post.changed` | 角色-岗位分配 / 解绑 | `role_id`、`post_ids` | 否 |
| `org.role_dept.changed` | 角色-部门分配 / 解绑 | `role_id`、`dept_ids` | 否 |

- **契约登记**：经事件契约注册表登记（口径同 bms），字段**只增不删**、破坏性变更升版本；事件域 `org.*` 已在服务目录登记。
- **发布**：写侧（01_02）在本地事务内写 Outbox，投递器转发平台事件总线（库↔事件原子）。

## 8. 失败分支与边界 <a id="edge"></a>

| 场景 | 处置 |
| --- | --- |
| 平台用户来源不可达 | 用户维度出口降级报错（不静默旧值）；部门 / 岗位出口不受影响 |
| `id_in` 非法 | 参数校验错误（不 500） |
| 回显 id 不存在 / 已停用 | 不抛错，`exists=false` / `status=disabled` 标记 |
| 无数据范围权限 | 结果按范围过滤为空（不报错、不泄露） |
| 敏感字段无明文权限 | 掩码返回 |
| 事件发布失败 | 不影响主事务（Outbox 重试） |
