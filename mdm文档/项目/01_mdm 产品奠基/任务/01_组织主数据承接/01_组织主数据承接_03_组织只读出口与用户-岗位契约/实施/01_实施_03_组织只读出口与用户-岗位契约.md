1. **上下文与决策**：按《AI开发规范》读 bms 规范（AI开发规范）、bms `bms_core/org/{base,null}.py`、`core/assembly.py`（`PLUGIN_WIRINGS`）、`api/deps.py`、bms 前端 `OrgSourceAdapter`（`org-source.ts` / `org-select.ts` / `utils/orgSource.ts`）、bms 需求 11（组织服务退役）、bms 阶段七计划与 `02_用户与角色`、mdm 需求 01-3 / 任务 01_03 / 详设 / 01_02 实施与测试记录 / 架构总览 / 概要设计 02·03 / 数据库设计总览 / 计划。
   - **待拍板事项逐项确认（question 工具，共 24 项 / 9 批）**：出口路径落点、出口鉴权口径、用户取数方式、用户-部门缺口、端口装配落点、数据范围与脱敏接入口径、契约基线与门禁归属、前端类型归属、缓存与失效策略、兼容期口径、跨仓改动归属、范围对齐、缓存落点、bms 登记归口、内部契约字段范围、一致性屏障、屏障回退、bms 子任务编号、`sys_user.dept_id` 取数通道**回退为不引入**、窗口口径、users 部门过滤实现、user-roles 部门链粒度、缓存失效粒度、原型迁移落点。
   - **实施中发现并回写设计的偏差**：① **响应包装**——基座集合类须经契约标注方可作为响应模型字段，`dept-tree` / `resolve-names` 由「裸数组」改为 `{items:[...]}` 包装（前端 `readArray` 兼容 `items`）；② 数据范围条件形态判定改为按 `Iterable` 而非 `list`（基座 `ConcurrentStableList` 是 `Sequence` 而非 `list` 子类）；③ 业务失败统一 HTTP 200 + 统一响应 `code`（`ParamError` 亦为 200，不裸 4xx）。
2. **原型设计迁入（先原型后实现的前提物）**：把组织域原型自 bms 迁入 mdm 并**按模块分两个目录**——`mdm文档/设计/原型设计/{01_原型设计_总览.html, 02_岗位管理/*, 03_部门管理/*}`（设计说明 + 列表页 + 表单页）；静态资源不复制，改为相对引用 `../../../bms文档/设计/原型设计/资源/`；bms 侧 `11_部门与岗位` 目录删除、总览与公共原型说明改为纯文本指向 mdm。
3. **详设重写与台账回写**：重写本任务详设（24 项决策 / 出口路径与鉴权 / 端口与实现 / 缓存与失效 / 错误码 / 交付物 / 测试设计 / 登记落点 / 开放项）；回写任务文档（范围收敛、前置契约表、原型对照交付物）、需求 01-3、概要设计 02·03（原型依据）、架构总览（出口路径与鉴权、用户来源、缓存）、阶段一计划。
4. **bms 跨仓联动立项**：bms 侧新增子任务 `02_用户与角色_06_平台用户只读出口内部契约`（需求 07-2 注记、父任务子任务数、阶段七计划联动），并在本任务内实施该内部契约（见 §4 第 13 项）。
5. **Kiwi 先登记后编码**：登记输入 `test/scripts/kiwi/cases/2026-10-07_mdm阶段一01-03_组织只读出口与用户-岗位契约.json`（经 `register_cases.py` 走 Kiwi 容器 Django shell），平台回读编号 **2256**；用例代码以 `@pytest.mark.kiwi_id(2256)` 标注（bms 02_06 同批登记 **2257**）。
6. **端口契约与数据契约**：新建 `mdm_org/org/base.py`——自 bms `bms_core/org` 迁入常量（`ORG_STATUSES` / `ORG_TARGETS` / `DEFAULT_ORG_PAGE_SIZE`）与数据契约（`OrgUser`（手机 / 邮箱声明为敏感字段）/ `OrgPost` / `OrgDept`（嵌套树）/ `OrgNameRef`），并新增**用户来源端口** `BaseOrgUserSource`（`query` / `by_ids`）；三端口保留基座 `BasePluggable` 形态但**不依赖平台 `PLUGIN_WIRINGS`**（组织服务退役后平台侧不再有本域接线）。
7. **真实取数实现**：新建 `mdm_org/org/default.py`——`DbOrgDataSource`（`posts` / `dept_tree` 取本域库；部门过滤按 `ancestors` 展开子树；**数据范围 `dept_scope` 由装配侧注入并按之限定**；`users` 经用户来源端口，部门过滤按「该部门（含子树）下岗位且用户已分配该岗位」派生候选集并受 `org.data_source_max_filter_ids` 上限约束）与 `DbOrgNameResolver`（岗位 / 部门取本域库、用户取来源；单批 `IN` 查询避免 N+1；未命中占位 `exists=false` / `status=disabled`）。
8. **用户来源实现**：新建 `mdm_org/org/user_source.py`——`PlatformOrgUserSource` 经 `service_client` 基座调 bms platform 内部端点 `POST /api/v1/platform/internal/users/query`（东西向直连不经网关；出站附自签服务 JWT + `tenant` claim），**不跨库读 `sys_user`**；下行不可达 / 非 2xx / 业务码非 0 / 响应契约非法一律 fail-closed 转 `330101`（不静默返回空或旧值）。
9. **出口服务**：新建 `mdm_org/services/open_read.py`——`OpenReadService` 编排四类取数 + `user_roles`（岗位链 `org_user_post → org_role_post` ∪ 部门链「用户归属部门 → `org_role_dept` 精确匹配」、并集去重保 insertion 序；不返回用户直接角色）；结果按租户 + 用户短时缓存（`org.user_roles_cache_ttl`，≤0 即直查），缓存键内嵌**租户级失效代**；`bump_user_roles_generation()` 供写侧推进失效代。
10. **响应契约与出口路由**：新建 `mdm_org/schemas/open_read.py`（`OrgDeptTree` / `OrgNameRefs` / `OrgUserRoles`，集合字段内联 `CONTRACT_COLLECTION` 标注）与 `mdm_org/api/open_read.py`——出口挂 `/org/data-source/{users,posts,dept-tree}` + `/org/resolve-names` + `/org/user-roles`（与 01_02 管理面**路径彻底分离**）；`require_org_reader` 实现**双通道鉴权**（服务身份 + 调用方白名单优先，否则回落 `require_auth`）；`get_dept_scope` 读基座 `DataScope` 并解析部门范围（实现侧强制接入、调用方不可绕过）；路由级 `Depends(get_masker)` 激活脱敏上下文；`resolve-names` 的 `id_in` 上限 200、空段忽略。
11. **仓储扩展与写侧失效接线**：仓储补批量 `IN` 查询（`DeptRepository.list_by_ids`、`PostRepository.list_by_depts/list_by_ids`、`UserPostRepository.list_by_posts`、`RolePostRepository.list_by_posts`）与 `PostRepository` 的 `dept_ids` 过滤；角色-岗位 / 角色-部门 / 用户-岗位三类分配的**写端点**（全量覆盖与解绑共 6 处）在写成功后推进失效代。
12. **错误码与配置**：`mdm_org/errors.py` 新增 `330101`（用户来源不可达 / 未装配）与 `OrgSourceUnavailableError`；`mdm_org/config.py` 新增 `org.data_source_max_filter_ids`（默认 1000）与 `org.user_roles_cache_ttl`（默认 30）；`config.toml` 增 `[cache]`（dev/test `memory`）与 `[service_client]`（`http` + 出站附服务 JWT），`config.prod.toml` 切 `[cache] redis`。
13. **跨仓 bms 改动（同批交付）**：bms platform 新增 `POST /api/v1/platform/internal/users/query`（独立 `query_router`，`require_service("org")` 白名单，与既有 `require_service("identity")` 路由分离——模块级依赖无法按路由放宽）+ 请求 / 响应契约 + 仓储 `ids` 限定集合 + 查询服务；**不含 `dept_id` 过滤**（待平台字段落地）；同步重生成 platform 契约快照与前端 `api-types`，基线**零破坏**（纯加性）。
14. **契约基线与门禁**：新建 `ops/contract_gate.py`（基线管理 + 破坏性变更比对，`--engine auto|oasdiff|structural`；结构化引擎内置「只加不删」判定：路径 / 操作 / 响应码 / 组件 schema 与属性不得删除，新增放行）与基线 `deploy/contracts/baseline/org.json`；CI `backend-modules` 增 `ops.contract_gate check`。
15. **用例**：`services/org/tests/open_read/`（取数三契约 / 部门过滤过渡口径与上限 / 数据范围交与并 / 名称回显三类与占位 / 按用户解析角色并集与去重 / 缓存命中与失效代 / TTL 关闭 / 用户来源 fail-closed / 出口路由响应形态与参数校验 / 鉴权双通道与白名单 / 用户来源解析与降级矩阵 / 数据范围条件解析）、`tests/test_contract_gate.py`（结构化判定四类破坏 / oasdiff 输出解析 / 基线缺件与篡改 / CLI / docker 调用编排）、`tests_support/org_env.py` 扩展（用户来源替身与不可用替身、服务客户端替身、出口服务与数据源装配、组织树造数）。
16. **验证**：见 §5；**记录**：见 §6 / §7。
