## 2. 任务内容 <a id="content"></a>

1. **只读出口两契约**（自 bms `bms_core/org` 迁入）：组织数据源（`users` / `posts` / `dept_tree`）+ 名称回显（`resolve_names`）；**真实取数**，租户隔离与动作级数据范围经数据范围注入、敏感字段经脱敏（**实现侧强制接入，调用方不可绕过**）；部门树一次性返回、不分页。**HTTP 出口路径**：`/api/v1/org/data-source/{users,posts,dept-tree}` 与 `/api/v1/org/resolve-names`（对外 `/api/mdm/v1/org/...`）。
2. **用户数据来源**：新增 `BaseOrgUserSource` 端口 + 平台实现（经服务间调用 bms platform 新增的 `/api/v1/platform/internal/users/query`）；mdm **不跨库读** `sys_user`。平台不可达时用户维度出口明确降级报错（`330101`），不静默返回旧值。
3. **按用户解析角色只读契约**：`GET /api/v1/org/user-roles`（入参 `user_id`），供 bms 权限引擎跨服务汇总（岗位 / 部门角色并集去重）；结果按租户 + 用户**短时缓存**，写侧以**租户级失效代**失效。
4. **鉴权**：出口一律 `require_auth`（已登录用户）+ 服务间经 `require_service`（调用方服务白名单，当前 `platform`）。
5. **公开契约基线与门禁**：`deploy/contracts/baseline/org.json` + `ops.contract_gate`（oasdiff 破坏性变更比对，接 CI）；快照重生成零漂移。
6. **事件发布**：`org.dept.changed` / `org.post.changed` / `org.role_post.changed` / `org.role_dept.changed`（+ `org.user_post.changed`）——**已随 01_02 登记并发布**，本任务只核验契约零漂移。
7. **组织域原型迁入**：部门 / 岗位页面原型随职责自 bms 迁入 mdm，**按模块拆为两组**（`设计/原型设计/02_岗位管理/`、`03_部门管理/`）+ 新建 mdm 原型总览；bms 原址改纯文本指向（跨仓不设链接）。本任务无界面源码变更，测试记录按「原型对照：不适用 + 理由」登记。

> **范围收敛（2026-10-07 拍板）**：本任务原列的「用户-岗位契约（按用户查岗位 / 全量分配 / 解绑）」**已由 01_02 交付**（`GET /org/user-posts`、`PUT /org/user-posts/{user_id}`、`DELETE /org/user-posts/{user_id}/{post_id}`），本任务不重复建设。
