## 1. 域说明 <a id="intro"></a>

本域对应 mdm 阶段一「组织主数据承接」：**组织主数据（部门 / 岗位 / 用户-岗位 / 岗位与部门角色分配）统一由 mdm 承载**，配合 bms 原 `org` 服务退役；mdm 落产品工程骨架与平台接入，实现组织主数据域，交付**组织只读出口**（组织数据源 / 名称回显）与**用户-岗位契约**、**按用户解析角色只读契约**，供 bms 与业务产品经契约 / 事件一致性引用。

**依据**：《[mdm 主数据管理规划](../../../规划/mdm主数据管理规划.md)》（「组织服务归位」「标识符登记」「与业务产品的引用边界」节）、《[架构设计 · 总览](../../../设计/架构设计/01_架构设计_总览.md)》《[概要设计 · 总览](../../../设计/概要设计/01_概要设计_总览.md)》（组织域）、《[mdm 知识档案总览](../../../资料/知识档案/mdm知识档案总览.md)》主数据管理专题、bms《微服务演进规划》（服务化地基 S1~S7）、《平台可扩展性规划》（产品接入形态，经软链 `bms文档` 引用）。

**依赖与顺序**：本域为 bms 侧「组织服务退役」（bms 阶段二 需求域十一）前置——需 **mdm 先实现、bms 后退役**；`01-3` 交付后方可 `01-4` 与 bms 退役。

## 2. 需求 01-1：mdm 产品工程骨架与平台接入 <a id="r01-1"></a>

优先级：2（高）

**背景与动机**：mdm 目前仅有文档、尚无代码；承接组织主数据须先落**产品后端工程与平台接入**（认证 / 网关 / 事件 / 每服务独立库），作为主数据域的承载基座。

**内容**（《[mdm 主数据管理规划](../../../规划/mdm主数据管理规划.md)》「平台复用边界」「演进路线」节）：

1. **产品服务工程**：mdm 后端按主数据域拆服务、每服务独立库（× 每租户）的工程骨架（FastAPI + uv 工作区结构，与 bms 平台工程同构）；组织域为**首个服务**。
2. **平台接入**：OIDC 认证（复用 bms IdP）+ 开放接口（`/api/open`）+ 事件总线接入；**服务目录登记**（`sys_module` 升格，服务标识与域简称一致：`org` ↔ `org_` ↔ `org` ↔ `33xxxx` ↔ `org.*`）。
3. **部署与 CI**：服务容器化与编排、产品侧 CI 流水线（构建 / 测试 / 契约）。
4. **复用平台能力**：认证 / RBAC / 审计 / 事件 / 文件 / 字典等一律复用 bms，mdm 不重复实现。

**完成标准**：mdm 产品服务可启动（`/healthz` / `readyz`）、经网关可达、服务目录登记校验通过、CI 可构建；`pytest` / `ruff` / `pyright` 全绿。

**参考文档**：《[mdm 主数据管理规划](../../../规划/mdm主数据管理规划.md)》「平台复用边界」「依赖台账」节；bms《微服务演进规划》《平台可扩展性规划》

## 3. 需求 01-2：组织主数据域实现 <a id="r01-2"></a>

优先级：2（高）

**背景与动机**：组织主数据（部门 / 岗位 / 用户-岗位 / 角色分配）原由 bms `org` 服务占位承载，实为跨业务共享主数据；须在 mdm 组织域真实落库并对外可用，bms 方可退役。

**内容**（《[架构设计 · 总览](../../../设计/架构设计/01_架构设计_总览.md)》「域服务划分与数据边界」节、《[概要设计 · 总览](../../../设计/概要设计/01_概要设计_总览.md)》组织域）：

1. **数据模型**：部门（组织架构树 `org_dept`）、岗位（归属部门 `org_post`）、用户-岗位关联（`org_user_post`）、角色-岗位（`org_role_post`）、角色-部门（`org_role_dept`）五表；先落表文件（含变更记录）→ ORM 模型 → 迁移。
2. **维护能力**：各实体 CRUD、部门树移动（级联维护子树）、状态 / 冻结 / 注销；权限码域级 `org:query` / `org:create` / `org:update` / `org:delete` 与域专属动作（`org:move` 等）。
3. **质量与留痕**：录入校验 + 唯一约束（源头控质）；ORM 事件接入审计（谁在何时改了什么）。
4. **用户联动**：用户删除经事件驱动清理用户-岗位关联。

**完成标准**：五表落库且迁移可跑；各实体 CRUD 与部门树可用；校验与唯一约束生效；审计接入；`pytest` / `ruff` / `pyright` 全绿。

**参考文档**：《[概要设计 · 总览](../../../设计/概要设计/01_概要设计_总览.md)》；《[mdm 英文简称规范](../../../规范/英文简称规范.md)》；mdm 知识档案《[主数据管理 · 数据标准与数据模型](../../../资料/知识档案/主数据管理/06_主数据管理_数据标准与数据模型.md)》

## 4. 需求 01-3：组织只读出口与用户-岗位契约 <a id="r01-3"></a>

优先级：2（高）

**背景与动机**：bms 与业务产品对组织的引用**只经只读出口**（不跨库、不自建）；原 `bms_core/org` 两契约（组织数据源 / 名称回显）随组织主数据迁 mdm，须在 mdm 实现真实取数并对外提供。

**内容**（《[架构设计 · 总览](../../../设计/架构设计/01_架构设计_总览.md)》「域服务划分与数据边界」节；bms《后端开发规范》「组织主数据」节）：

1. **只读出口两契约**（自 `bms_core/org` 迁入）：组织数据源（`users` / `posts` / `dept_tree`）+ 名称回显（`resolve_names`）；**真实取数**，租户隔离与动作级数据范围经数据范围注入、敏感字段经脱敏（**实现侧强制接入，调用方不可绕过**）；部门树一次性返回、不分页。
2. **用户-岗位契约**：按用户查岗位 / 全量分配 / 解绑（供 bms 用户管理页经具名插槽插件读写）。
3. **按用户解析角色只读契约**：`/api/v1/org/user-roles`，供 bms 权限引擎跨服务汇总（岗位 / 部门角色）。
4. **事件发布**：`org.dept.changed` / `org.post.changed` / `org.role_post.changed` / `org.role_dept.changed`，供消费方刷新投影 / 缓存。

**完成标准**：两契约实现真实取数（经 bms 前端联通）；用户-岗位契约与按用户解析角色契约可用；事件发布与审计接入；`pytest` / `ruff` / `pyright` 全绿。

**参考文档**：《[架构设计 · 总览](../../../设计/架构设计/01_架构设计_总览.md)》「域服务划分与数据边界」节；bms《后端开发规范》「组织主数据」节；bms《架构设计 · 事件总线》《架构设计 · 权限计算引擎》

> 注（实现期要点，2026-10-07）：**范围收敛**——「用户-岗位契约（按用户查岗位 / 全量分配 / 解绑）」**已由任务 `01_02` 交付**（管理面 `/api/v1/org/user-posts`），本需求实施范围为「只读出口两契约 + 按用户解析角色只读契约」。要点：出口路径＝`/api/v1/org/data-source/{users,posts,dept-tree}` + `/api/v1/org/resolve-names` + `/api/v1/org/user-roles`（对外 `/api/mdm/v1/org/...`，**与管面路径分离**）；鉴权＝`require_auth`（用户）+ `require_service`（服务间白名单）；数据范围 / 脱敏**实现侧强制接入**（基座 `DataScope` / `BaseMasker`）；**用户明细经 bms 平台用户只读出口内部契约取数（bms 阶段七任务 `02_06`）、mdm 不跨库读 `sys_user`**，平台不可达时用户维度明确降级报错（`330101`）；`user-roles` 短时缓存 + **租户级失效代**失效；公开契约基线与 oasdiff 门禁本任务建立；5 条 `org.*` 事件契约已随 `01_02` 登记（本任务只核验零漂移）。详见任务 [01_03](../任务/01_组织主数据承接/01_组织主数据承接_03_组织只读出口与用户-岗位契约/01_组织主数据承接_03_组织只读出口与用户-岗位契约.md) 与[详细设计](../任务/01_组织主数据承接/01_组织主数据承接_03_组织只读出口与用户-岗位契约/设计/01_详细设计_03_组织只读出口与用户-岗位契约.md)。

## 5. 需求 01-4：前端接入与 bms 切换支撑 <a id="r01-4"></a>

优先级：3（中）

**背景与动机**：bms 前端组织选择字段现经 bms `org` 服务 HTTP 出口取数，退役后须切 mdm 出口；mdm 须提供与前端对齐的公开契约与类型。

**内容**：

1. **前端切换**：配合 bms 需求 `11-2`，前端组织选择字段族（`OrgSelectField` / `PostSelectField` / `DeptTreeSelectField` / `OrgCompositePicker`）出口地址切 mdm 组织域公开契约；`OrgSourceAdapter` http 默认实现指向 mdm 出口。
2. **契约与类型**：mdm 组织域公开契约（OpenAPI）与前端类型生成对齐。
3. **联调与验收**：与 bms 侧退役验收联合验证（组织主数据查询 / 批量回显 / 部门树全链路联通）。

**完成标准**：前端组织选择经 mdm 出口联通（查询与批量回显分列、部门树一次性返回）；bms `org` 服务退役验收通过（bms 需求 `11-2` / `11-3`）。

**参考文档**：《[mdm 主数据管理规划](../../../规划/mdm主数据管理规划.md)》「与业务产品的引用边界」节；bms《前端基类清单》「组织选择字段」；bms 需求 [11-2](../../../../bms文档/项目/02_后端基座与服务化地基/需求/11_需求_组织服务退役.md#r11-2)
