## 1. 域说明 <a id="intro"></a>

本域对应 mdm 阶段一「组织主数据承接」：**组织主数据（部门 / 岗位 / 用户-岗位 / 岗位与部门角色分配）统一由 mdm 承载**，配合 bms 原 `org` 服务退役；mdm 落产品工程骨架与平台接入，实现组织主数据域，交付**组织只读出口**（组织数据源 / 名称回显）与**用户-岗位契约**、**按用户解析角色只读契约**，供 bms 与业务产品经契约 / 事件一致性引用。

**依据**：《[mdm 主数据管理规划](../../../规划/mdm主数据管理规划.md)》（「组织服务归位」「标识符登记」「与业务产品的引用边界」节）、《[架构设计 · 总览](../../../设计/架构设计/01_架构设计_总览.md)》《[概要设计 · 总览](../../../设计/概要设计/01_概要设计_总览.md)》（组织域）、《[mdm 知识档案总览](../../../资料/知识档案/mdm知识档案总览.md)》主数据管理专题、bms《微服务演进规划》（服务化地基 S1~S7）、《平台可扩展性规划》（产品接入形态，经软链 `bms文档` 引用）。

**依赖与顺序**：本域为 bms 侧「组织服务退役」（bms 阶段二 需求域十一）前置——需 **mdm 先实现、bms 后退役**；`01-3` 交付后方可 `01-4` 与 bms 退役。

## 2. 需求 01-1：mdm 产品工程骨架与平台接入 <a id="r01-1"></a>

优先级：2（高）

**背景与动机**：mdm 目前仅有文档、尚无代码；承接组织主数据须先落**产品后端工程与平台接入**（认证 / 网关 / 事件 / 每服务独立库），作为主数据域的承载基座。

**内容**（《[mdm 主数据管理规划](../../../规划/mdm主数据管理规划.md)》「平台复用边界」「演进路线」节）：

1. **产品服务工程**：mdm 后端按主数据域拆服务、每服务独立库（× 每租户）的工程骨架（FastAPI + uv 工作区结构，与 bms 平台工程同构）；组织域为**首个服务**。
2. **平台接入**：OIDC 认证（复用 bms IdP）+ 开放接口（`/api/open`）+ 事件总线接入；**服务目录登记**（`sys_module` 升格，服务标识与域简称一致：`org` ↔ `org_` ↔ `org` ↔ `33xxxx` ↔ `org.*`）。
3. **部署与 CI**：服务容器化与编排、产品侧 CI 流水线（构建 / 测试 / 契约）。
4. **复用平台能力**：认证 / RBAC / 审计 / 事件 / 文件 / 字典等一律复用 bms，mdm 不重复实现。

**完成标准**：mdm 产品服务可启动（`/healthz` / `readyz`）、经网关可达、服务目录登记校验通过、CI 可构建；`pytest` / `ruff` / `pyright` 全绿。

**参考文档**：《[mdm 主数据管理规划](../../../规划/mdm主数据管理规划.md)》「平台复用边界」「依赖台账」节；bms《微服务演进规划》《平台可扩展性规划》

## 4. 需求 01-3：组织只读出口与用户-岗位契约 <a id="r01-3"></a>

优先级：2（高）

**背景与动机**：bms 与业务产品对组织的引用**只经只读出口**（不跨库、不自建）；原 `bms_core/org` 两契约（组织数据源 / 名称回显）随组织主数据迁 mdm，须在 mdm 实现真实取数并对外提供。

**内容**（《[架构设计 · 总览](../../../设计/架构设计/01_架构设计_总览.md)》「域服务划分与数据边界」节；bms《后端开发规范》「组织主数据」节）：

1. **只读出口两契约**（自 `bms_core/org` 迁入）：组织数据源（`users` / `posts` / `dept_tree`）+ 名称回显（`resolve_names`）；**真实取数**，租户隔离与动作级数据范围经数据范围注入、敏感字段经脱敏（**实现侧强制接入，调用方不可绕过**）；部门树一次性返回、不分页。
2. **用户-岗位契约**：按用户查岗位 / 全量分配 / 解绑（供 bms 用户管理页经具名插槽插件读写）。
3. **按用户解析角色只读契约**：`/api/v1/mdm/user-roles`，供 bms 权限引擎跨服务汇总（岗位 / 部门角色）。
4. **事件发布**：`mdm.dept.changed` / `mdm.post.changed` / `mdm.role_post.changed` / `mdm.role_dept.changed`，供消费方刷新投影 / 缓存。

**完成标准**：两契约实现真实取数（经 bms 前端联通）；用户-岗位契约与按用户解析角色契约可用；事件发布与审计接入；`pytest` / `ruff` / `pyright` 全绿。

**参考文档**：《[架构设计 · 总览](../../../设计/架构设计/01_架构设计_总览.md)》「域服务划分与数据边界」节；bms《后端开发规范》「组织主数据」节；bms《架构设计 · 事件总线》《架构设计 · 权限计算引擎》

> 注（实现期要点，2026-10-07）：**范围收敛**——「用户-岗位契约（按用户查岗位 / 全量分配 / 解绑）」**已由任务 `01_02` 交付**（管理面 `/api/v1/mdm/user-posts`），本需求实施范围为「只读出口两契约 + 按用户解析角色只读契约」。要点：出口路径＝`/api/v1/mdm/data-source/{users,posts,dept-tree}` + `/api/v1/mdm/resolve-names` + `/api/v1/mdm/user-roles`（对外 `/api/mdm/v1/mdm/...`，**与管面路径分离**）；鉴权＝`require_auth`（用户）+ `require_service`（服务间白名单）；数据范围 / 脱敏**实现侧强制接入**（基座 `DataScope` / `BaseMasker`）；**用户明细经 bms 平台用户只读出口内部契约取数（bms 阶段七任务 `02_06`）、mdm 不跨库读 `sys_user`**，平台不可达时用户维度明确降级报错（`330101`）；`user-roles` 短时缓存 + **租户级失效代**失效；公开契约基线与 oasdiff 门禁本任务建立；5 条 `org.*` 事件契约已随 `01_02` 登记（本任务只核验零漂移）。详见任务 [01_03](../任务/01_组织主数据承接/01_组织主数据承接_03_组织只读出口与用户-岗位契约/01_组织主数据承接_03_组织只读出口与用户-岗位契约.md) 与[详细设计](../任务/01_组织主数据承接/01_组织主数据承接_03_组织只读出口与用户-岗位契约/设计/01_详细设计_03_组织只读出口与用户-岗位契约.md)。

## 5. 需求 01-4：前端接入与 bms 切换支撑 <a id="r01-4"></a>

优先级：3（中）

**背景与动机**：bms 前端组织选择字段现经 bms `org` 服务 HTTP 出口取数，退役后须切 mdm 出口；mdm 须提供与前端对齐的公开契约与类型。另：组织主数据的**管理面**（部门 / 岗位维护）与「挂在 bms 页面里的分配功能块」同样须由 mdm 自持前端交付（bms 不再保留组织主数据页面），故 mdm 须自建前端工程并以运行时模块接入 bms 宿主。

**内容**（2026-10-08 范围扩容定稿：原三项 → 五项）：

1. **mdm 前端工程与运行时模块接入**：mdm 自建前端工程（Vue 3 + TS，`frontend/` 工作区），以**运行时模块**形态（模块名 `mdm_org`，2026-10-25 按需求 `01-7` 由 `mdm-org` 改为 snake_case）独立构建产物并经平台模块清单接入 bms 宿主；构建与发布编排遵循平台「跨仓接入」口径（平台侧执行发布，链路不持跨仓凭据）。

**完成标准**：① 前端工程可独立构建出可接入平台的模块产物，管理页与**四个插件**经**可交互原型逐页对照**通过；② 类型生成物与契约快照零漂移（门禁可复跑）；③ 前端组织选择经 mdm 出口联通（查询与批量回显分列、部门树一次性返回）；④ bms `org` 服务退役验收通过（bms 需求 `11-2` / `11-3`）。

**参考文档**：《[mdm 主数据管理规划](../../../规划/mdm主数据管理规划.md)》「与业务产品的引用边界」节；bms《前端基类清单》「组织选择字段」；bms《[微前端业务模块接入指南](../../../../bms文档/资料/知识档案/微前端/10_微前端_业务模块接入指南.md)》（含「跨仓接入」节）；bms 需求 [11-2](../../../../bms文档/项目/02_后端基座与服务化地基/需求/11_需求_组织服务退役.md#r11-2)

## 6. 需求 01-5：组织主数据表系统字段对齐（`form_key` / `parent_id`） <a id="r01-5"></a>

优先级：2（高）

**背景与动机**：bms「统一数据源注册与通用数据接口」（需求 `02-57`）落定**系统字段**口径——《数据库开发规范》「系统字段」节：字典表 = 基础系统字段 ＋ **`form_key`（表单标识）** / `code` / `name` / `status` / `parent_id`。`form_key` 为**多表联合（union）取数的表判别列**（同表所有行同值、每表常量、全局唯一、保存后不变），供通用页面路由 / 查询方案 / 用户偏好引用。mdm 组织主数据表建于该口径之前——`mdm_dept` / `mdm_post` 已有 `code` / `name` / `status`（`mdm_dept` 另有 `parent_id`），**仅缺 `form_key`**（`mdm_post` 另缺 `parent_id`）；不对齐则组织域数据无法参与 bms 通用出口与通用页面路由。

**内容**（依据 bms 任务 `02_11`（系统字段 `form_key` 落表）交付口径）：

1. `mdm_dept` 落 `form_key`（＝ `mdm_dept`）＋ `(form_key, deleted_at)` 复合唯一；
2. `mdm_post` 落 `form_key`（＝ `mdm_post`）＋ `parent_id`（非层级字典按系统字段口径保留冗余，顶层 NULL）；
3. **4 张关联表不处置**（`mdm_user_dept` / `mdm_role_dept` / `mdm_role_post` / `mdm_user_post`——关联表不套明细口径，不落 `form_key` / `parent_id`）；
4. 表文件（含变更记录）→ ORM 模型 → `mdm:tenant` 链新增一条迁移；**表文件 ↔ 模型 ↔ 迁移零漂移**；
5. `form_key` 值登记进 bms `form_key` 构建期清单（`bms_core/registry/forms.py` 的注入通道）——满足**跨表全局唯一**。

## 7. 需求 01-6：mdm 服务标识归并（`org` → `mdm`） <a id="r01-6"></a>

优先级：2（高）

**背景与动机**：mdm 以产品形态接入平台，但内部服务标识沿用承接前的 `org`——产品名（mdm）与服务名（org）双轨并存：库 `mdm_org`、迁移链 `org:tenant`、表前缀 `org_`、事件域 `org.*`、对外域段 `/api/mdm/v1/org/...` 五处口径不一致。后续每新增一个主数据域都要再起一个与产品名无关的服务名（如参考数据域只能叫 `ref`），与「mdm 一个产品」背离。另一处是平台侧耦合：bms 在 `SERVICE_CATALOG` / `PRODUCT_ROUTES` / `DATA_SOURCE_CATALOG` 三个常量里写死 mdm 的服务行、产品路由与数据源条目，产品内容进入基座源码。2026-10-23 拍板两条口径：① 服务标识统一 `mdm`；② 产品登记改**产品仓自持清单 + 装载时注册**，bms 不持有产品字面量。

**内容**：

1. **服务标识**：`org` → `mdm`（服务目录 `module_key` / `service_key` = `mdm`、`table_prefix` = `mdm_`、`event_domain` = `mdm`、`errcode_segment` = `33` 沿用、`build_batch` = `3`、`product_key` = `mdm`）；目录 `services/org` 保留分类，服务包名随服务去重为 `mdm`。
2. **数据实体与迁移**：六表 `org_*` → `mdm_*`；`form_key` / `data_source_key` 与表名同名闭合；迁移链 `org:tenant` → `mdm:tenant`（脚本直接改写；生产未上线，开发库重建）；库名 `mdm_{租户}`（基座派生 `prefix == service` 去重）。
3. **对外路径**：`/api/mdm/v1/org/...` → `/api/mdm/v1/mdm/...`；产品路由登记 `mdm/mdm → mdm`；前端产品域寻址改 `api.product('mdm','mdm')`。
4. **事件与契约**：事件域 `org.*` → `mdm.*`（6 条契约改名）；公开契约 `deploy/contracts/mdm.json` → `mdm.json`（含 baseline）重生成。
5. **产品登记自持与装载时注册**：mdm 仓新增 `deploy/registry/mdm.json`（产品档案 + 服务行 + 产品路由 + 数据源条目）；运行服务导入期经基座注册函数（`register_service_records()` / `register_product_records()` / `register_product_routes()`）注册；bms 装配期与离线脚本（网关生成、离线校验）按配置路径读同一份清单；bms 常量删除 `org` 行、`mdm/org` 路由与 `org_dept` / `org_post` 数据源条目。
6. **基座配套**：库名派生去重（`prefix == service` 时不重复拼接）；新增 `register_product_routes()` / `register_data_source_records()` 及合并视图（`product_routes_view()` / `data_source_records_view()`）；网关生成改读「平台内建 + 产品清单」合并视图。

**完成标准**：服务目录 `mdm` 行与产品清单逐字段同值、库名 `mdm_{租户}`、迁移链 `mdm:tenant` 可跑；六表 `mdm_*` 与 `form_key` / `data_source_key` 同名闭合；对外 `/api/mdm/v1/mdm/...` 可达且网关生成件零漂移；`mdm.*` 事件契约与公开契约快照零漂移；bms 仓不再出现 mdm 字面量（三个常量、网关生成与相关用例）；`pytest` / `ruff` / `pyright` 与定向用例全绿，覆盖率行 + 分支 100%（口径见《AI开发规范》「覆盖率要求」节）。
