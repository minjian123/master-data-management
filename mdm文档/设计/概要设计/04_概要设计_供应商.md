## 1. 模块概述与职责 <a id="overview"></a>

本节对应《mdm 主数据管理规划》「主数据域全景」之**供应商域（sup）**，与「标识符登记」（sup_supplier）。供应商档案由 biz 采购管理**迁出**，作为 mdm 主数据统一维护，供采购（biz pur）、收付款（biz pay）等业务域**逻辑外键 + 快照**引用。

供应商域负责供应商档案的增删改查（`code / name / contact / phone / qualification / status`），维护名称、联系人、联系方式、资质与状态，并向采购/收付款提供供应商查询与名称回显契约。

职责边界：供应商域只维护**主数据档案**，不承载采购询价、准入审核、绩效评估等**业务流转**（归 biz 采购/供应商业务域）；供应商被业务单据引用时保存**名称快照**（code 逻辑外键）；跨服务读走本域契约或事件，禁止跨库 JOIN。

## 2. 功能分解与业务流程 <a id="func"></a>

### 2.1 功能点分解 <a id="func-list"></a>

| 功能点 | 说明 | 权限码 |
| --- | --- | --- |
| 供应商列表/详情 | 按 code/名称/状态/关键字筛选，分页 | sup:query |
| 新建供应商 | code/name/contact/phone/qualification/status | sup:create |
| 修改供应商 | 名称/联系人/资质/状态调整 | sup:update |
| 删除供应商 | 软删除；被业务单据引用时保留（引用走 code + 快照） | sup:delete |
| 启停供应商 | status 切换；停用退出新单据引用选择 | sup:update |
| 资质附件 | 资质附件经 bms 文件服务上传，存文件引用 | sup:update |

### 2.2 业务规则 <a id="func-rules"></a>

- 唯一性：供应商 code 租户内唯一，复合唯一索引 `(code, deleted_at)`；name 建议唯一
- 状态：status = enabled/disabled，停用供应商不再出现在业务单据的供应商选择列表（历史单据快照不受影响）
- 引用约束：供应商变更**不影响已生成单据**（单据保存 supplier code + name 快照）；跨服务引用走逻辑外键，无跨库外键
- 资质：qualification 存资质摘要与文件引用（bms 文件服务）；资质变更落字段级审计
- 变更即时生效：供应商启停 / 名称变更发布 `sup.supplier.changed` 事件，业务侧缓存与检索索引同步

### 2.3 流程步骤 <a id="func-flow"></a>

1. **新建供应商**：填 code/name/联系人/资质 → 校验 code 唯一 → 入库 → 发布 `sup.supplier.changed` → 落审计
2. **停用供应商**：status 置 disabled → 退出业务选择列表 → 发布事件 → 落审计
3. **删除供应商**：引用检查（业务单据走快照、不阻断归档）→ 软删除 → 进回收站
4. **异常分支**：code 冲突返回错误码；被引用供应商停用后历史单据正常展示快照名称

## 3. 关键时序与协作 <a id="sequence"></a>

```mermaid
sequenceDiagram
    autonumber
    participant 管理员
    participant 供应商服务 as mdm 供应商服务（sup）
    participant DB
    participant 事件总线

    管理员->>供应商服务: POST /sup/suppliers
    供应商服务->>DB: 校验 code 唯一 → insert sup_supplier
    供应商服务->>事件总线: 发布 sup.supplier.changed
    Note over 事件总线: 检索索引 / 业务缓存同步
    Note over 管理员: biz 采购申请引用供应商
    Note over 管理员: 单据保存 supplier code + name 快照
```

协作要点：供应商档案为采购（biz pur）、收付款（biz pay）等业务域**共享引用**；业务侧只读经本域契约（查询 / 名称回显），引用走 code + 快照；供应商域不反向依赖业务域。

## 4. 数据模型与表设计 <a id="data"></a>

### 4.1 核心表 <a id="data-tables"></a>

| 表 | 关键字段 | 说明 |
| --- | --- | --- |
| sup_supplier | code、name、contact、phone、qualification、status | 供应商档案主表（mdm 供应商库，每租户一库）；软删除 + 审计字段 + version |
| （引用，biz） | 采购申请/订单存 supplier_code + supplier_name 快照 | 跨服务引用走逻辑外键 + 快照，不做跨库外键 |

### 4.2 索引与唯一约束 <a id="data-index"></a>

- `sup_supplier`：复合唯一索引 `(code, deleted_at)`；索引 status、name（关键字检索）

### 4.3 数据流转 <a id="data-flow"></a>

- 供应商增删改经 ORM 事件落字段级变更审计（bms sys_data_audit_log，按月分表）
- `sup.supplier.changed` 事件：驱动全文检索索引同步、业务侧供应商缓存失效
- 供应商软删除进回收站（recycle 恢复即清除 deleted_at）；过期残留由 Celery 物理清理

## 5. 接口设计 <a id="api"></a>

### 5.1 接口清单 <a id="api-list"></a>

| 方法 | 路径 | 说明 | 权限码 |
| --- | --- | --- | --- |
| GET | /api/v1/sup/suppliers | 供应商列表（page/size；code/名称/状态/关键字） | sup:query |
| POST | /api/v1/sup/suppliers | 新建供应商 | sup:create |
| GET | /api/v1/sup/suppliers/{id} | 供应商详情 | sup:query |
| PUT | /api/v1/sup/suppliers/{id} | 修改供应商（version 乐观锁） | sup:update |
| DELETE | /api/v1/sup/suppliers/{id} | 删除供应商（软删除） | sup:delete |
| GET | /api/v1/sup/suppliers/resolve | 名称回显（按 code 批量取名称，供业务侧引用回显） | sup:query |

### 5.2 分页/幂等/限流 <a id="api-rule"></a>

- 列表分页 `page/size`，响应 `{list, total, page, size}`
- 写接口支持 `Idempotency-Key` 幂等（Redis SETNX 前置拦截 + 唯一约束兜底）
- 限流：写操作按用户维度叠加 slowapi 限制；查询走常规限流

### 5.3 事件发布 <a id="api-events"></a>

| 事件 | 触发时机 | 主要载荷 | Webhook 订阅 |
| --- | --- | --- | --- |
| sup.supplier.changed | 供应商增删改/启停 | supplier_id、code、status | 否 |

## 6. 权限与配置 <a id="perm"></a>

### 6.1 权限码 <a id="perm-codes"></a>

本模块对应 `sup` 业务（供应商主数据），动作：`sup:query`（查询）、`sup:create`（新建）、`sup:update`（修改/启停）、`sup:delete`（删除）。

### 6.2 菜单挂接 <a id="perm-menu"></a>

- 菜单「供应商档案」（form=supplier_form，挂 sup 业务），置于主数据菜单组
- 按钮挂接：新增/编辑/删除/启停（create/update/delete）按角色授予后显隐
- 供应商被业务表单引用（采购申请/订单选择供应商）——引用方按各自权限码校验

### 6.3 sys_config 参数 <a id="perm-config"></a>

| 参数 | 默认 | 说明 |
| --- | --- | --- |
| sup.code_pattern | ^[a-z0-9][a-z0-9_-]{1,31}$ | 供应商 code 格式约束 |

### 6.4 种子数据 <a id="perm-seed"></a>

- 平台库种子：sup 业务码与动作码（query/create/update/delete）、供应商档案菜单/表单/按钮/字段挂接与 i18n 文案
- 租户开通种子：无预置供应商（由管理员按实际维护）

## 7. 错误码与异常处理 <a id="error"></a>

本模块错误码段 **mdm 供应商域 34xxxx**，文案由前端按 i18n 映射。

| 错误码 | 说明 |
| --- | --- |
| 340001 | 供应商不存在 |
| 340002 | 供应商 code 已存在 |
| 340003 | 供应商 code 不符合格式约束 |
| 340004 | 供应商已停用，不可用于新单据 |

异常处理要求：code 冲突返回明确错误码；并发修改用 version 乐观锁；停用不影响历史单据快照引用；`sup.supplier.changed` 发布失败不影响主事务（事件总线重试）。

## 8. 页面清单与验收要点 <a id="page"></a>

### 8.1 页面清单 <a id="page-list"></a>

| 页面 | 端 | 说明 |
| --- | --- | --- |
| 供应商档案 | PC | 供应商列表、新建/编辑/删除、资质与状态维护 |

### 8.2 验收标准 <a id="page-accept"></a>

- 供应商 CRUD 全链路可用；code 唯一与格式校验生效；软删除后回收站可恢复
- 供应商名称/状态变更即时生效于业务选择列表；历史单据快照名称不受影响
- 名称回显契约（resolve）批量回显正确、已删除/停用对象不抛错
- `sup.supplier.changed` 事件发布与消费验证通过；字段级审计与哈希链校验通过
