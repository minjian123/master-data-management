# mdm 后端基类实现契约

> 本仓基类的逐类契约与继承链。平台基类语义（体系根、四段链、形态要求）以 bms《后端基类实现契约》为准，本文件只写 **mdm 自己的端口契约与接线**，不复述平台口径。

[文档首页](../../文档首页.md) › 设计 › 基类体系 › 后端基类实现契约　|　配套：[mdm 后端基类清单](../../后端基类清单.md)

## 1. 范围 <a id="scope"></a>

- **覆盖**：本仓全部可被继承的类（当前 3 个端口基类，见清单 §2）及其接入平台基类体系的链。
- **不覆盖**：平台基类（权威在 bms）、业务实现类（承接实现，不是新基类）。
- **判定入口**：预检步骤「基座：check_backend_base」（`[rules.backend_base]`，`profile = "product"`）。

## 2. 端口通用契约 <a id="port"></a>

三个端口基类统一按平台插件契约声明身份，字段口径一致：

| 字段 | 取值口径 |
| --- | --- |
| `key` / `plugin_key` | 插件端口名（`mdm_data_source` / `mdm_name_resolver` / `mdm_user_source`） |
| `plugin_name` | 缺省 `NULL_PLUGIN_NAME`（未装配时落到空实现，不抛错） |
| `contract_version` | 缺省 `DEFAULT_CONTRACT_VERSION`，按平台契约版本演进 |

**边界**：基类只声明抽象方法与身份，**不实现**取数、缓存、重试；装配由本仓 `configure_plugins` 完成，生命周期与契约校验归平台。

## 3. 逐类语义 <a id="each"></a>

### 3.1 `BaseMdmDataSource` <a id="mdm-data-source"></a>

组织主数据查询契约：用户 / 岗位查询与部门树取数。实现 `DbMdmDataSource` 走本仓库；组织数据归 mdm，**不从平台库直读**。

### 3.2 `BaseMdmNameResolver` <a id="mdm-name-resolver"></a>

组织主数据回显契约：按标识批量回显名称，避免 N+1。未命中 id 也在结果中占位（`exists=False`），不抛错。

### 3.3 `BaseMdmUserSource` <a id="mdm-user-source"></a>

用户明细来源端口（跨服务）：用户（账号）归 platform，mdm 经**平台用户只读出口契约**取数，**不跨库读** `sys_user`；实现 `PlatformMdmUserSource` 走服务间调用。

## 4. 形态要求 <a id="shape"></a>

- 三个端口均为**插件**：继承 `BasePluggable`（进而 `BaseCapability` → `BaseFrameworkObject` → `BaseObject`），**不得**声明为 dataclass；
- 端口方法一律 `@abstractmethod`，实现类必须全覆盖（抽象缺口由运行期装配暴露，预检不替代）；
- 端口不得承载公共字段实现：公共字段 / 方法只在平台对应层基类维护。

## 4.1 工厂类与插件类的归属 <a id="factory-plugin"></a>

按平台基类体系的分工，本仓各类落在下列基类上（**不得错层**：工厂接工厂基类、插件接插件基类）：

| 类别 | 本仓类 | 应继承（平台） | 说明 |
| --- | --- | --- | --- |
| 服务应用工厂 | `ApplicationFactory` | `BaseServiceApplicationFactory` | 服务身份 / 中间件 / 插件装配统一挂载 |
| 插件（可插拔端口） | `BaseMdmDataSource` / `BaseMdmNameResolver` / `BaseMdmUserSource` | `BasePluggable` | 带 `plugin_key`，经插件注册表解析，未装配落 `Null` 实现 |
| 端口实现类 | `DbMdmDataSource` / `DbMdmNameResolver` / `PlatformMdmUserSource` | 本表基类 | 承接实现，不是新基类 |

**判定口径**：一个类是否属「插件」，看它是否有 `plugin_key` 身份并经插件注册表解析——不是看名字；工厂必须落在 `BaseFactory` 链上（插件型工厂经 `BasePluginFactory`），不得直接继承 `BaseObject` 或裸 `ABC`。

## 5. 错误码段位 <a id="errcodes"></a>

本仓错误码为**产品码**：6 位 = 2 位段位 + 4 位序号，段位 `33` 取自服务行 `errcode_segment`，不在代码里手写段位。预检按段位与位数判定，段位不符即失败。

## 6. 迁移链 <a id="migrations"></a>

迁移脚本落 `backend/alembic/versions/`，按域分目录；要求**单 head**、不断链、分支标签与配置段一致。预检判该三项。

## 7. 继承链与代码位置 <a id="chain"></a>

> 本仓**不新增体系根**：允许直接继承 `BaseObject` 的只有下列平台体系根；本仓自有基类一律挂在平台链的下方。

**体系根清单（允许直接继承 `BaseObject`）**：

- `BaseValueObject`
- `BaseDataContract`
- `BaseFrameworkObject`
- `BaseCollection`
- `BaseRepository`
- `BaseService`
- `UnitOfWork`

**本仓继承链（产品段）**：

- `BaseMdmDataSource` → `BasePluggable`（代码：`mdm/mdm/base.py`）
- `BaseMdmNameResolver` → `BasePluggable`（代码：`mdm/mdm/base.py`）
- `BaseMdmUserSource` → `BasePluggable`（代码：`mdm/mdm/base.py`）

## 8. 维护 <a id="maintain"></a>

新增可继承类：先在[清单](../../后端基类清单.md) §2 登记，再在本文件 §7 补一条链，最后写代码；调整端口身份字段视为契约变更，须同步装配与详细设计。
