# 英文简称规范（mdm）

> mdm 主数据管理文档散落英文简称统一口径

[文档首页](../文档首页.md) › 规范 › 英文简称规范　|　配套：基座《[英文简称规范](../../bms文档/规范/英文简称规范.md)》（bms 权威源）

## 1. 目的与适用范围 <a id="purpose"></a>

统一 mdm 仓库内散落于文档（规划、设计、说明）中的英文简称理解口径，防止同一缩写出现多义、歧义或按通用外义误读。mdm 以**产品服务（独立服务）**形态接入 BMS 平台：**平台域与通用技术/组件/命名后缀的简称一律以基座 bms《英文简称规范》为权威（本文档不重复）**，本文档只登记 **mdm 主数据域相关**的简称与业务词。与基座规范冲突时以基座规范为准；标识符写法规则以《命名规范》为准。

## 2. 通用原则 <a id="principle"></a>

- **项目内含义优先**：同一缩写若通用外义与本业务含义不同，一律以本表"业务含义"列为准。
- **先查后写**：写作或阅读时遇缩写，先查本文档；本文档未收录时查基座 bms《英文简称规范》；两表均未收录的缩写须先登记再使用，禁止临时自造。
- **大小写**：主数据域简称全小写（org、sup、cus、mat）；通用缩写词全大写（SKU、BOM、MDM）；组件/产品名保留官方写法。
- **域标识符**：主数据域简称同时用于表前缀（{简称}_）、业务码、错误码段（33xxxx 起注册制）、事件域（{简称}.{动作}）与前端目录（views/{简称}/），登记于平台服务目录（`sys_module` 升格），见《[mdm 主数据管理规划](../规划/mdm主数据管理规划.md)》「标识符登记」节。

## 3. mdm 主数据域简称 <a id="module"></a>

**已定（首批四域）**（与 bms《英文简称规范》模块登记一致）：

| 简称 | 全称/来源 | 业务含义 | 表前缀 / 业务码 / 错误码段 / 事件域 |
| --- | --- | --- | --- |
| org | organization | 组织主数据：部门（组织架构树）+ 岗位（归属部门，含用户-岗位关联读口） | org_ / org / 33xxxx / org.* |
| sup | supplier | 供应商档案：名称/联系人/资质/状态 | sup_ / sup / 34xxxx / sup.* |
| cus | customer | 客户档案：联系人/信用/结算方式 | cus_ / cus / 35xxxx / cus.* |
| mat | material | 物料/商品档案：SKU 基础档案，含 BOM/工艺路线承接位 | mat_ / mat / 36xxxx / mat.* |

**预留（登记待建，段位自 37xxxx 顺延，接入时按平台注册流程确认）**：

| 简称 | 全称/来源 | 业务含义 | 表前缀 / 业务码 / 错误码段 |
| --- | --- | --- | --- |
| uom | unit of measure | 计量单位与换算 | uom_ / uom / 37xxxx |
| cur | currency | 币种与汇率 | cur_ / cur / 38xxxx |
| settle | settlement | 收付款结算方式 | settle_ / settle / 39xxxx |
| rate | tax rate | 税种税率 | rate_ / rate / 40xxxx |
| emp | employee | 员工主数据（人事域 hr 扩展承接） | emp_ / emp / 41xxxx |

> **命名避让**：物料归 mdm 占 `mat`（业务产品生产制造-物料并入 mdm 物料主数据）；税率用 `rate`（避开业务产品税管域 `tax`）；员工用 `emp`（业务产品人事域 `hr` 为业务承载，员工档案主数据归 mdm `emp`）。biz 等业务产品对主数据一律**引用**（逻辑外键 + 快照），不自建。

## 4. mdm 业务动作码 <a id="action"></a>

通用动作码（query / create / update / delete / manage / grant / approve / restore / import / export / upload / download / send / view / design / plain 等）以基座 bms《英文简称规范》「动作码简称」节为权威，本表只登记 **mdm 域专属动作码**（命名 `业务:动作`）：

| 动作码 | 含义 | 典型权限码 | 状态 |
| --- | --- | --- | --- |
| move | 移动部门（调整父部门，级联维护子树 ancestors） | org:update | 已定 |
| freeze | 停用/冻结主数据（退出引用与权限收敛） | org:update、sup:update | 候选 |

> 部门与岗位的增删改沿用通用动作码并收敛为域级权限码 `org:query` / `org:create` / `org:update` / `org:delete`。

## 5. 业务词缩写 <a id="term"></a>

通用技术与协议缩写以基座 bms《英文简称规范》「通用技术与协议缩写」节为准（API、ORM、CRUD、REST、JWT 等不再重复）；以下为 mdm 业务词与行业常见缩写：

| 缩写 | 全称 | 项目内含义/用法 |
| --- | --- | --- |
| MDM | Master Data Management | 主数据管理（本产品名称；业务码/表前缀用小写 mdm 仅用于仓库与文档，各域仍独立标识符） |
| SKU | Stock Keeping Unit | 商品库存最小单元（物料/商品档案唯一可售/可管粒度） |
| BOM | Bill of Materials | 物料清单（生产制造物料承接位，暂缓） |
| UOM | Unit of Measure | 计量单位（预留域 uom） |
| AR / AP | Accounts Receivable / Payable | 应收 / 应付（客户信用 / 供应商结算引用维度） |

## 6. 使用规则 <a id="usage"></a>

- 阅读与写作以本文档 + 基座《英文简称规范》为理解口径；同一缩写多义时按"业务含义"列解读。
- 主数据域简称、表前缀、业务码、错误码段、事件域五者一一对应，且**服务标识与简称一致**（服务目录登记制，`sys_module` 升格）：org↔org_↔org↔33xxxx↔org.*。
- 新增主数据域/业务词：先按 bms「平台扩展接入流程」在**服务目录（`sys_module` 升格）**登记标识符，再同步补充本表；未登记缩写不得在正式文档中使用。
- 与基座《英文简称规范》《命名规范》及平台《项目规划说明》冲突时以上述文档为准并回改本表。

## 7. 检查清单 <a id="checklist"></a>

- □ 文档中出现的业务英文简称均可在本文档或基座《英文简称规范》查得，含义一致
- □ mdm 主数据域简称/前缀/业务码/错误码段/事件域与服务目录登记一致
- □ 通用简称（API/ORM/etc.）未在 mdm 文档重复自造、以基座为权威
- □ 动作码写法 `业务:动作`（如 org:update），未造未登记动作
- □ 新增主数据域/业务词已登记本表
