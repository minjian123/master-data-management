## 1. 概述 <a id="overview"></a>

主数据管理不是「上线即完成」的一次性项目，而是一条持续演进的路线。成熟度模型帮你看清「现在在哪、下一步去哪」，实施方法论告诉你「怎么分步落地」。本篇汇集 Gartner / IBM 的五级成熟度与国内常见的七阶段实施法。

## 2. 成熟度五级 <a id="maturity"></a>

Gartner / IBM 等把主数据管理成熟度分为五级（措辞略有差异，语义一致）：

| 级别 | 名称 | 特征 |
| --- | --- | --- |
| **L1** | 初始（Initial） | 无正式主数据管理，各系统各自为政、过程零散 |
| **L2** | 发展中（Developing） | 有初步治理、质量、集成，但未集成/自动化；开始元数据与数据剖析 |
| **L3** | 已定义（Defined） | 有定义清晰、集成的主数据管理体系，正式流程、治理与系统就位 |
| **L4** | 受管（Managed） | 可度量与监控成效，KPI 在手；数据生命周期与数据管家成为核心 |
| **L5** | 优化（Optimizing） | 持续优化、自动化、创新；数据驱动决策与竞争优势 |

> Gartner 的观察：**多数大型组织处于 L2，正朝 L3 走**。级别不是越大越好，而是「与业务需求匹配、能落得住」。

## 3. 实施方法论：七阶段 25 步 <a id="methodology"></a>

国内常见的主数据实施方法论分七个阶段（对 25 个实施步骤）：

```mermaid

    A["① 项目规划"] --> B["② 现状分析"] --> C["③ 治理保障"] --> D["④ 平台建设"]
    D --> E["⑤ 存量清洗"] --> F["⑥ 数据集成"] --> G["⑦ 外围变更与运营分析"]
    classDef k fill:#e8eef4,stroke:#38a,color:#111
    class A,B,C,D,E,F,G k
```

| 阶段 | 主要工作 |
| --- | --- |
| ① 项目规划 | 定范围、优先级、组织（领导小组 / 工作小组 / 系统架构组 / 数据架构组）、路线图 |
| ② 现状分析 | 盘点现有主数据、系统、问题与差异 |
| ③ 治理保障 | 建标准体系（数据 / 管理 / 服务）、组织、制度、流程 |
| ④ 平台建设 | 主数据建模、维护、采集、分发、质量治理平台落地 |
| ⑤ 存量清洗 | 历史数据归集、清洗、去重、合并，形成高质量主数据库 |
| ⑥ 数据集成 | 与上下游系统集成，打通申请 / 审核 / 分发链路 |
| ⑦ 外围变更与运营 | 外围系统割接、持续运营与稽核，防止质量回退 |

## 4. 分批建设原则 <a id="phasing"></a>

企业主数据多，**一次全管起来周期长、风险高**，应按优先级分批：

| 排序依据 | 说明 |
| --- | --- |
| 企业最需要统一的 | 痛点最明显、共享最广的域优先 |
| 标准化程度高、基础好的 | 见效快、阻力的域优先 |
| 数据量可控的 | 风险可控、便于试点 |
| 依赖少的 | 不阻塞其他域的独立域优先 |

> 通常以 2–3 年分批完成并持续优化，**按期看到阶段性效果**便于推进。

## 5. 持续运营 <a id="operations"></a>

「实施成功、半年后质量回到解放前」是常见翻车场景。持续运营的关键动作：

- **定岗定责**：运营团队、数据管家，责任到人；
- **监督流程执行**：对新增 / 变更 / 使用的流程持续督导改进；
- **自动稽核**：质量规则固化、定期稽核、问题闭环；
- **度量与考核**：质量指标看板 + 纳入考核。

## 6. 与本项目的对照 <a id="project"></a>

本项目从零构建、无「多源历史库各自为政」包袱，属于「**新建体系**」路径：

- 成熟度目标不必追 L4/L5，**先把 L3「已定义」做扎实**（标准、流程、系统、治理就位）；
- 实施顺序按「**规划 → 设计 → 分域实现 → 业务接入**」推进（见《[mdm 主数据管理规划](../../../规划/mdm主数据管理规划.md)》「演进路线」节）；
- 分批建设：组织 / 供应商 / 客户 / 物料**首批**，其余域**预留登记、按需接入**。
