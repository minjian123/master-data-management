## 1. 范围与前置 <a id="scope"></a>

**目标**：把「组织主数据承接」从**代码交付**推到**真实链路联通**——mdm 组织域服务 ↔ bms 网关（产品命名空间）↔ bms 前端（组织选择字段族）↔ mdm 前端模块与三插件 ↔ 三库与运维收尾。

**前置（代码侧均已交付）**：

| 面 | 交付物 |
| --- | --- |
| mdm 组织域服务 | `/api/v1/org/data-source/{users,posts,dept-tree}`、`/resolve-names`、`/user-roles`（双通道鉴权；数据范围 / 脱敏强制接入） |
| bms 网关与边缘 | APISIX standalone（`route-mdm-org`：`/api/mdm/v1/org` + `/org/*` → upstream `org`，重写 `^/api/mdm/v1(.*)$`）+ 边缘 nginx（请求体上限 `GATEWAY_MAX_BODY_SIZE`，缺省 32m） |
| bms 前端 | 组织数据源默认端点经寻址契约组装为 `/api/mdm/v1/org`（`data-source/*`、`resolve-names`）；核对页 13 项自检 |
| mdm 前端 | `mdm-org` 模块（管理页 + 三插件 + 上下文通道）、类型包与零漂移门禁、独立预览产物 |
| 跨仓发布 | bms `release-module.mjs publish --module-dir`（跨仓产物接入 + 四关强校验 + 清单登记） |

**环境前置**：docker + Compose；三库（MySQL / PostgreSQL / 达梦）与 Redis、MinIO；Kiwi 容器（用例登记）；bms 与 mdm 两仓克隆（`bizs/` 同级）。

## 2. 环境准备 <a id="prepare"></a>

```bash
# 1) 环境变量（网关端口 / 代理 / 库前缀等；mdm 侧库名前缀配 mdm）
cd bms/deploy && cp .env.example .env && ${EDITOR:-vi} .env

# 2) 起全栈（含网关：APISIX + 边缘 nginx）
cd bms/deploy && docker compose -f compose/base.yml -f compose/gateway.yml --env-file .env up -d

# 3) mdm 组织域服务（按部署形态：容器或裸进程；容器名与 upstream 目标一致）
#    非 Compose 环境：GATEWAY_AUTH_HOST / upstream org 指向可达主机，见 deploy/.env 注释

# 4) 静态校验（应全绿）
cd bms/backend && uv run python -m ops.check_modules          # 接库对账（清单 + 产品档案）
uv run python -m ops.gateway_config check                     # 生成件零漂移 + 请求体上限三方一致
uv run python -m ops.contract_snapshot check                  # 公开契约零漂移
uv run python -m ops.event_contracts check                    # 事件契约零漂移

# 5) 容器内可达性
docker exec bms-apisix curl -s -o /dev/null -w '%{http_code}\n' http://org:8000/healthz   # 期望 200
```

**证据落点**：`mdm` 01_04 测试记录 §部署联调；bms 阶段二测试报告追加说明。

## 3. 步骤 A｜网关与产品命名空间可达 <a id="step-a"></a>

```bash
# 未带凭据（期望 401；路由命中即可，说明产品命名空间已暴露）
curl -i http://localhost:8088/api/mdm/v1/org/data-source/dept-tree

# 路由命中确认（APISIX 访问日志：upstream=org、path 重写为 /api/v1/org/...）
docker logs --tail 20 bms-apisix 2>&1 | grep 'mdm/v1/org'
```

**期望**：请求被 `route-mdm-org` 接住；**未带凭据 401**（鉴权生效）；服务内路径为 `/api/v1/org/...`（网关剥离 `/api/mdm/v1`）。

## 4. 步骤 B｜组织只读出口联通（带凭据） <a id="step-b"></a>

```bash
# 取用户令牌（示例；实际端点与字段见 identity 契约）
TOKEN=$(curl -s -X POST http://localhost:8088/api/identity/v1/auth/login \
  -H 'Content-Type: application/json' -d '{"username":"admin","password":"***","tenant":"***"}' \
  | python3 -c 'import json,sys;print(json.load(sys.stdin)["data"]["access_token"])')

BASE=http://localhost:8088/api/mdm/v1/org
curl -s -H "Authorization: Bearer $TOKEN" "$BASE/data-source/users?keyword=&page=1&size=10"
curl -s -H "Authorization: Bearer $TOKEN" "$BASE/data-source/posts?dept_id=1&include_children=true&page=1&size=10"
curl -s -H "Authorization: Bearer $TOKEN" "$BASE/data-source/dept-tree"
curl -s -H "Authorization: Bearer $TOKEN" "$BASE/resolve-names?target=user&id_in=1,2"
curl -s -H "Authorization: Bearer $TOKEN" "$BASE/user-roles?user_id=1"
```

**逐项期望**：

| 出口 | 期望 |
| --- | --- |
| `data-source/users` | `{code:0,data:{list:[...],total}}`；**手机号 / 邮箱为掩码**（脱敏生效）；部门过滤为「该部门含子树下岗位、且用户已分配该岗位」（**本域最终口径**；`sys_user.dept_id` 通道不引入） |
| `data-source/posts` | 分页 + 部门含子级生效；`dept_id=1&include_children=true` 含子树 |
| `data-source/dept-tree` | **一次性返回**（`{items:[...]}`，嵌套 `children`，不分页）；数据范围外的部门不入树 |
| `resolve-names` | 批量回显（`id_in` 逗号分隔、去重保序、单批 ≤200）；**未命中项占位不抛错**（`exists:false`） |
| `user-roles` | 岗位链 ∪ **部门链（精确匹配，不含子树）** 并集去重；短时缓存 + 写侧失效代 |

**异常口径**：平台用户来源不可达 → `330101`（fail-closed）；未带凭据 → 401；非法 `id_in` → 参数错误。

## 5. 步骤 C｜bms 前端切址联通（`11_02`） <a id="step-c"></a>

```bash
# dev 代理（两种口径之一）
#  a) 走网关：VITE_API_PROXY=http://localhost:8088
#  b) 本机裸跑 mdm 服务：VITE_LOCAL_API=mdm=<host>:8000（/api/mdm/v1 → 服务内 /api/v1 重写）
cd bms/frontend/apps/desktop && pnpm run dev     # 打开 http://localhost:5173/#/dev/org-check

# 类型零漂移
cd bms/frontend && pnpm --filter @bms/api-types run gen:check    # 期望：8 份一致
```

**逐项期望**：核对页 **13 项自检全通过**（含「组织数据源默认端点为 mdm 产品命名空间 `/api/mdm/v1/org`」与「数据源可替换」）；组织选择字段族（统一件 / 人员 / 岗位 / 部门树 / 复合弹窗）经 mdm 出口取数；**截图留证**（对照 06_05 原型口径）。

## 6. 步骤 D｜mdm 前端模块与三插件（`01_04`） <a id="step-d"></a>

```bash
# 1) mdm 侧构建与门禁
cd mdm/frontend/modules/org && pnpm run build && pnpm run budget && pnpm run guard:isolation

# 2) 跨仓发布（平台侧执行；链路不持跨仓凭据）
cd bms/frontend && node scripts/release-module.mjs publish \
  --module mdm-org --module-dir /abs/path/to/mdm/frontend/modules/org

# 3) 清单与四关校验
node scripts/check-module-manifest.mjs      # 期望：仓内 N 项 / 跨仓 1 项（mdm-org）

# 4) 启动宿主（dev 或构建产物），模块随清单加载
cd bms/frontend/apps/desktop && pnpm run dev
```

**逐项期望**：

| 面 | 期望 |
| --- | --- |
| 管理页 | `/#/org/depts`（树 + 页内编辑 + `ancestors` 链 + 启停 / 移动）、`/#/org/posts`（关键字 + 多选批量删除 + 绑定角色只读入口）可用（与原型逐页对照） |
| 用户分配岗位 | 用户详情「分配岗位」页签：已分配回显、弹窗分配（部门筛选 + 多选）、单条解绑 |
| 角色两插件 | 角色分配页签：岗位分配 / 部门分配（**上下文通道**取 `roleId`；部门树多选、精确匹配） |
| 降级 | 插件未加载 / 上下文缺失 / 无权限 → 该项不渲染，宿主页其余正常（不报错） |
| 发布回滚 | 清单回滚 / 停用可复现（`releases/<名>/<版本>/` 归档口径） |

## 7. 步骤 E｜网关请求体限制真机实测（`04-1-2`） <a id="step-e"></a>

```bash
# 1) 渲染值确认（模板经 GATEWAY_MAX_BODY_SIZE 渲染）
docker exec bms-gateway-nginx nginx -T 2>/dev/null | grep client_max_body_size      # 期望 32m
docker exec bms-apisix grep -n client_max_body_size /usr/local/apisix/conf/config.yaml  # 同值

# 2) 超限 → 413
dd if=/dev/zero of=/tmp/big bs=1M count=40
curl -i -X POST -H "Authorization: Bearer $TOKEN" -H 'Content-Type: application/octet-stream' \
  --data-binary @/tmp/big http://localhost:8088/api/file/v1/files | head -1              # 期望 413

# 3) 整包 ≤20MB 通过；>20MB 走分片（每片 ≤20MB）逐片通过、最终合并成功
```

**注意**：若 APISIX 启动日志报 `client_max_body_size` 键名未知（3.9+ 该节更名 `http_config`）→ 改 `deploy/gateway/config.yaml` 的 `nginx_config.http_config` 并重启，记录实测口径（bms 04-1-2 测试记录 §6）。

```bash
# 1) 三库真跑（可达时自动启用；不可达即跳过）
cd bms/backend && BMS_TEST_DB_URL=... BMS_TEST_TENANT_DB_URL=... uv run pytest -q

# 2) mdm 侧库前缀与迁移（产品自有前缀 mdm）
#    期望库名：mdm_org / mdm_org_{tenant_code} / mdm_archive（随 [database].name_prefix 派生）

# 3) 旧库下线：确认无连接后 DROP（运维执行，不可逆）
#    DROP DATABASE bms_org_{tenant_code};

# 4) 跨仓「拉取 + 构建」编排与生产托管（产物上传 / 静态托管基址）随部署形态落地
```

## 10. 回滚与风险 <a id="risk"></a>

| 风险 | 处置 |
| --- | --- |
| 网关配置改错导致 5xx | 配置声明式入 Git；回滚 `deploy/gateway/*` 后重启网关容器（APISIX 1s 文件轮询热加载，路由层改动无需重启） |
| 模块产物异常 | 清单回滚 / 停用（`releases/` 归档按版本可回） |
| 前端切址后取数失败 | 核对页自检 + 浏览器网络面板确认请求落在 `/api/mdm/v1/org`；必要时临时传 `endpoint` 覆盖（宿主可注入） |
| 旧库未清理 | 先只读观察；确认无连接（`SHOW PROCESSLIST` / 达梦会话视图）再 DROP，**不可逆** |
| 请求体上限版本差异 | 见 §7 注意（`http` → `http_config`），改后复跑 `ops.gateway_config check` |
