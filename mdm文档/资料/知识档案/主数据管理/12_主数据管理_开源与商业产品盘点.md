## 1. 概述 <a id="overview"></a>

主数据管理有三种落地形态：**采购商业套件、采用开源平台、自研自建**。本篇盘点主流产品谱系与选型维度，供「买还是建」判断参考。

> 具体产品能力与版本以官方为准；本篇为**选型知识储备**，不代表本项目选型结论（本项目结论见《[14 项目评估与选型](14_主数据管理_项目评估与选型.md)》）。

## 2. 产品谱系 <a id="landscape"></a>

| 类别 | 代表产品 | 特点 |
| --- | --- | --- |
| **商业 MDM 套件** | Informatica IDMC、SAP Master Data Governance、Oracle MDM、IBM InfoSphere MDM、Stibo Systems、Profisee、Reltio、Semarchy | 功能全（匹配 / 治理 / 管家 / 360 视图），能力强，许可与实施成本高 |
| **统一数据治理平台内含 MDM** | Ataccama ONE、CluedIn、Microsoft Purview + Profisee | 把 MDM 与数据质量、治理解析、元数据打通 |
| **开源 / 社区版** | Pimcore（PIM/主数据/DAM）、qData-mdm（国产开源主数据平台）等 | 自托管、可定制、成本低；功能与支持相对有限，需自行建设 |
| **平台/中台自带** | 数据中台、ERP/CRM 套件自带的主数据模块 | 与既有系统耦合，跨系统统一能力弱 |

## 3. 选型维度 <a id="criteria"></a>

| 维度 | 考察点 |
| --- | --- |
| 功能覆盖 | 建模、维护、匹配合并、分发、质量治理、治理工作流、审计血缘 |
| 架构契合 | 与现有技术栈、部署形态（云 / 自托管）、集成方式（API / 事件）是否契合 |
| 可扩展与可替换 | 能否适配自有域模型、能否与平台能力（认证 / 权限 / 事件）集成 |
| 成本 | 许可费 + 实施费 + 运维费 + 长期 TCO |
| 自主可控 | 数据主权、国产化 / 信创要求、二次开发自由度 |
| 生态与支持 | 社区活跃度、文档、厂商支持、行业案例 |

## 4. 开源 vs 商业 <a id="open-vs-commercial"></a>

| 维度 | 开源 | 商业 |
| --- | --- | --- |
| 成本 | 低（自建运维成本） | 高（许可 + 实施） |
| 定制 | 高自由度 | 受产品边界约束 |
| 功能 | 基础能力为主，需自建补齐 | 全面、开箱即用 |
| 支持 | 社区 / 自建团队 | 厂商专业支持 |
| 适用 | 预算有限、特定需求、有研发能力 | 快速上线、功能完整、要支持 |

## 5. 自建（自研）的适用条件 <a id="build"></a>

自研自建并非一定更差，以下情形值得自建：

- 主数据域与企业业务**深度绑定**，通用产品模型难适配；
- 已有成熟平台基座（认证 / 权限 / 事件 / 审计 / 工作流），只需补主数据域；
- 有**信创 / 自主可控 / 数据主权**硬要求；
- 团队具备长期自主研发与运维能力；
- 期望与既有产品体系**同构演进**，而非引入异构套件。

> 本项目即属于「**已有平台基座 + 深度绑定业务 + 自主演进**」的自建情形（见《[14 项目评估与选型](14_主数据管理_项目评估与选型.md)》）。
