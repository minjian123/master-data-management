## 1. 产品定位与范围 <a id="position"></a>

**mdm（主数据管理，Master Data Management）** 为独立产品仓库：专门承载**企业内跨业务项目公用的基础数据**——部门、岗位、供应商、客户、物料等**主数据**，作为采购、销售、仓储等各业务项目**一致性引用**的权威源，统一维护、统一口径、统一授权。

- **主数据定义**：被两个及以上业务域共同引用、且引用需保持一致的实体档案（相对「交易数据 / 单据」而言）。主数据不承载业务流转，只提供权威档案与只读出口。
- **平台边界**：**用户、角色、菜单、权限、字典、系统参数**等**平台运行必需的基础数据**（登录、鉴权、平台配置）仍属 BMS 基座（`sys_` 域），保留在 bms 仓库，不迁入 mdm。部门、岗位由原平台组织模块迁出为 mdm **组织主数据域（org）**。
- **与业务产品分工**：biz（采购 / 收付款 / 销售 / 仓储）等业务产品**不自建**供应商 / 客户 / 物料档案，一律以**逻辑外键（code）引用 + 名称快照**方式引用 mdm；实际主数据实体归 mdm。原 biz 规划中的 `sup`（供应商）、`gds`（商品主数据）与内置 `sale` 客户档案一并迁入 mdm。

> 判定尺：一个实体若「只被单一业务产品使用、且随该产品交易流转」，归业务产品；若「被多产品共同引用、需统一口径」，归 mdm（见 bms《平台可扩展性规划》3.2 边界争议处置）。

## 2. 主数据域全景 <a id="domains"></a>

mdm 按主数据域垂直切分，每域独立注册标识符（表前缀 / 业务码 / 错误码段 / 事件域）、独立演进，按限界上下文拆服务独立部署（每服务独立库）。

### 2.1 已定主数据域（首批） <a id="domains-core"></a>

| 主数据域 | 域简称 | 承载内容 | 表前缀 / 业务码 / 错误码段 / 事件域 | 优先级 |
| --- | --- | --- | --- | --- |
| 组织 | org | 部门（组织架构树）+ 岗位（归属部门）+ 用户-岗位关联（`org_user_post`）+ 角色-岗位/角色-部门分配（`org_role_post` / `org_role_dept`） | `org_` / `org` / `33xxxx` / `org.*` | 首批 |
| 供应商 | sup | 供应商档案（名称 / 联系人 / 资质 / 状态） | `sup_` / `sup` / `34xxxx` / `sup.*` | 首批 |
| 客户 | cus | 客户档案（联系人 / 信用 / 结算方式） | `cus_` / `cus` / `35xxxx` / `cus.*` | 首批 |
| 物料 | mat | 物料 / 商品档案（SKU 基础档案，含 BOM / 工艺路线承接位） | `mat_` / `mat` / `36xxxx` / `mat.*` | 首批 |

> **组织域说明**：部门与岗位同属「组织」限界上下文，以 `org` 单域承载（`org_dept` / `org_post` / `org_user_post` / `org_role_post` / `org_role_dept`）；权限码为域级 `org:query` / `org:create` / `org:update` / `org:delete`，事件 `org.dept.changed` / `org.post.changed` / `org.role_post.changed` / `org.role_dept.changed`。**角色-岗位 / 角色-部门分配（2026-10-06）归本域**（`role_id` 对 bms 角色逻辑外键），经 bms 角色管理页「角色分配」页签插件读写，并供 **「按用户解析角色」只读契约**（`/api/v1/org/user-roles`）供 bms 权限引擎跨服务汇总。

### 2.2 预留主数据域（登记待建） <a id="domains-reserved"></a>

下表为**规划预留**——先在本文与平台服务目录登记标识符（防日后返工、防跨产品冲突），**暂不建表与设计**，按业务产品实际需要分批接入：

| 主数据域 | 域简称 | 预留内容 | 拟表前缀 / 业务码 / 错误码段 / 事件域 |
| --- | --- | --- | --- |
| 计量单位 | uom | 计量单位与换算 | `uom_` / `uom` / `37xxxx` / `uom.*` |
| 币种汇率 | cur | 币种与汇率 | `cur_` / `cur` / `38xxxx` / `cur.*` |
| 结算方式 | settle | 收付款结算方式 | `settle_` / `settle` / `39xxxx` / `settle.*` |
| 税率 | rate | 税种税率 | `rate_` / `rate` / `40xxxx` / `rate.*` |
| 员工 | emp | 员工主数据（人事域 hr 扩展承接） | `emp_` / `emp` / `41xxxx` / `emp.*` |

> **命名避让**：mdm 物料用 `mat`（生产制造-物料域并入 mdm 物料主数据）；mdm 税率用 `rate`（避开业务产品税管域 `tax`）；mdm 员工用 `emp`（业务产品人事域 `hr` 作为人事业务承载，员工档案主数据归 mdm `emp`）。biz 原预留 `mat`（28xxxx）、`tax`（32xxxx）相应让位（见 6 节与 biz《英文简称规范》）。

> **不入 mdm 的基础数据**：仓库 / 库位归仓储业务（biz `wh`）主数据与库存交易一体；用户 / 角色 / 菜单 / 权限 / 字典 / 系统参数归 bms 基座 `sys_` 域。

## 3. 平台复用边界与依赖台账 <a id="platform"></a>

### 3.1 复用边界 <a id="platform-reuse"></a>

mdm 以**产品服务（独立服务）**形态接入 BMS 平台（见 bms《平台可扩展性规划》5.2 / 5.7、bms《微服务演进规划》），自身只做主数据域，平台能力不重复实现：

| 能力 | 来源 | mdm 侧做法 |
| --- | --- | --- |
| 认证与会话 / SSO | bms 平台 | 复用（OIDC / JWT，不实现登录） |
| RBAC 权限（角色 / 菜单 / 权限码 / 数据范围） | bms 平台 | 复用（域级权限码 `org:*` / `sup:*` / `cus:*` / `mat:*` 注册于平台） |
| 文件 / 附件（供应商资质等） | bms 平台 | 复用（文件服务） |
| 审计（操作 / 字段级变更 / 哈希链） | bms 平台 | 复用（主数据表按注册纳入审计） |
| 事件总线 / Webhook | bms 平台 | 复用（主数据变更发布 `org.*` / `sup.*` 等事件） |
| 字典 / 系统参数 | bms 平台 | 复用（主数据枚举取字典） |
| 全文检索 | bms 平台 | 复用（主数据入检索索引） |
| 租户隔离 / 域名 / 配额 | bms 平台 | 复用 |

### 3.2 平台依赖台账 <a id="platform-ledger"></a>

| 依赖能力 | 就绪状态 | 未就绪时的推进方式 |
| --- | --- | --- |
| 产品服务接入（微服务形态、服务目录登记） | 规划中（bms R4.1~R4.3） | 文档先行；注册要素先本仓库登记，接入时对齐平台服务目录 |
| 产品级注册（表前缀 / 错误码段 / 事件域） | 规划中 | 本文先行登记，接入时写入平台 `sys_module`（升格服务目录） |
| 组织主数据查询基座（组织数据源 / 名称回显两契约） | **已迁入 mdm**（原 bms 跨阶段基座） | mdm 组织域按契约实现；bms / biz 经契约消费 |

| --- | --- | --- | --- | --- | --- |

| 供应商 sup | `sup_` | `sup` | `34xxxx` | `sup.*` | 已定 |
| 客户 cus | `cus_` | `cus` | `35xxxx` | `cus.*` | 已定 |
| 物料 mat | `mat_` | `mat` | `36xxxx` | `mat.*` | 已定 |
| 计量单位 uom | `uom_` | `uom` | `37xxxx` | `uom.*` | 预留 |
| 币种汇率 cur | `cur_` | `cur` | `38xxxx` | `cur.*` | 预留 |
| 结算方式 settle | `settle_` | `settle` | `39xxxx` | `settle.*` | 预留 |
| 税率 rate | `rate_` | `rate` | `40xxxx` | `rate.*` | 预留 |
| 员工 emp | `emp_` | `emp` | `41xxxx` | `emp.*` | 预留 |

## 6. 与业务产品的引用边界 <a id="boundary"></a>

- **引用方式**：业务产品（biz 等）对 mdm 主数据以 **code 逻辑外键**引用，单据保存名称 / 单价等**快照**；跨服务读走 mdm 公开契约或事件，**禁止跨库 JOIN**（bms《微服务演进规划》S2）。
- **biz 侧调整**：biz 原 `sup`（供应商）、`gds`（商品主数据）与内置 `sale` 客户档案**迁入 mdm**；biz 采购 / 销售 / 仓储改为引用 mdm 供应商 / 客户 / 物料，`pur` / `sale` / `wh` 业务域保留。biz 原预留 `mat`（28xxxx）、`tax`（32xxxx）让位（物料归 mdm `mat`、税管域改名避让）。
- **组织主数据**：`sys_user.dept_id` 保留在 bms，为对 mdm 部门的**逻辑外键**；用户-岗位关联表随组织主数据**迁 mdm**（`org_user_post`，2026-10-03），mdm 另供**用户-岗位契约**（查 / 分配 / 解绑）并在 bms 用户管理页经**具名插槽插件**提供分配界面；**用户-角色分配 `sys_user_role` 留 bms**（授权归平台权限体系）；**岗位/部门的角色分配归 mdm**（角色-岗位 `org_role_post` / 角色-部门 `org_role_dept`，2026-10-06），经 bms 角色管理页「角色分配」页签插件读写（依赖 bms 基座显式上下文注入通道 `05-11`），并提供**「按用户解析角色」只读契约**（`/api/v1/org/user-roles`）供 bms 权限引擎汇总。组织主数据**只读出口**（组织数据源 / 名称回显）由 mdm 组织域实现。
- **工作区引用**：bms、biz 仓库根设软链 `mdm文档 → ../mdm/mdm文档`；mdm 仓库根设软链 `bms文档 → ../bms/bms文档`（见 7 节）。

## 8. 明确不采用 <a id="not-adopt"></a>

- 不承载登录 / 权限 / 用户 / 角色 / 菜单 / 字典 / 系统参数（平台运行必需基础数据，留 bms 基座）。
- 不承载交易数据 / 单据 / 流转状态（归各业务产品）。
- 不自建认证、权限、文件、审计、事件、检索等平台能力（复用 bms）。
- 不把仓库 / 库位纳入 mdm（归仓储业务主数据，与库存交易一体）。

## 9. 风险与对策 <a id="risk"></a>

| 风险 | 影响 | 概率 | 缓解措施 |
| --- | --- | --- | --- |
| 标识符与 biz 等业务产品冲突 | 高 | 低 | 全域登记 + 命名避让（mat 归 mdm、税率 rate、员工 emp）；接入时平台服务目录唯一性校验 |
| 部门 / 岗位迁出牵动 bms 权限体系（角色分配、数据范围） | 中 | 中 | 用户-角色分配留 bms，岗位/部门角色分配随组织归 mdm 并经只读契约汇总；仅改数据所有权与只读出口；文档层先行，实现随平台阶段 |
| 业务产品仍自建主数据、引用不一致 | 中 | 中 | 规划层明确「业务产品不自建主数据」并回写 biz 规划与简称规范 |
| 平台产品接入机制未就绪 | 中 | 高 | 文档先行；依赖台账登记，接入时对齐平台服务目录与契约 |
