# mdm 后端基类清单

> **产品仓自持**的基类登记表：只登记**本仓可被继承的类**。平台基类体系（体系根、分层、逐类契约）的权威在 bms《后端基类清单》与《后端基类实现契约》，本文件不复制、不改写平台基类。

[文档首页](文档首页.md) › mdm 后端基类清单　|　配套：[后端基类实现契约](设计/基类体系/后端基类实现契约.md)

## 1. 用途与维护 <a id="purpose"></a>

- **定位**：回答「mdm 仓里有哪些类可被继承、父类是谁、代码在哪、由谁承接」。平台基类（`BaseValueObject` / `BaseDataContract` / `BaseSchema` / `BasePluggable` / `BaseRepository` / `BaseService` / `BaseModel` 等）不在此登记。
- **强制口径（平台基类体系，不得违反）**：
  1. 本仓任何类都必须能追到**平台体系根**；
  2. **不得新增体系根**——直接继承 `BaseObject` 一律拒绝，体系根由平台契约定；
  3. 新增可继承类须**先登记本表 + 在实现契约 §7 补链**，再写代码。
- **状态取值**：`已交付` / `占位`（接口就位、真实实现待回补）/ `待交付`（已设计未落地）。
- **代码位置口径**：包根相对路径（本仓包根为 `backend/services/mdm/src/`，即 `mdm/...`）。

## 3. 与平台基类的关系 <a id="platform"></a>

- 三个基类都经 `BasePluggable` 接入平台四段链（`BasePluggable` → `BaseCapability` → `BaseFrameworkObject` → `BaseObject`），逐段语义以平台《后端基类实现契约》为准，本仓只实现端口语义（查询 / 回显 / 取数）。
- 三个基类均为**端口**：只声明抽象方法 + 插件身份（`key` / `plugin_key` / `contract_version`），真实取数经本仓装配注入，不复制平台的插件生命周期与契约校验。

## 4. 不登记的情形 <a id="excluded"></a>

以下类**不构成新的可继承层**，直接继承平台基类，不在本表登记：

- 业务模型 / 契约：继承 `BaseModel` / `BaseSchema`；
- 服务与仓储：继承 `BaseService` / `BaseRepository`；
- 插件实现类（`DbMdmDataSource` 等）：继承本表基类，属**承接实现**而非新基类；
- 错误类：继承平台 `bms_core` 的错误基类，不另立根系。

## 5. 维护 <a id="maintain"></a>

新增 / 调整本仓基类须同步：本表 + [实现契约](设计/基类体系/后端基类实现契约.md) §7 链 + 对应任务设计；判定由预检步骤「基座：check_backend_base」承担（继承链对账 / 清单对账 / 直继承合法性 / 数据类形态 / 错误码段位 / 迁移链）。
